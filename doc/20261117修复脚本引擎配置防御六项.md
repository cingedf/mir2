# 20261117修复脚本引擎配置防御六项

## 现象

第五轮深度审计（NPC 脚本引擎 + 配置加载路线）回报 6 项 P1 缺陷，均可由 GM 配置误填/脚本自引用/玩家输入触发客户端崩溃或服务器异常：

1. **钓鱼刷怪率负数崩溃**：FishingMobSpawnChance 配 >100 → `Random.Next(100 - chance)` 参数为负 → ArgumentOutOfRangeException（PlayerObject.cs:11611）。
2. **钓鱼进度除零**：FishingAttempts（FishingProgressMax）配 0 且已钓到鱼 → decimal 除零 → DivideByZeroException（PlayerObject.cs:11704）。
3. **%INPUTSTR 注入脚本动作**：玩家输入的 NPCInputStr 直接替换进脚本动作参数，含 \r\n\t\0 等控制字符可破坏脚本参数结构（NPCSegment.cs:3213）。
4. **CALC 除零**：脚本 CALC 运算除数为 0 → DivideByZeroException → 脚本线程异常（NPCSegment.cs:5411）。
5. **AwakeMaterials 保存翻倍**：SaveAwakeAttribute 内再次 Add 静态列表 → 每次保存觉醒材料配置翻倍膨胀，Load 重复加载亦累加（Settings.cs:1501/1550）。
6. **#INSERT/#INCLUDE 自引用死循环**：脚本 #INSERT/#INCLUDE 指向自身时 AddRange/InsertRange 无限扩张 → 启动期死循环/内存爆炸（NPCScript.cs:304-386）。

## 排查过程

- 逐处读源码确认触发链：钓鱼两处为配置直读无钳制（SaveFishing 允许 UI 写任意值，运行时必须钳制）；
- %INPUTSTR 替换发生在 Act 分词之后（空格不改参数个数但改内容），多数 switch 分支有 TryParse 守卫，但控制字符可注入文本类参数；上批已对 NPCInputStr 截断 100 字符，本批补控制字符清理；
- AwakeMaterials：Load 循环 Add（:1501 正常），Save 的 else 分支 :1550 又 Add（根因），且 Load 无 Clear（重复加载累加）；
- #INSERT（:304）循环内 AddRange(newLines)，自引用 → 无限扩张；#INCLUDE（:331）循环内 InsertRange，自引用 → 无限插入；两处 path/split 无长度校验 → 越界 NRE；文件不存在时 newLines 沿用上轮残留值（重复插入错误内容）。

## 修复内容

**PlayerObject.cs**：
1. :11611 刷怪率前置钳制 `int fishMobChance = Math.Max(0, Math.Min(100, Settings.FishingMobSpawnChance));`，判定用 `Random.Next(Math.Max(1, 100 - fishMobChance))`（chance=100 必中，=0 保持 1% 原语义）。
2. :11704 进度条件加 `FishingProgressMax > 0 &&`。

**NPCSegment.cs**：
3. :3213 `%INPUTSTR` 替换值改 `Regex.Replace((string)_npcInputStr ?? string.Empty, @"[\r\n\t\0]", string.Empty)`（using System.Text.RegularExpressions 已存在，清理控制字符保留合法文本）。
4. :5411 `case "/": return right == 0 ? 0 : left / right;`。

**Settings.cs**：
5. ①LoadAwakeAttribute :1469 InIReader 前加 `Awake.AwakeMaterials.Clear();`；②SaveAwakeAttribute 原 :1550 `Awake.AwakeMaterials.Add(value);` 删除（翻倍根因）；③LoadFishing 读值后 `FishingAttempts = Math.Max(1, FishingAttempts); FishingMobSpawnChance = Math.Max(0, Math.Min(100, FishingMobSpawnChance));`（源头钳制）。

**NPCScript.cs**：
6. ParseInsert/ParseInclude 各加 `HashSet<string> processed = new HashSet<string>(StringComparer.OrdinalIgnoreCase);`；path 用 `Path.GetFullPath` 归一后 `if (!processed.Add(...)) continue;`（自引用第二次即跳过，归一防 `./self.txt` 绕过）；ParseInsert 文件不存在分支加 `newLines.Clear(); continue;`（防沿用残留）；ParseInclude :337 split 后加 `if (split.Length < 3) continue;`（越界防护）。
