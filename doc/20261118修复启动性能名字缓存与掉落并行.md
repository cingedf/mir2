# 20261118修复启动性能名字缓存与掉落并行

## 现象

服务端启动性能审计（启动时间路）发现两处启动慢的根因，均属「必付成本中的可优化浪费」：

1. **物品名字查找无缓存**（Envir.cs:3655-3664 `GetItemInfo(string)`）：每次按名字查物品都线性遍历 `ItemInfoList`，且对**每个元素**执行 `info.Name.Replace(" ", "")` 字符串分配。启动期掉落加载（MonsterInfo.cs:358）、任务定义（QuestInfo.cs:268/272/275/312）、配方（RecipeInfo.cs:33/97/114）合计约 2 万次名字查找 × 5000 物品 ≈ 1 亿次字符串分配，实测消耗 1-5 秒。对照同文件的 `GetItemInfo(int)`（:3640-3653）已有 `_itemInfoIndexCache`，名字版缺失缓存属明显不对称。
2. **怪物掉落文件串行加载**（Envir.cs:4349-4361 `ReloadDrops`）：1000+ 个怪物掉落 txt 逐个串行 `File.ReadAllLines` + 解析，冷盘数百 ms~2 秒。

## 排查过程

1. 名字缓存：确认 int 版已有 `ConcurrentDictionary<int, ItemInfo>` 索引缓存，名字版无；逐调用点核对名字参数语义——原实现对 `info.Name` 去空格、**name 参数原样比较**（带空格的 name 匹配不到），修法必须严格保持此等价性（不能对 name 去空格，否则改变语义）。
2. 掉落并行化：逐项核实线程安全——
   - `MessageQueue`（Server\MessageQueue.cs:14-26）：MessageLog/DebugLog/ChatLog 全为 `ConcurrentQueue<string>`，Enqueue 只入队 + Logger.Info，安全；
   - `DropInfo.Load`/`FromLine`（MonsterInfo.cs:330-437）/ParseInsert/ParseGroup（:439-484）：全为局部字符串操作 + 传入的局部 List，无共享静态状态；
   - `FromLine` 内的 `Envir.GetItemInfo(parts[1])`（:358）：本批已改为 `ConcurrentDictionary` 缓存，线程安全；
   - 现有 ReloadDrops（20261116 修复）已用「局部 new List 加载完整体替换引用」实现原子切换，并行化只需把每怪的局部 List 存入按索引的数组，循环外按 index 回写即可保持最终顺序/引用绑定一致。

## 修复内容

### Server\MirEnvir\Envir.cs（4 处名字缓存 + 1 处并行化）

1. **字段声明**（:3470 附近）：新增 `private readonly ConcurrentDictionary<string, ItemInfo> _itemInfoNameCache = new ConcurrentDictionary<string, ItemInfo>(StringComparer.OrdinalIgnoreCase);`（OrdinalIgnoreCase 与原 Compare 语义一致）。
2. **`GetItemInfo(string)`**（:3668 附近）：入口 `if (name == null) return null; if (_itemInfoNameCache.TryGetValue(name, out var cached)) return cached;`；原线性循环命中后 `_itemInfoNameCache[name] = info;` 回填（name 原样作 key，严格等价；首命中顺序由线性扫描决定）。
3. **LoadDB 重载**（:1682）：`_itemInfoIndexCache.Clear()` 后补 `_itemInfoNameCache.Clear();`（重载时同步失效）。
4. **运行期删除 Remove(ItemInfo)**（:3182）：补 `_itemInfoNameCache.TryRemove(info.Name.Replace(" ", ""), out _);`（能命中 info 的查询 name 必为 info.Name 去空格后结果，字典 OrdinalIgnoreCase 保证大小写不同也能移除）。
5. **ReloadDrops 并行化**（:4349-4361）：加 `using System.Threading.Tasks;`；怪物掉落循环改 `var newDropArrays = new List<DropInfo>[MonsterInfoList.Count]; Parallel.For(0, MonsterInfoList.Count, i => { ...路径构造... var newDrops = new List<DropInfo>(); DropInfo.Load(newDrops, ...); newDropArrays[i] = newDrops; });` 循环外 `for i: MonsterInfoList[i].Drops = newDropArrays[i];`。钓鱼/觉醒/宝箱/灵物石/绝技掉落保持串行（数量少且共享累加 List，不宜并行）。`Enqueue(DropsLoaded)` 留最后。

MonsterInfo.cs 无需改动（Load/FromLine 本身线程安全）。

**硬约束遵守**：未改存档格式、BinaryReader/Writer 字段顺序、ini 文本格式；并行仅改加载并发度，最终集合顺序与引用绑定不变。
