# 20261115修复爆率生成器工艺材料页签加载失效

> 服务端 UI 英文显示全景取证（explore 子代理 ses_e22f0ee13ffe530eSJ6EBO8jwK）产出的 H9 双效项：DropBuilderForm（爆率生成器）工艺材料页签的物品列表加载失败 + 页签 Tag 英文——一处字符修复同时解决 bug 与汉化。用户授权自主决策顺手处置（@679@）。

## 现象

- server.exe → 爆率生成器（DropBuilderForm）→ 工艺材料页签：物品列表恒为空（其他页签正常），无法把工艺材料类物品加入爆率列表。
- 该页签 Tag 为英文 `"Crafting Material"`，其余 37 个页签 Tag 全中文（武器/盔甲/护身符…）。

## 排查过程

- 筛选机制（DropBuilderForm.cs:344）：`Envir.ItemInfoList[i].Type.ToString() == Tab.SelectedTab.Tag.ToString()`——`Type` 是 `ItemType` 枚举，工艺材料枚举名 = **中文「工艺材料」**（ItemType 已汉化枚举），Tag 是英文时永不匹配 ⇒ 列表恒空。
- 三个消费点全核对：344 行筛选、362 行 `switch(Tag)` → `case "工艺材料": listBoxCraftingMaterial.Items.AddRange(...)`（406-408）、497 行 `switch(SelectedTab.Tag)` → `case "工艺材料": 工艺材料.Add(...)`（555-559）——两个 switch 的 case 全中文，唯 designer.cs:480 的 `listBoxCraftingMaterial.Tag = "Crafting Material"` 错位。
- 37 组 page/listBox Tag 对逐一比对：仅此一处不匹配（listBoxCraftingMaterial 与 tabPageCraftingMaterial 应同为「工艺材料」）。

## 修复内容（`Server.MirForms\DropBuilder\DropBuilderForm.designer.cs:480`，1 行）

```csharp
this.listBoxCraftingMaterial.Tag = "工艺材料";   // 原 "Crafting Material"
```

- 同时达成：①工艺材料页签物品列表恢复加载（Type.ToString() 匹配成立）②页签 Tag 全中文统一（汉化）。
- 两个 switch 的 case 与筛选逻辑零改动（行为等价收敛）。

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：**0 警告 0 错误**（27.81s，含 server.exe 入口工程全量构建）。
- 上线验证：打开爆率生成器 → 工艺材料页签 → 物品列表出现全部 `ItemType.工艺材料` 物品 → 选中加入爆率列表正常。
