# 20261114 实装GM命令华丽雨光

## 现象

「华丽雨光」buff 在代码层五环齐全，但**没有任何生效途径**：

1. 枚举定义：`Shared\Enums.cs:1685`；
2. 服务端默认注册：`Server\MirDatabase\BuffInfo.cs:605-608`（`Properties = BuffProperty.RemoveOnDeath`，`Visible = true`，**无任何 Stats 加成字段**——设计即纯光效 buff）；
3. 客户端人物光效：`Client\MirObjects\MapObject.cs:279-281`（`Effects.Add(new BuffEffect(Libraries.Magic3, 3470, 8, 1400, this, true, type) { Repeat = true })`——Magic3 第 3470 图起 8 帧、1400ms 循环）；
4. 客户端 buff 栏图标/文案：`Client\MirScenes\Dialogs\BuffDialog.cs:383`（tooltip）、`:673`（分组显示）；
5. 唯一授予途径是 NPC 脚本 `GIVEBUFF 华丽雨光 ...` 命令（任务A 已修复其属性传参，commit `d99ead4`），但检索部署区全部 NPC 脚本（`C:\1.40\mir2-deploy\Server\Envir\NPCs` 及 baseline 备份）`GIVEBUFF|华丽雨光` **零命中**——没有任何脚本使用它。

来源考证：`git log -S 华丽雨光` 显示由上游 Crystal 社区 #1169 系同步带入（901d54a / d5ee942 / 74fc7fe），初始 commit `4c06be4` 的 Enums.cs 不含该枚举 ⇒ **非原版自带，上游预留未实装内容**。本修复为其提供一个可用的游戏内授予入口。

## 排查过程

- 用户命令处理结构：`PlayerObject.cs:2268` `else if (message.StartsWith("@"))` → 去 '@' → `parts = message.Split(new[]{' '}, RemoveEmptyEntries)` → `:2291` `switch (parts[0].ToUpper())` 大 switch 分发；既有权限守卫模式为 case 首行 `if (!IsGM) return;`（KILL）或 `if (!IsGM && !Settings.TestServer) return;`（CHANGEGENDER）；反馈用 `ReceiveChat(..., ChatType.System)`。
- `AddBuff` 签名（`MapObject.cs:643`）：`AddBuff(BuffType type, MapObject owner, int duration, Stats stats, bool refreshStats = true, bool updateOnly = false, params int[] values)`——`duration` 为**相对毫秒**（NPC 脚本 GIVEBUFF 传 `Settings.Second * 秒数`），分钟级应传 `Settings.Minute * 分钟`（`Settings.Minute` 在 Envir 存档门控已使用）。
- 锚点核查：`case "CHANGEGENDER":` 在 PlayerObject.cs 中唯一（2352 行），可直接定位插入点；该 case 前为 KILL case（2350 行结束）。
- 确认 `BuffType` 与 `Stats` 在 PlayerObject.cs 已有使用（GetInfo 4996 魔法盾判断等），无需新增 using。

## 修复内容

**`Server\MirObjects\PlayerObject.cs`**（@ 命令 switch 内、`case "CHANGEGENDER":` 之前新增）：

```csharp
case "华丽雨光":
    if (!IsGM) return;

    {
        int minutes = 60;
        if (parts.Length >= 2 && (!int.TryParse(parts[1], out minutes) || minutes <= 0))
            minutes = 60;

        AddBuff(BuffType.华丽雨光, this, Settings.Minute * minutes, new Stats(), true);

        ReceiveChat($"华丽雨光光环已激活，持续 {minutes} 分钟。", ChatType.System);
    }
    return;
```

设计要点：

- **权限**：`IsGM` 守卫，与 KILL 命令同模式（演示用光效 buff 不对普通玩家开放；NPC 脚本侧可用 `GIVEBUFF 华丽雨光` 面向玩家授予）。
- **参数**：可选分钟数（`@华丽雨光` 默认 60 分钟；`@华丽雨光 120` 持续 2 小时；非法/非正数回落默认 60）。
- **属性**：传 `new Stats()` 空 Stats——注册本就无加成，纯光效 buff，语义与资料一致。
- **可见性/光效**：客户端光效 case 早已就绪（MapObject.cs:279-281），服务端 AddBuff 后自动广播 buff → 客户端出现人物光效 + buff 栏图标。
- **反馈**：ReceiveChat 提示激活与时长。

**使用方法**：GM 账号聊天框输入 `@华丽雨光`（或 `@华丽雨光 分钟数`）。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**（19.17s）。
- 逻辑复核：`parts[0].ToUpper()` 为 "华丽雨光"（中文无大小写差异，ToUpper 幂等）；`int.TryParse` 失败时 `minutes` 被 out 置 0 → `minutes <= 0` 条件成立回落 60（注意 `!int.TryParse(...) || minutes <= 0` 短路顺序，两种失败路径均回落默认）；`AddBuff` 的 buff 会进 `PlayerObject.Buffs` 并走既有 `RefreshStats`/广播链（stats 为空无可刷新项，`refreshStats: true` 与缺省一致）。
- 客户端无需改动（光效/图标 case 已存在）。
