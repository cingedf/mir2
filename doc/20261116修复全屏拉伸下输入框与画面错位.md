# 20261116修复全屏拉伸下输入框与画面错位

## 现象

用户反馈：全屏模式下登录界面，账号/密码输入框（及新账号/改密码等对话框输入框）**与游戏画面上的框位置错开**——画面上的输入框被拉伸放大了，但真正能打字的原生输入框还停在原位。

## 排查过程

1. **输入框机制**：`MirTextBox` 是 MirControl 包装的**原生 WinForms TextBox**（`MirTextBox_Shown` :372 `TextBox.Parent = Program.Form`）。原生控件直接挂在窗体上，坐标=窗体客户区**物理像素**。
2. **错位原理**：全屏拉伸改造后，窗体 ClientSize=物理屏（如 1920×1080），游戏画面按逻辑分辨率（如 1366×768）渲染再由 D3D 拉伸铺满。游戏画面里的框（D3D 纹理）被拉伸到物理坐标（85,85 → ~120,120），而原生 TextBox 不在 D3D 画面里，仍用逻辑坐标 (85,85) → **画面框与真实输入框分离**。
3. **影响面**：全仓 grep `Parent = Program.Form` 仅 MirTextBox 一处（MirTextBox.cs:372）。登录/新账号/改密码/聊天/InputBox/AmountBox/MessageBox 全部经 MirTextBox，修一层全覆盖。
4. 窗口模式窗体=逻辑尺寸，1:1 无此问题。

## 修复内容

`Client\MirControls\MirTextBox.cs`：

1. 新增 `UpdateNativeBounds()` 实例方法：全屏且 ClientSize/逻辑尺寸有效时，`TextBox.Location/Size = 逻辑值 × ClientSize / ScreenWidth(Height)`（按拉伸比例换算为物理 bounds）；否则 1:1 赋 DisplayLocation/Size（窗口模式行为不变）。
2. 统一落点改造：
   - `OnLocationChanged`（:45）：原直接 `TextBox.Location = DisplayLocation` → 改调 `UpdateNativeBounds()`（保留 TextureValid=false + Redraw）；
   - `OnSizeChanged`（:127）：原 `TextBox.Size = Size` → 改调 `UpdateNativeBounds()`；
   - `MultiLine()`（:234）：`TextBox.Size = Size` → `UpdateNativeBounds()`；
   - `MirTextBox_Shown`（:370）：`TextBox.Parent = Program.Form` 后补 `UpdateNativeBounds()`。
3. 新增静态 `RefreshAllNativeBounds()`：遍历 `Program.Form.Controls` 中 `Tag is MirTextBox` 的原生 TextBox（ctor :261 `Tag = this` 已有）逐个重算 bounds。
4. `Client\Forms\CMain.cs`：`ToggleFullScreen` 与 `SetResolution` 尾部各挂 `MirTextBox.RefreshAllNativeBounds()`——切全屏/切分辨率后所有存活输入框立即对位。

自绘光标 CreateTexture 用逻辑 Size（D3D 纹理坐标系），未动。

## 验证证据

- `dotnet build Client\Client.csproj -c Release`：0 错误（1 存量 MSB3277 警告与本改动无关）；
- 逻辑复核：全屏比例 = ClientSize/逻辑尺寸与 D3D 拉伸比例一致，输入框物理位置=游戏画面框拉伸后位置；
- 待用户实测：全屏登录界面账号/密码框与画面框重合可正常点击输入；新账号/改密码窗同理；窗口模式如旧。
