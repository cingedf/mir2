# 20261113修复掉落过期NPC变量与聊天链接正则重复实例化

> 深度体检第三轮产出三处修复（用户拍板「修123」后实施），病根同类：常量模式的 Regex 未静态化，运行期高频路径反复 new Regex 实例。

## 现象

1. **Envir.UpdateItemExpiry 每件掉落物白分配**（`Server\MirEnvir\Envir.cs:2973-3016`）：每件掉落物创建（`CreateDropItem` 必经）都无条件 `new ExpireInfo()` + 新建 2 个 Regex 实例（`\[(.*?)\]` 与 `(?<Numeric>[0-9]*)(?<Alpha>[a-zA-Z]*)`）解析物品名 `[30d]` 式过期后缀——绝大多数物品名不含 `[...]`，两个 Regex 对象与 ExpireInfo 全部变成垃圾。打怪掉落为全服最高频事件之一。
2. **NPCSegment.ReplaceValue 每次 NPC 对话新建 4 个 Regex**（`Server\MirObjects\NPC\NPCSegment.cs:1366-1378`）：`ParseSay` 每行每词调用一次，NPC 对话是高频玩家操作，一段对话可触发几十上百次 `new Regex` ×4。同文件 1745 行 `ReplaceValue(MonsterObject,...)` 怪物版重载同病根，每次新建 2 个 Regex。
3. **PlayerObject.ProcessChatItems 每条物品链接聊天新建 Regex**（`Server\MirObjects\PlayerObject.cs:4365`）：每条带物品链接的聊天对每个 ChatItem `new Regex(chatItem.RegexInternalName, RegexOptions.IgnoreCase)`，不缓存。

## 排查过程

- 深度体检第三轮聚焦聊天系统、NPC 脚本执行器、存档路径、掉落系统、序列化与客户端收包，逐文件核查热路径分配：
  - Envir.CreateDropItem（2939-2956）→ UpdateItemExpiry 链路确认每件掉落物必经，Regex/ExpireInfo 位于方法体无条件段；UpgradeItem（3018-3062）纯概率链无分配，健康。
  - NPCSegment.ParseSay（1329-1344）→ ReplaceValue 确认每行每词调用；grep 全文件 Regex 使用点，确认 52/71/87/111/452 等处均为 ParseCheck/ParseAct 脚本加载期路径（运行期不跑，不动），929/945/1147 为静态 Regex.Match 调用（加载期），仅 1366/1745 两处 ReplaceValue 为运行期高频。
  - PlayerObject.ProcessChatItems（4356-4420）确认 Regex 位于每 ChatItem 循环体内；全仓 grep 确认触发点 2111-2261 共 9 处调用（私聊/组队/行会/喊话等全部聊天通道）。
- 复核两处 ReplaceValue 重载方法体引用的变量名完全一致（regex/varRegex/oneValRegex/twoValRegex），静态化后方法体可零改动；确认 `Envir.cs` 无 ExpiryBracketRegex/ExpiryNumAlphaRegex 撞名，NPCSegment 内 71/87 行局部 `regex` 变量会遮蔽同名字段（各自方法内自洽，无行为影响）。
- 确认 PlayerObject.cs 已有 `using System.Text.RegularExpressions` 但缺 `using System.Collections.Concurrent`（缓存字典所需）。

## 修复内容

1. **`Server\MirEnvir\Envir.cs`**（UpdateItemExpiry 重写）：
   - 两个 Regex 提为 `private static readonly Regex ExpiryBracketRegex / ExpiryNumAlphaRegex`（模式常量，线程安全）；
   - 新增短路：`item.Info.Name.IndexOf('[') < 0` 直接 return——绝大多数物品名无过期后缀，零 Regex 调用零分配；
   - 改为先 Match 后 `new ExpireInfo()`（匹配失败即 return），消除原「先 new 后弃」的白分配；
   - 过期时间 switch 逻辑逐字保留，行为完全等价。
2. **`Server\MirObjects\NPC\NPCSegment.cs`**（两处 ReplaceValue）：
   - 四个模式提为 `private static readonly Regex regex / varRegex / oneValRegex / twoValRegex`（置于玩家版方法前）；
   - 玩家版删除 4 行局部 `new Regex`，怪物版删除 2 行局部 `new Regex`；两处方法体其余代码零改动，引用同名字段。
3. **`Server\MirObjects\PlayerObject.cs`**（ProcessChatItems）：
   - 新增 `private static readonly ConcurrentDictionary<string, Regex> ChatItemRegexCache`；
   - `new Regex(...)` 改为 `ChatItemRegexCache.GetOrAdd(chatItem.RegexInternalName, name => new Regex(name, RegexOptions.IgnoreCase))`——同一物品链接模式只构建一次，线程安全；
   - 文件头补 `using System.Collections.Concurrent;`。

## 验证证据

- 三处改动均为「静态化 + 提前短路」的分配消除，匹配/替换逻辑与原实现逐字一致，无行为变化；仅 Envir.UpdateItemExpiry 因新增 `IndexOf('[')` 短路使无后缀物品提前 return（原实现此时除产生垃圾外也无任何可观察副作用）。
