# 20261119提升PBKDF2迭代次数

## 现象
账号密码哈希算法 PBKDF2 的迭代次数仅 50 次（Server\Utils\Crypto.cs:10），远低于任何现代安全基线（OWASP 建议 PBKDF2 至少 10 万次以上）。50 次迭代下现代 GPU 每秒可尝试数百万次密码，一旦账号数据库泄露，弱口令可在极短时间内被暴力破解。此前该改动因"提升迭代会使全账号密码失效"被登记为不修项。

## 排查过程
1. 读 Crypto.cs 确认：`Iterations = 50`、`SaltSize/HashSize = 24`、`HashAlgorithmName.SHA1`，`HashPassword` 用 `Rfc2898DeriveBytes(password, salt, Iterations, SHA1)`。
2. 追踪调用链：账号密码 `AccountInfo.Password` setter(:27) 与仓库密码(:41) 均经 HashPassword；登录校验 Envir.Login(:2769)/ChangePassword(:2715)/HTTPLogin(:2852) 均以同一迭代数重算后 `CompareOrdinal` 比对。迭代数是 PBKDF2 派生输入的一部分，改变后同一密码+盐算出的哈希完全不同 → 旧哈希全部校验失败。
3. 确认影响面：本服为自建测试环境，仅 1 个测试账号，用户明确表示完全不用担心密码失效风险。

## 修复内容
- Server\Utils\Crypto.cs:10：`Iterations` 从 50 改为 100000，附注释说明安全收益（成本约提升 2000 倍）、性能代价（单次登录仅几十毫秒）、以及"旧哈希失效需重置账号密码"的后果。
- 未升级 SHA1→SHA256：算法升级同样会使旧哈希失效且改动更大，本轮仅按用户诉求提升迭代次数，保持最小侵入。

## 验证证据
- `dotnet build Server.MirForms\Server.csproj -c Release`：**0 警告 0 错误**；
- 影响提示：现有测试账号以 50 次迭代存储的密码哈希将校验失败，需重置该账号密码后方可登录（用户已确认可接受）。
