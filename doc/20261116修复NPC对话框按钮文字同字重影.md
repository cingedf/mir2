# 20261116修复NPC对话框按钮文字同字重影

## 现象

玩家反馈：NPC 对话框中出现**相同文字重叠（重影）**——按钮/彩色/链接文字底下还垫着一层错位的白字，两层叠印看起来模糊错位。

## 排查过程

1. **服务端排除**：NPCScript.cs 每页 `player.NPCSpeech = new List<string>()` 重建后逐段 Add，`S.NPCResponse` 单一消费；ParseSay 就地替换变量，无同页重复行；无 S.Chat 气泡双发同文。
2. **客户端残留排除**：NewText 重建链完整——TextButtons 逐个 Dispose 后 Clear、TextLabel 旧槽 Text="" 后 new 覆盖、BigButtons 前置 Clear，无累积残留。
3. **根因实锤（叠印机制）**：NPCDialogs.cs 行处理循环（:426-507）中，主 `TextLabel[i]`（420×20、WordBreak、描边白字）被赋值**整行含替换后文字**（:493/:507），而 `NewButton/NewColour/NewLink` 又把**同一段文字**作为独立 AutoSize MirLabel（黄/彩/青色）画在主层之上。设计意图是彩色层精确覆盖白字，但：
   - 主层渲染 = GDI+ 纹理 + 描边偏移 (1,1) + WordBreak（MirLabel.cs:187-240）；
   - 按钮定位测宽 = `TextRenderer.MeasureText(..., TextFormatFlags.TextBoxControl)` − 10px 魔法数（按旧字体 MS Sans Serif 调死）；
   - NewLink 侧又是第三种口径 `CalculateLinkOffset`（NoPadding|NoPrefix 逐字符累计）。
   三种口径在中文字体（Microsoft YaHei 9F）下测量偏差数像素，**彩色层与底层白字无法重合 = 同字重影**。
4. 次要观感：WordBreak 折行溢出 20px 槽位与下一行叠印（非本次主修）。

## 修复内容

`Client\MirScenes\Dialogs\NPCDialogs.cs` 两处（20261116 注释标记）：

1. **链接分支**（MONSTER/NPC/ITEM）：`currentLine` 替换标记时改插 `new string(' ', displayName.Length)` **等宽空格占位**（原为 displayName 本身）——主 Label 只画空格，`NewLink` 彩色文字成为该段唯一绘制者；定位沿用 `CalculateLinkOffset(textUpToLink)`，且 textUpToLink 现含占位空格，宽度与显示宽度一致。
2. **按钮分支**（R/C/L 标记 `<B*txt/action>`）：同样改插 `placeholder = new string(' ', txt.Length)`；按钮位置从 `MeasureText(TextBoxControl)-10` 魔法数改为 `CalculateLinkOffset(text2)`（text2 为含占位的前缀）——与链接分支**统一测宽口径**，且前缀含占位后逐字符累计的起点就是按钮段开头。

彻底消除叠印：底层不再画按钮段文字，按钮层成为唯一绘制者，不再受任何测宽精度影响。占位空格数=按钮文字字符数，保证同一行后续 match 的 `offSet` 推算与显示宽度一致（中英文均成立）。

## 验证证据
