# 20261111批量开启NPC大地图显示与传送

## 现象

1. 大地图（WorldMap）右侧 NPC 列表只显示零星几个，绝大多数 NPC 不出现。
2. 大地图右下角「移动/传送」按钮永远灰死不可点。

## 排查过程

- 客户端按钮启用条件（`Client\MirForms\BigMapDialog.cs@68`）：`TargetMapIndex == 当前图 && selectedNPC.Info.CanTeleportTo`——选中 NPC 的 CanTeleportTo 为 false 时按钮灰死。
- 服务端下发链（`PlayerObject.cs@1095-1126`）：`Envir.NPCs.Where(x => x.CurrentMap == map && x.Info.ShowOnBigMap)`——NPC 必须勾 ShowOnBigMap 才会出现在大地图列表。
- 服务端传送校验（`PlayerObject.TeleportToNPC@7883-7914`）：`!ob.Info.CanTeleportTo → return`；另扣费 `Settings.TeleportToNPCCost`（部署区 Setup.ini [Game] = 3000 金币/次）。
- **数据实测**（导出文件 `Exports\4_NPC数据.csv`，644 个 NPC）：
  - ShowOnBigMap = true 仅 187（主城功能 NPC），457 未勾；
  - CanTeleportTo = true 仅 28（3 个传送石/员 + 25 个 GM 图管理 NPC），616 未勾。
- 结论：**非引擎故障，是 NPC 数据标志没人勾过**（默认 false）。两标志均为 NPC DB 布尔字段（NPCInfo.cs@35/@37），管理界面 NPCInfoForm 有对应复选框，但逐个手勾 644 个不现实。

## 修复内容（数据修复 + 工具入库）

用户决策：**两标志全勾（644 个 NPC 全部置 true）**（单人/朋友服无剧透顾虑；传送自带 3000 金币/次成本门槛防滥用）。

新增工具 `tools\NPCFlagFix\`（照 RespawnFix 模板）：

- `NPCFlagFix plan`：预览两标志当前分布（不写库）；
- `NPCFlagFix fix [bigmap|teleport|all]`：批量置 true 并保存 Server.MirDB（缺省 all）；
- 安全门：必须在含 Server.MirDB 的目录运行；Server.exe 运行时拒绝执行（防 SaveDB 冲突）；SaveDB 自动备份 DatabaseBackup。

执行流程：确认服务端已停 → 手动备份 `C:\1.40\mir2-deploy\_backup-Server.MirDB-20261111.bak`（938,957 字节）→ `fix`（变更 457 + 616 处）→ `plan` 复验 → 重启服务端。

## 验证证据

- `plan` 复验（写库后重 LoadDB）：**ShowOnBigMap = 644/644，CanTeleportTo = 644/644**，与目标一致。
- 服务端重启正常：PID 9368，7000 LISTENING，Private 3169MB（懒分配修复后正常水位），空闲 60 秒 CPU 9.3 秒 ≈ 0.16 核。
- 游戏内验收（用户侧）：大地图 NPC 列表应显示当前地图全部 NPC；选中 NPC 点「移动/传送」应扣 3000 金币传送到 NPC 身边。

## 回滚方法

- 数据：`Copy-Item C:\1.40\mir2-deploy\_backup-Server.MirDB-20261111.bak C:\1.40\mir2-deploy\Server\Server.MirDB -Force`（先停服），重启即回 10-11 深夜状态；
- 或重跑 `NPCFlagFix` 前用管理界面/SQL 按需改回个别 NPC 标志；
- 工具本身无侵入（只改 DB 不改引擎），代码无需回滚。
