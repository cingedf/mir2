# 20261116修复NPC对话框中文占位宽度重影

## 现象

用户反馈（第二轮）：NPC 对话文字仍有**白字+彩字双层重叠**（国王攻城战、行会战争、新人向导等全中文对话全部中招）。经确认 deploy Client.dll 与 Build 哈希一致（用户跑的确实是最新二进制），排除旧版可能，属首版修复方案不彻底。

## 排查过程

1. **替换链复核**：NPCDialogs.cs 链接分支 :477 与 R/C/L 分支 :497-498 的 Remove+Insert 占位替换逻辑本身正确（有赋值回 currentLine），主层 TextLabel 只画占位符，不可能画出彩字段白字。
2. **锁定真根因=占位宽度不足**：首版修复用 `new string(' ', displayName.Length)` 按**字符数**填半角空格。中文是**全角字符，1 个全角字宽 ≈ 2 个半角空格宽**——「申请沙巴克攻城战」7 个全角字只占 7 个半角空格宽度，主层占位区只有彩色层实际文字的一半宽。
3. **后果**：CalculateLinkOffset 按替换后文本（含占位空格）逐字符测量彩色层位置，但主层后续文字从「过窄的占位区」之后就开始画 → 彩色层（按真实宽度定位）与主层后续文字**错位重叠**，视觉上就是白字+彩字双层。
4. **为何纯英文场景不重现**：数字/英文是半角字符，占位宽度恰好正确。全中文 NPC 话全部中招。
5. 媒体配额耗尽，改用 OCR 脚本核读 4 张用户截图，全部为全中文对话场景，与此假说完全吻合。

## 修复内容

`Client\MirScenes\Dialogs\NPCDialogs.cs`：

1. 新增 `BuildPlaceholder(string text, Font font)` 方法（:990 附近）：
   - 逐字符 `TextRenderer.MeasureText(CMain.Graphics, ch.ToString(), font, Size(MaxValue), LinkMeasureFlags)`（NoPadding|NoPrefix，与 CalculateLinkOffset 同口径）累计真实显示宽度；
   - `spaces = Max(text.Length, Ceil(totalWidth / 5))`（半角空格典型宽 5px），返回等宽空格串；
   - 空文本返回 empty；totalWidth<=0 回退 text.Length（防御）。
2. 链接分支 :478：`new string(' ', displayName.Length)` → `BuildPlaceholder(displayName, font)`；
3. R/C/L 分支 :499：`placeholder = new string(' ', txt.Length)` → `BuildPlaceholder(txt, font)`（`font` 为类字段 `new Font(Settings.FontName, 9F)`，与 TextLabel 同实例）。
4. offSet 机制核查无碍：offSet = oldLength - currentLine.Length 每次循环重算，占位变长自动纳入后续匹配定位。

## 验证证据

- `dotnet build Client\Client.csproj -c Release`：0 错误（1 存量 MSB3277 警告与本改动无关）；
- 逻辑复核：全角字符占位长度≈ceil(全角宽/5px)≈2×字符数，与彩色层文字实际宽度对齐；
- 待用户实测：4 张截图同场景（国王攻城战/行会战争/副官/新人向导）应无双层。
