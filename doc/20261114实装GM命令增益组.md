# 20261114实装GM命令增益组

> 死接线审计 P0-1 产出：Stats 族「提升」系正面增益（49 个）在 BuffInfo.cs 全部注册，但游戏内零授予途径——底层属性逻辑完好，仅授予入口缺失。用户拍板仿 `@华丽雨光`（commit c31d69b）加 GM 命令组实装。

## 现象

- 审计确认 49 个「提升」系增益（防御提升/攻击力提升/暴击率提升/经验收益提升/金币收益提升等，BuffInfo.cs 注册行号 154-546）在服务端没有任何授予代码：NPC 脚本零使用、任务/物品零绑定，玩家永远无法获得，属「代码已实现功能、游戏内永不生效」类问题。
- 同族背景：既有 `GIVEBUFF` 脚本命令（玩家侧 NPCSegment.cs:4088-4173）仅能授予脚本写死的特定 buff，无法作为 GM 通用工具。

## 排查过程

- 核对 `Server\MirDatabase\BuffInfo.cs` 注册表：49 个「提升」系 buff 全部带 Visible/RemoveOnDeath 等属性，底层 Stats 加成逻辑完好（幸运提升 232-238、背包重量提升 240-245、暴击率提升 346、攻速强化提升 402、金币收益提升 466 等抽样确认）；客户端 BuffDialog.cs 图标 case 齐全（648 金币收益提升命中等）。
- 复核 GM 命令结构：PlayerObject.cs `@` 命令 switch（2268 StartsWith → 2291 switch(parts[0].ToUpper())），权限守卫模式 `if (!IsGM) return;`（@华丽雨光 c31d69b 同款）。
- 复核玩家侧 GIVEBUFF 的 SetBuffs.txt 预设语义（4090 读 `Envir\SetBuffs.txt`，行格式 `buff名;Key=Val;...`），确定新命令可复用同一预设回落——与脚本授予行为同源。
- 核对 AddBuff 签名（MapObject.cs:643）：`(BuffType type, MapObject owner, int duration, Stats stats, bool refreshStats = true, ...)`，duration 为相对毫秒（`Settings.Minute * 分钟`）。
- 设计取舍：**白名单制**——仅放行 49 个「提升」系正面增益（`GrantableStatsBuffs` 静态 HashSet，逐项对应 BuffInfo.cs 注册），麻痹/伤口加深等 debuff 与系统 buff 不在名单，杜绝误授。

## 修复内容（`Server\MirObjects\PlayerObject.cs`）

1. 类头部新增 `private static readonly HashSet<BuffType> GrantableStatsBuffs = new HashSet<BuffType> { ...49 项... };`（注释注明审计来源与防误授设计）。
2. `@` 命令 switch 内（`case "CHANGEGENDER":` 前）新增 `case "增益":`：
   - `if (!IsGM) return;`；`parts.Length < 2` return；
   - `Enum.TryParse<BuffType>(parts[1], true, out buffType)` 失败或不在白名单 → 提示「未知的增益名称或不在可授予名单。」并 return；
   - 分钟参数（parts[2]）缺省 60，非法/非正数回落 60；
   - parts[3..] 逐条 `Key=Val` 解析为 Stats（`Enum.TryParse<Stat>` + `int.TryParse`；格式错误 → 提示「属性参数无效（应为 Stat键=值）」并整体拒绝 return）；
   - **未给任何属性对时回落 SetBuffs.txt 预设行**（按 `StartsWith(parts[1] + ";")` 匹配，分号拆分 Key=Val 填入）——与 GIVEBUFF 同源预设（SetBuffs.txt 键名已在 commit 36dd50a 修正为枚举名）；
   - `AddBuff(buffType, this, Settings.Minute * minutes, buffStats, true);` + ReceiveChat 确认（「增益 X 已激活，持续 N 分钟。」）。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**。
- 逻辑复核：白名单外 buff 被拒；属性对解析失败整体拒绝不半授予；预设回落与 GIVEBUFF 同源；AddBuff 第 5 参显式 true（refreshStats 为死参数，无行为影响）。
- 部署验证路径（用户既定流程）：产物部署至 `C:\1.40\mir2-deploy` 后用 server.exe+客户端实测。
- 使用说明：GM 聊天框输入 `@增益 暴击率提升`（走 SetBuffs 预设属性）、`@增益 防御提升 120 MaxDC=50`（自定义时长与属性）、`@增益 伤害减免提升 60 伤害减免=30`。
