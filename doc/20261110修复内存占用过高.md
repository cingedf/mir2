# 20261110修复内存占用过高

## 现象

- 服务端私有内存 4429MB、工作集 ~4430MB（同版基线 PID 1372 实测），远高于旧 crystal 引擎版同数据的 ~963MB，8GB 物理内存的机器被单个进程压掉一半以上。

## 排查过程

1. **dotnet-counters 实测（PID 1372）**：GC Heap Size=4475MB ≈ Private 全部 → 纯托管堆，无原生泄漏。
2. **dotnet-dump + dumpheap -stat 直方图**（总 8861 万对象 4.56GB）：
   - `Cell` 42,195,626 个 = 1.35GB + `List<MapObject>` 同样 4219 万个 = 1.35GB —— 每个 Cell 字段初始化就 new 一个列表，墙格也分配。
   - `Point[]` 877MB（WalkableCells 缓存）、`Cell[,]` 338MB、`Door[,]` 338MB（817 张图每图整张门数组，无门地图也分配）。
3. **代码对照**：与旧 crystal 版 `Map.cs` 逐行一致（Cell 类/CreateMap/LoadMapCells*/GetWalkableCells），引擎无退化。
4. **真差异 = 地图数据规模**：旧版 Maps 497 文件 365MB vs 现 2257 文件（817 张有效）1474MB，4 倍数据 → 等比 4.5 倍堆。内存高是"数据规模 × 急切分配"叠加，非泄漏。

## 修复内容（`Server/MirEnvir/Map.cs`，两处懒分配改造）

### ① Cell.Objects 共享空列表（Cell 类 @3156）

- 新增 `private static readonly List<MapObject> EmptyObjectList = new List<MapObject>(0);`，字段初始化改为 `Objects = EmptyObjectList`。
- `Add()`：`ReferenceEquals(Objects, EmptyObjectList)` 时先 `new List<MapObject>` 再添加。
- `Remove()`：空列表时保持原失败告警语义（ReportCellIssue）并 return。
- 勘察依据：全库 200+ 处 `.Objects` 读取均有 null 防御或安全遍历；写入仅经 Cell.Add/Remove 两方法。墙格从此不再各持一个空 List（省约 1.35GB 中墙格份额）。

### ② Door[,] 懒分配

- 新增 `private void EnsureDoorArray()`：`DoorIndex == null` 时才 `new Door[Width, Height]`。
- 删除 LoadMapCellsv0-v4 共 9 处开头的急切 `DoorIndex = new Door[...]`；7 个写门点在写入前调用 `EnsureDoorArray()`；`CheckDoorOpen` 首行加 `if (DoorIndex == null) return true;`（无门=可通行）。
- 无门地图的 338MB 门数组归零，有门图在首扇门写入时才创建。

### 不在本轮（已知残留）

- `Point[]` WalkableCells 877MB 缓存可再省（改 ushort[]/RLE，改动大）；预计 a+b 落地后仍高于旧版属合理水位（数据规模 4 倍）。

## 验证证据

- 编译 0 错误（仅旧警告 CS0169）。
- 部署后（PID 2836）：T0 启动期 Private=3290MB → T1（+60s 空闲）3289MB，**较基线 4429MB 省 1140MB（-26%）**。
- 空闲 CPU 11.1s/60s = 0.185 核（较 Sleep(100) 版 0.27 核更低：每圈遍历分配减少、缓存局部性变好）。
- 7000 端口 LISTENING、817 张地图加载完成、Logs 无 Exception/NRE。

## 回滚方法

- 代码：`git revert <本次commit>`，或手工还原 Map.cs 两处（恢复字段初始化 `Objects = new List<MapObject>()`、恢复 9 处 `DoorIndex = new Door[Width, Height]` 与原写门循环）。
- 部署：重编译后停止 Server 进程，将 Build\Server\Release 下 9 件（Server.exe/Server.dll/Server.pdb/Server.Library.dll/Server.Library.pdb/Shared.dll/Shared.pdb/Server.deps.json/Server.runtimeconfig.json）拷回 `C:\1.40\mir2-deploy\Server`，重启。
