# 20261113修复发包批量乱序与资料查找线性扫描缓存

> 深度体检第四轮产出四项修复（用户拍板「先修1234，逐个完美修复，过程注意引用逻辑链，不能修复后带出新问题」后实施）。第四轮按热点路径审查：主循环 → 地图/对象处理 → 网络 → 缓存/容器。

## 现象

1. **发包批处理溢出重排 + 单包超限永久卡死**（`Server\MirNetwork\MirConnection.cs` TryBeginSend 630-679）：原实现 `TryDequeue` 出队后若超出 `MaxSendBatchBytes`（1MB）即 `_sendList.Enqueue(p)` **塞回队尾**——FIFO 被破坏，该包排到其后已入队包之后发送（包序错乱可致客户端不同步）；且单包 >1MB 时 `data.Count` 恒为 0 → 每次 TryBeginSend 直接 return，该包永远发不出去（客户端挂死）。
2. **五类资料查找全部 List 线性扫描、无索引**（`Server\MirEnvir\Envir.cs` 3169-3302）：`GetItemInfo(int)`/`GetMonsterInfo(int)`/`GetNPCInfo(int)`/`GetCharacterInfo(int)`/`GetHeroInfo(int)` 每次全表扫描。热度实测：`GetItemInfo(int)` 在每件掉落（CreateDropItem:2937）+ NPC 对话链接格式化（LinkFormatter.cs:49）+ 商城邮寄；`GetCharacterInfo(name)` 在结婚/师徒/邮件等（角色表可达数万条）；`GetHeroInfo` 原实现还是 LINQ `FirstOrDefault`（额外分配）。
3. **SentChatItem 为 List，`Contains` O(n) 且无上限增长**（`Server\MirNetwork\MirConnection.cs:209`）：聊天物品链接每发一次对收件人列表做线性 Contains。
4. **Map.Process ActionList 移除后跳项**（`Server\MirEnvir\Map.cs` 784-789）：`RemoveAt(i)` 不回退 i，同刻多个到期动作被隔 tick 处理（各延迟一 tick，不丢失）。

## 排查过程

- 第四轮按四段顺序核查：主循环（WorkLoop 521-703：LinkedList 游标遍历/OperateTime 门控/20ms 切片——健康）、地图对象（Map.Process 702-790：空闲门控/门关闭/地图特效/刷怪冷却——健康，唯 ActionList 跳项）、网络（MirConnection 全量：收发防洪/KeepAlive/单飞行包状态机/六段式 Process——健康，唯 TryBeginSend 两处缺陷）、缓存容器（Envir 查找族/SentChatItem）。
- ①修复前引用链核查：grep `_sendList` 全部 9 处——确认 `TryBeginSend` 是**唯一消费者**（其余为构造、IsEmpty 探测、Enqueue 生产者侧），`_sendPumpLock` 串行化泵体 + `_sendState` 单飞行包，故 TryPeek/TryDequeue 配对安全。
- ②修复前引用链核查（防带出新问题的核心）：
  - grep 全 Server 对五张表的 **Add/Clear/Remove** 全量清单——发现**运行期存在删除**：`Envir.Remove(ItemInfo/MonsterInfo/NPCInfo)`（2890-2903，管理/编辑删除）、`PlayerObject` SAVEPLAYER 归档 `CharacterList.Remove`（2861）、RESTOREPLAYER/建角色 `Add`（2944/2597）、建英雄 `HeroList.Add`（9934）、GM 建资料 `CreateItemInfo` 等（2853-2864）——**纯加载期建字典会返回已删除旧对象**，故弃用「加载期预建」方案；
  - 发现 `EditEnvir`（MirDatabase 4 个资料类的 `protected static Envir` 静态引用）仅走 Add 路径——惰性缓存的「未命中→线性扫→回填」天然覆盖新增，无需挂钩；
  - 并发面：多线程模式下 mob 线程（掉落路径 GetItemInfo）与主线程并发读——必须用 `ConcurrentDictionary`，普通 Dictionary 并发读写会损坏；
  - 同 Index 重复资料语义：回填值来自线性扫描首命中，与原「首个匹配返回」语义一致；惰性回填天然保持；
  - 确认 Envir.cs 已有 `using System.Collections.Concurrent;`（第 7 行）。
- ③修复前引用链核查：grep `SentChatItem` 全部 7 处——声明 + PlayerObject 6 处，**用法仅 Contains/Add**，无遍历/无 Remove/无重赋值；UserItem 未重写 GetHashCode/Equals（引用相等语义不变）→ List→HashSet 零行为差异。
- ④修复前引用链核查：`ActionList.RemoveAt(i)` 在 Map.cs 唯一；Map.Process(DelayedAction) 不往 ActionList 增删；正序遍历保留（保持动作执行顺序 FIFO），仅补 `i--`。

## 修复内容

1. **`Server\MirNetwork\MirConnection.cs`**（TryBeginSend 重写 ①）：
   - `while (_sendList.TryDequeue(out Packet p))` → `while (_sendList.TryPeek(out Packet p))`：先探测队首、序列化、放得下才 `TryDequeue` 入批；放不下且批非空 → `break`（**包留在队首，顺序无损**）；空包/无效包出队丢弃（与原 continue 语义一致）；防御分支：Peek 与 Dequeue 之间队首被他人消费则 break（正常不应发生）；
   - **data 为空且队首单包超限 → 强制单发**（放行该包，消除永久卡死）；
   - `_sendQueueCount` 仅在实际出队时递减，与原语义一致。
2. **`Server\MirEnvir\Envir.cs`**（②索引缓存）：
   - 新增五个 `ConcurrentDictionary<int, T>` 惰性缓存字段（ItemInfo/MonsterInfo/NPCInfo/CharacterInfo/HeroInfo）+ 公开 `InvalidateCharacterIndex(int)`；
   - 五个 getter 重写：命中 O(1) 直返；未命中走原线性扫描（逐字保留）→ 命中后回填缓存；查不到返回 null（不缓存 null）；
   - **失效钩子 6 处**：加载 Clear ×5（1407 ItemInfo / 1417 MonsterInfo / 1422 NPCInfo / 1520 HeroList / 1529 CharacterList，各紧跟 `_xxxIndexCache.Clear()`）；运行期删除 ×3（`Envir.Remove(ItemInfo/MonsterInfo/NPCInfo)` 各加 `TryRemove(info.Index, out _)`）；
   - `PlayerObject.cs` SAVEPLAYER 归档删除处补 `Envir.InvalidateCharacterIndex(data.Index)`；
   - `GetHeroInfo` 顺带由 LINQ `FirstOrDefault` 改手写循环（去 LINQ 分配，行为等价）；
   - 按名查找族（GetItemInfo(name)/GetMonsterInfo(name)/GetCharacterInfo(name)）**维持线性扫描不动**：改名/同名边界下按名缓存有返回旧数据的正确性风险，且热度低于按索引路径。
3. **`Server\MirNetwork\MirConnection.cs`**（③）：`public List<UserItem> SentChatItem` → `public readonly HashSet<UserItem> SentChatItem`（注释保留原 TODO）。
4. **`Server\MirEnvir\Map.cs`**（④）：ActionList 处理循环 `RemoveAt(i)` 后补 `i--`，同刻多到期动作不再被跳过。
