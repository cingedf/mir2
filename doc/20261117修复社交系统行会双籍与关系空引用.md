# 20261117修复社交系统行会双籍与关系空引用

## 现象

第五轮新维度审计（社交系统路线）回报 7 项缺陷，涉及行会权限错乱与关系系统崩溃：

1. **F1 行会幽灵双籍**（PlayerObject.cs:10445 GuildInvite）：玩家收到 A 行会邀请后，自己创建了 B 行会（或加入 B），再点接受 A 的旧邀请 → 同时进入 A、B 两名册，`Info.GuildIndex` 指向 A，B 名册残留幽灵成员。
2. **F2 官阶权限关闭反开**（GuildObject.cs:370 ChangeRankOption）：关闭某官阶权限（Enabled="false"）用 XOR `^=`，若该 bit 本来是关的，XOR 反而把它打开——「关闭权限操作反而授予权限」。
3. **F6 配偶删档崩溃**（GetRelationship:13909）：配偶角色删档后 `Envir.GetCharacterInfo(Info.Married)` 返回 null，直接 `Lover.Name` → NRE，玩家登录/刷新关系时报错。
4. **F7 师父删档崩溃**（GetMentor:14158）：同理 `mentor.Name` NRE。
5. **F8 师父断绝崩溃**（MentorBreak:13957）：`partner.Name` NRE。
6. **F9 拜师回复崩溃**（MentorReply:14115）：对方下线时 `student == null`，但错误提示仍传 `student.Name` → NRE。
7. **NPCDivorce 离婚崩溃**（:13486/:13499）：配偶删档后 `lover.Name`、`lover.Married` NRE。

## 排查过程

- **F1 引用链**：邀请发出点 :10331 检查了接受方 `MyGuild==null`、:10341 检查无待处理邀请、:10354 写入 `PendingGuildInvite`；但接受时刻 :10445-10478 全程未复查 `MyGuild`——发出与接受之间存在时间窗，期间玩家可自建/加入其他行会；`GuildObject.NewMember`(:222) 内部也不检查 newMember 现有行会 → 双籍实锤。
- **F2**：`ChangeRankOption` 的 Enable 分支用 `|=`（正确置位），Disable 分支用 `^=`（翻转）——布尔语义错误。
- **F6-F9/NPCDivorce**：五处均在取到关系对象后立即解引用，无判空；仓库已有先例（LogoutRelationship:13929 / LogoutMentor:14176 已做 `if (lover/mentor == null)` 判空），证明确属遗漏。

## 修复内容

**GuildObject.cs（1 处）**：
- :370 ChangeRankOption：`^=` → `&= ~(GuildRankOptions)(1 << Option)`（正确清除 bit，Enable 分支 `|=` 保留）。

**PlayerObject.cs（6 处）**：
1. F1 GuildInvite :10452 accept 分支后：加 `if (MyGuild != null || MyGuildRank != null || Info.GuildIndex != -1) { PendingGuildInvite = null; ReceiveChat(AlreadyInGuild); return; }`。
2. F6 GetRelationship :13909 后：Lover==null 时 Enqueue 空的 LoverUpdate 并 return。
3. F7 GetMentor :14158 后：mentor==null 时 Enqueue 空的 MentorUpdate 并 return。
4. F8 MentorBreak :13957：`partnerP = partner == null ? null : Envir.GetPlayer(partner.Name)`。
5. F9 MentorReply :14110 前：先存 `string requestName = MentorRequest.Info.Name;`，student==null 时用 requestName 提示。
6. NPCDivorce :13485-13486/:13499：player 取法加 lover 判空三元；对方字段更新包在 `if (lover != null)` 内，自己侧解除照常。
