# 20261114接线尊者之魂封印技能

> 审计登记项 Mon564NSealing 的接线实施（对应 doc《20261114登记未实装功能预留项》中「随尊者系 BOSS 实装一并接线」的承诺兑现）。

## 现象

- `BuffType.Mon564NSealing`（Shared\Enums.cs:1603，紧邻绝对封锁）在 BuffInfo.cs:89 注册、客户端光效（Client\MirObjects\MapObject.cs:369-371，Mon564N 帧 1016 起 10 帧循环）与 BuffDialog 图标（BuffDialog.cs:633-634，与绝对封锁共用图标 61）全就绪，但服务端全仓零 AddBuff——尊者之魂（Mon564N，AI=564）的技能代码从未写封印授予。
- 同族参照 Mon562N（尊者之王）的「绝对封锁」链路完整（Mon562N.cs:100-119）：远程 case 2 → ObjectRangeAttack 广播 → HasBuff 防重 → 30 秒内部冷却（`_BuffTime`）→ 生命值强化/法力值强化 -25 → AddBuff 300 秒。

## 排查过程

- 通读 Mon564N.cs 全文（216 行）：近战三连（半月/全月/直线 LineAttack）、近距远程 case 0（群体 MC+麻痹毒 PoisonType.Paralysis）、远距 case 1（单体大威力 MC×2，Type=1）、case 2（龙卷风 SeniorTornado，Type=2）。全类无 `_BuffTime` 字段、无 AddBuff。
- 确认接入点选择：case 1 是「单体大威力」技能（MC×2 重击），与封印 debuff 的「BOSS 重击附带削弱」设计语义最匹配（Mon562N 也是在其远程 case 单体分支加绝对封锁）；case 0 已带群体麻痹毒，叠加封印会过强。
- 效果数值决策（自主拍板）：完全复刻 Mon562N 蓝图——生命值强化/法力值强化 -25、持续 300 秒、30 秒冷却；客户端光效链路原样激活（挂上 buff 即显示 Mon564N 专属光效）。
- 安全核查：Target.AddBuff 目标可能为玩家/宠物，AddBuff 内 BuffInfo 注册存在（BuffInfo.cs:89）不会走 Info==null 拒绝分支；HasBuff 防重 + `_BuffTime` 冷却与 Mon562N 同款；Mon564N 原有伤害链逐字未动。

## 修复内容（`Server\MirObjects\Monsters\Mon564N.cs`，仅此一文件）

1. 类头部新增 `public long _BuffTime;`（仿 Mon562N.cs:9）+ 注释说明接线来源。
2. 远距 `case 1` 分支：伤害计算前插入封印授予——`!Target.Dead && !Target.HasBuff(BuffType.Mon564NSealing) && Envir.Time >= _BuffTime` 时 `Target.AddBuff(BuffType.Mon564NSealing, this, Settings.Second * 300, new Stats { [Stat.生命值强化] = -25, [Stat.法力值强化] = -25 })` 并置 `_BuffTime = Envir.Time + 30000`；原有 DelayedAction 伤害逻辑逐字保留。
