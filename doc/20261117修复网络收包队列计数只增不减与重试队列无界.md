# 20261117修复网络收包队列计数只增不减与重试队列无界

## 现象

第五轮深度审计（网络底层维度）发现两处强耦合的收包队列缺陷，影响**全体在线玩家**：

1. **收包队列计数只增不减（P1-1）**：`_receiveQueueCount` 在 `ReceiveData` 入队时 `++`，但 `Process()` 消费 dequeue 时**无对应 `--`**，仅断线时归零。健康玩家正常游戏累计发约 5001 个包（挂机走路/连击，数分钟即可达到）后即触发 `BeginDisconnect(20)` 被**误踢下线**；健康度统计读取的是累计值而非当前队列深度，永远呈 Critical。
2. **动作重试队列无界且绕过收包限流（P1-2）**：每 tick 把 `_retryList` 全部倒回 `_receiveList`，倒回不经 `ReceiveData`、不检查收包上限；7 处动作重试入口（转向/走路/奔跑/攻击/范围攻击/采集/施法）无容量检查，包在收包队列与重试队列之间无限循环。单 WorkLoop 线程串行处理，可拖慢全服 tick。
3. **每 tick 处理包数上限未接线（P2-2）**：`MaxProcessPacketsPerTick=500` 已定义但未使用，`Process()` 的 while 无上限，单连接可独占主线程。

## 排查过程

- 逐行核对 `MirConnection.cs` 队列生命周期：字段定义（:93 `_receiveQueueCount`、:99 `MaxReceiveQueue=5000`、:101 `MaxProcessPacketsPerTick=500`）→ 入队（:367 上限判断/:374 Enqueue/:375 `++`）→ 消费（:753-763 while TryDequeue + ProcessPacket，**确无 `--`**）→ retry 倒回（:770-781 直接 Enqueue，无 `++`/无上限）→ 断线归零（:1607-1609）。
- 7 处 retry 入队点全为 `_retryList.Enqueue(p);`（:2266/:2277/:2288/:2656/:2669/:2683/:2811），均无容量/过期检查。
- 确认 WorkLoop 单线程串行（Envir.cs:658-665），重试循环膨胀直接拖慢全服。
- 决策：P1-1/P1-2/P2-2 内聚一次修复，统一计数语义（入队 ++ / 消费 -- / retry 倒回 ++），避免分批改出现计数负数窗口。

## 修复内容（Server\MirNetwork\MirConnection.cs）

1. **新增常量**（:102）：`private const int MaxRetryQueue = 64;`
2. **消费循环**（:754 起）：加 `int processed = 0;`；`ProcessPacket` 前补 `_receiveQueueCount--;`（P1-1 主修）；`ProcessPacket` 后 `processed++; if (processed >= MaxProcessPacketsPerTick) break;`（P2-2），保留原连接状态 break。
3. **retry 倒回**（:773 起）：while 内加 `if (_receiveQueueCount >= MaxReceiveQueue) break;`（上限保护）；re-enqueue 后补 `_receiveQueueCount++;`（与消费处 `--` 配对，计数自洽不出现负数）。
4. **7 处 retry 入队**：`_retryList.Enqueue(p);` 全部改为统一入口 `TryRetry(p);`。
5. **新增方法**（Turn 前）：`private void TryRetry(Packet p) { if (_retryList.Count < MaxRetryQueue) _retryList.Enqueue(p); }`——超限重试直接丢弃（动作本就延迟执行，丢一个无伤大雅，远好过无限循环拖垮全服 tick）。

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：**0 警告 0 错误**；
- 计数守恒复核：ReceiveData 入队 ++ → 消费 -- → 未执行动作经 TryRetry 回 retry 队列 → 倒回 ++ → 下次消费 --，单包循环内 ++/-- 严格配对，无泄漏无负数；断线时 :1608 统一归零；
- 行为复核：正常玩家永不误触 5000 包上限；单 tick 每连接最多处理 500 包，剩余下帧继续；动作在冷却期内最多重试 64 次入队；
- 待实测：长时间挂机（走路/连击）不再数分钟被踢；全服 tick 稳定。
