# 20261114修复增益预设键名不匹配

> 死接线审计（子代理 P2-2）产出：SetBuffs.txt 四行增益预设的第一段键名与 BuffType 枚举不匹配，导致 GIVEBUFF 按名授增益时静默失效。用户拍板第一批修复。

## 现象

部署区数据文件 `C:\1.40\mir2-deploy\Server\Envir\SetBuffs.txt`（运行期由服务端按 `Settings.EnvirPath` 读取，非编译资源）第 26-29 行四个增益预设名在 `BuffType` 枚举中不存在：

| 文件原行 | 枚举实际名 |
|---|---|
| `准确命中提升;准确=0;;` | 准确提升（Shared\Enums.cs:1627） |
| `敏捷躲避提升;敏捷=0;;` | 敏捷提升（:1628） |
| `背包负重提升;背包重量=0;;` | 背包重量提升（:1633） |
| `技能经验提升;技能熟练度收益=0;;` | 技能熟练提升（:1669） |

后果：NPC 脚本玩家侧 GIVEBUFF 执行链（NPCSegment.cs:4088-4173）`Enum.TryParse<BuffType>(param[0])` 对这四个名字失败后**静默 return**——脚本想授这四个增益时整个命令无效果（属性段第二键 `准确/敏捷/背包重量/技能熟练度收益` 本身正确，问题仅在第一段名）。

## 排查过程

- 子代理全量审计（死接线/恒空参数）定位后，人工复核两端：
  - 枚举端：`Shared\Enums.cs` grep 确认四个正确名与四个错误名（错误名零存在）。
  - 消费端：NPCSegment.cs:4090 `Path.Combine(Settings.EnvirPath, "SetBuffs.txt")` 逐行 `StartsWith(param[0] + ";")` 匹配预设（4105）→ 解析 `Key=Val` 进 buffStats（4115-4131，`Enum.TryParse(statName, out Stat)`）→ 冲突拒授（4152-4162）→ AddBuff（4170）。第一段名即 TryParse 的 buff 名，匹配失败即整命令失效。
  - 第二段属性键安全核查：`Shared\Data\Stat.cs` 确认 准确=98、敏捷=99、背包重量=104、技能熟练度收益=139 全部真实存在，属性段无需动。
  - 现网影响面：部署区 `Envir` 目录递归 grep `GIVEBUFF (准确|敏捷|背包|技能)` 零命中——无任何脚本在用这四个预设，改名不破坏任何现网调用（防带出新问题核查）。
- 数据文件归属确认：SetBuffs.txt 在 mir2-deploy 仓库未被 git 跟踪（ls-files 无输出）；angelk 源码仓库不含该文件（运行期读 EnvirPath）。修复=改部署区数据文件 + angelk 仓库落修复文档。

## 修复内容

- `C:\1.40\mir2-deploy\Server\Envir\SetBuffs.txt` 第 26-29 行，仅改第一段键名（`;;` 结尾结构与第二段属性键逐字保留）：
  - `准确命中提升` → `准确提升`
  - `敏捷躲避提升` → `敏捷提升`
  - `背包负重提升` → `背包重量提升`
  - `技能经验提升` → `技能熟练提升`
- 无代码改动； angelk 仓库落本文档记录。

## 验证证据

- 属性键段未动（准确/敏捷/背包重量/技能熟练度收益在 Stat.cs 98/99/104/139 均存在）。
