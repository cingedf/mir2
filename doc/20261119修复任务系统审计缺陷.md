# 20261119修复任务系统审计缺陷

## 现象

新维度审计（任务/成就/活动路线）回报 3 项缺陷，其中 1 项 P0 可被任意玩家用伪造包触发全服停机，1 项 P1 可由配置错误导致主循环死循环：

1. **P0 AcceptQuest 未校验任务存在 → NRE → 熔断全服停机**（PlayerObject.cs）：客户端 `C.AcceptQuest.QuestIndex` 完全由客户端提供，传入不存在的任务 index 且当前地图有 NPC 时，服务端解引用 null 的 QuestInfo → NRE。该异常经无 try 的 ProcessPacket 冒泡到 Envir 逐连接 catch → ErrorCircuitBreaker.Record()，单客户端一帧可发 500 包打满 500 次/60 秒阈值 → 有序停机（踢全服 + 存档）。
2. **P1 任务发奖 StackSize==0 死循环**（PlayerObject.cs 三处）：AcceptQuest 发 CarryItems、FinishQuest 发 FixedRewards/选中奖励的 `while(count>0)` 循环，物品 StackSize 配置为 0 时 `count -= 0` 恒定 → 主线程永久死循环（非异常，不走熔断）。
3. **P2 运行期删除任务未清理玩家状态**（Envir.cs）：GM 运行期删除 QuestInfo 只移全局列表，未清角色任务进度 → 进度静默丢失（登记不修，见下）。

## 排查过程

逐项读现场核实子代理报告（历史多次误报，必须验证引用链）：

- **P0**：读 PlayerObject.cs:11781-11819 AcceptQuest 全貌——:11787 `QuestInfo info = Envir.QuestInfoList.FirstOrDefault(d => d.Index == index);` 未判空，紧接着 :11793 `if (CurrentMap.NPCs[i].ObjectID != info.NpcIndex) continue;` 解引用 info。客户端包 `Shared\ClientPackets.cs:1916 C.AcceptQuest.QuestIndex(int)` 任意提供，经 MirConnection.cs:3314 直接透传。放大链：MirConnection ProcessPacket 无 try → Envir.cs ErrorCircuitBreaker（阈值 500 次/60 秒）→ 有序停机；单 tick 上限 500 包（MaxProcessPacketsPerTick）。**子代理建议的 AbandonQuest/FinishQuest/ShareQuest 防御判空**：读现场确认 FinishQuest :11882 已用 `quest == null` 保护（quest 来自 CurrentQuests 必非空），AbandonQuest/ShareQuest 无同类裸解引用，故不扩大改动，仅修 AcceptQuest 一处。
- **P1**：读 PlayerObject.cs:11837-11950 三处发奖循环，确认 StackSize 为 ushort（ItemData.cs 默认 1，编辑器可写 0），`if(StackSize>count)`/`>=count` 的 else 分支 `count -= StackSize`，为 0 时 count 恒定 → 死循环。对照 GameshopBuy :14373 已用 `if(StackSize==0)return` 修过同类，任务系统遗漏。
- **P2**：读 Envir.cs:3270-3274 `Remove(QuestInfo)` 仅 `QuestInfoList.Remove(info)` + 注释占位，对比 Remove(NPCInfo) 有实际索引清理动作。

## 修复内容

均在 Server\MirObjects\PlayerObject.cs，附 20261119 注释：

1. **P0 AcceptQuest 判空**（:11787 后）：加 `if (info == null) return;`——index 不存在时直接返回，杜绝 info.NpcIndex 解引用 NRE，切断熔断停机利用链。
2. **P1-① CarryItems**：carryItem foreach 内 while 前加 `if (carryItem.Item.StackSize <= 0) continue;`——StackSize 为 0 时跳过该奖励项。
3. **P1-② FixedRewards**：FinishQuest reward foreach 内 while 前加 `if (reward.Item.StackSize <= 0) continue;`。
4. **P1-③ SelectRewards**：FinishQuest for i 内 while 前加 `if (quest.Info.SelectRewards[i].Item.StackSize <= 0) continue;`。

三处守门均用 ItemInfo 直访 StackSize 字段 + continue 跳过整个奖励项，对齐 GameshopBuy 既有修法，不改变原 while 内判断逻辑。

**不修（记录在案）：**
- **P2 Remove(QuestInfo)**：改动面大（需遍历全服角色 + 在线玩家清 CurrentQuests/CompletedQuests 并同步客户端）；运行期删任务是 GM 低频操作，重启后登录的孤儿任务判定（CharacterInfo.cs:274）本就过滤，进度丢失限于当前会话。风险收益不成比例，保持现状。

- 待用户实测：正常接任务/交任务/选奖励，伪造 QuestIndex 不再导致停机。
