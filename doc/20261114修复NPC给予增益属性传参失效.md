# 20261114修复NPC给予增益属性传参失效

## 现象

NPC 脚本 `GIVEBUFF` 命令的**属性参数整体失效**。命令文档格式（`Envir\NPCs\NPC命令说明.txt:219-226`）：

```
GIVEBUFF 名称 秒数 TRUE FALSE FALSE MaxDC=12
```

第 6 段起的 `Key=Val` 属性对是设计上给 buff 附加属性加成的入口，但执行代码固定传 `new Stats()`（空加成）——现有脚本里的属性意图从未生效过。实际脚本案例（数据区 `C:\1.40\mir2-deploy\Server\Envir\NPCs`，与 angelk 仓库无关）：

- `游戏活动\雕刻师德勋.txt:58`：`GIVEBUFF 龙之特效 3600 TRUE FALSE FALSE MaxDC=12`（意图：下限攻击+12）
- `游戏活动\勇气战场\红方战斗传送-Valor.txt:5`、`蓝方战斗传送-Valor.txt:5`：`GIVEBUFF 荣誉战场 10 TRUE FALSE FALSE MaxAC=100 MaxMAC=100`（意图：双防+100）
- `飞天县\飞天城\皇宫副官-0.txt:41`：`GIVEBUFF 监禁 300 TRUE FALSE FALSE`（无属性，不受影响）

另发现一处**旗标错接**：脚本的 visible 旗标（第 4 段）被传入 `AddBuff` 第 5 参——该位置实为 `refreshStats`。因 `refreshStats` 在 `AddBuff` 内是从未被消费的死参数，历史上无行为差异，但属明确的接线错误。

## 排查过程

- **ParseAct 组装**（`NPCSegment.cs:959-976`）：`case "GIVEBUFF"` 要求 `parts.Length >= 4`；组装 allParams = {parts[1]=buff名, parts[2]=秒数, visible=parts[3], infinite=parts[4], stackable=parts[5]} + additionalParams=parts[6..]（Key=Val 原样入队）→ `new NPCActions(ActionType.GiveBuff, allParams.ToArray())`。即脚本第 6 段起 Key=Val **确实进入了 param[5+]**，数据链没断，断在执行端。
- **执行处**（原 `NPCSegment.cs:5186-5198`）：`Enum.IsDefined` 校验 buff 名 → 解析秒数与三个 bool 旗标 → `monster.AddBuff(type, monster, Settings.Second * tempInt, new Stats(), visible);` —— 属性参数被丢弃，`new Stats()` 硬编码；`visible` 传入第 5 参。
- **AddBuff 签名**（`MapObject.cs:643`）：`AddBuff(BuffType type, MapObject owner, int duration, Stats stats, bool refreshStats = true, bool updateOnly = false, params int[] values)` —— **第 5 参是 refreshStats，不是 visible**（AddBuff 根本没有 visible 形参，可见性由 `Envir\SetBuffs.txt` 注册决定）；且 `refreshStats` 全文件仅签名一处命中、从未被消费（死参数）——故错接历史上无行为差异。
- **Stat 枚举键名核对**（`Shared\Data\Stat.cs:85`，全局命名空间）：MaxDC=5、MaxAC=1、MaxMAC=3、HP=12、MP=13 等，**与脚本 Key 名完全一致**，`Enum.TryParse<Stat>(key, ignoreCase)` 可直接映射；`Stats` 类有 `stats[Stat.MaxDC] = 12` 索引器。
- **param 类型**：`List<string>`（非数组）；`ParseAct` 保证最少 5 元素（缺省段为空串），`bool.TryParse("")` 安全得 false，无越界风险。

## 修复内容

**`Server\MirObjects\NPC\NPCSegment.cs`**（GiveBuff 执行 case，约 5186-5222）：

1. 保留：`Enum.IsDefined` 校验、秒数解析、infinite/visible/stackable 三旗标解析（**维持脚本兼容、不扩展语义**，仅不再误传）；
2. 新增属性解析：`var buffStats = new Stats();` 后循环 `param[5..]`——空段跳过；按 `=` 分割，段格式错误（非 `键=值`）记 `MessageQueue.Enqueue("NPC脚本 GIVEBUFF 属性参数格式错误（应为 键=值）: ...")` 后继续；`Enum.TryParse(pair[0], true, out Stat statKey) && int.TryParse(pair[1], out int statVal)` 成功则 `buffStats[statKey] = statVal;`，键名无法识别记日志后继续（**单条参数错误不中断整条命令**）；
3. `AddBuff` 调用改为 `monster.AddBuff(type, monster, Settings.Second * tempInt, buffStats, true);`——属性真实传入；第 5 参显式 `true`（refreshStats 缺省值本就是 true，且其为死参数，行为等价收敛；visible 旗标不再流入）。

编译期修正两处：`param.Length` → `param.Count`（CS1061，List 无 Length）；循环变量 `i` → `p`（CS0136，与外层 NPC 执行循环的 `i` 冲突）。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**（17.33s）。
- 逻辑复核：`param[5..]` 为 ParseAct 原样透传的 Key=Val 对；`Stat` 键名与脚本一致；属性写入 `buff.Stats` 后由引擎既有的 buff 属性载体链路消费（与 `SetBuffs.txt` 注册 buff 的属性同路径）；无属性脚本（如监禁）解析循环零次迭代，`buffStats` 为空 Stats，与原 `new Stats()` 完全一致。
- **建议上线实测**：让雕刻师德勋给玩家上「龙之特效」，确认攻击下限 +12 生效、荣誉战场进出后双防 +100 生效。
