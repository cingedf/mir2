# 20261115修复矿石窗打开后采矿几率下拉为空

## 现象
- 打开 server.exe → 矿石窗后不做任何操作，切到「矿石开采率」页，顶部方案下拉已显示首方案、
  但「矿石开采率」下拉框是空的；只有手动在顶部方案下拉里重选一次后，几率下拉才出现数字编号。

## 排查（代码意图）
- 构造函数 `MineIndexcomboBox.DataSource = mineIndexItems` 会自动选中首项并同步触发 SelectedIndexChanged；
- 但事件处理首行守卫 `if (ActiveControl != sender) return;` 在构造期不成立（ActiveControl 为 null）→ 提前返回，
  **几率编号列表填充代码从未执行**；
- 随后构造函数调用的 `UpdateMines()` 只按当前选中项回填文本框，不负责填充几率下拉 Items；
- 用户手动重选方案时 ActiveControl==方案下拉，守卫放行 → Items 填充 → 现象与用户描述完全吻合。
- 结论：缺陷非设计意图，守卫只应拦截「程序化改选」（如增删方案后的重绑定），初始加载属于漏补场景。

## 修复
- MiningInfoForm.cs：
  - 抽出 `RefreshMineDropsItems()`（按选中方案填充几率下拉编号，逻辑与原事件内联代码逐字一致，
    对 SelectedIndex 增加 `>= 0` 防御，防 -1 索引越界）；
  - 构造函数在 DataSource 绑定后、UpdateMines() 前显式调用一次（补上初始加载漏掉的填充）；
  - SelectedIndexChanged 事件改为调用该方法（行为等价）。
- 增删方案按钮路径（ActiveControl 守卫拦截后手动 Clear/Update 的既有流程）未触碰。

## 验证
- dotnet build Server.MirForms\Server.csproj -c Release → 0 警告 0 错误。
- 运行验证点：打开矿石窗直接切「矿石开采率」页，几率下拉即有编号可选，无需先动顶部方案下拉；
  手动切换方案、+/- 增删几率行为不变。
