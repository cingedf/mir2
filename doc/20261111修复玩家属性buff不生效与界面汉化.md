# 20261111修复玩家属性buff不生效与界面汉化

## 现象

上一轮 `20261111修复玩家信息窗口属性框与搜索区布局` 验收时发现两问题：

1. **属性修改保存后客户端 F10 角色属性面板无变化**——保存提示成功，但玩家游戏内属性不变（服务端buff 链疑似失效）。
2. 搜索区布局已修复（用户认可），但界面存在**遗留英文文案**未汉化，且用户要求把 Server.exe 界面遗漏的英文一并汉化。

## 排查过程

### F10 不变化根因（双因叠加，全部实读源码确认）

1. **RemoveBuff 是标记删除**（`MapObject.cs@712-741`）：仅置 `FlagForRemoval=true + ExpireTime=0`，实际移除发生在 `HumanObject.ProcessBuffs`（@445-514，每秒 tick）。
2. 旧代码「先 RemoveBuff×8 再 AddBuff 同类型」：AddBuff 命中旧 buff（HasBuff 为真）走 `ResetStatAndDuration` 分支（重置 ExpireTime 与 Stats），**但清不掉 FlagForRemoval 标记**——下个 tick 照样把 buff 删掉。
3. 即使走新建分支：duration=0 且该 buff 的 StackType=ResetStatAndDuration（非 Infinite）→ ProcessBuffs 中 `ExpireTime -= change` 变负 → **buff 活不过 1 秒就被自动移除**（S.RemoveBuff 下发客户端 → 客户端也移除 → 属性回滚）。

结论：buff 存活时间 <1 秒，F10 自然看不到变化。客户端链路（S.AddBuff → BuffsDialog → User.RefreshStats）本身无问题。

### 汉化扫描

grep 全库 Server.MirForms 英文用户可见文案（MessageBox/Text/占位/列头），确认遗漏清单（见修复内容）。

## 修复内容

### ① ApplyStatsBuff 重写（PlayerInfoForm.cs）

- **去掉「Remove+Add」组合**：直接 `target.AddBuff(BuffType.防御提升, target, int.MaxValue, stats, true, false)`——
  - StackType=ResetStatAndDuration 会在旧 buff 存在时自动覆盖时长与数值（不碰 FlagForRemoval）；
  - duration=int.MaxValue 防 tick 过期；`RemoveOnDeath | RemoveOnExit` 特性仍保证死亡/下线自动清除（临时语义不变）。
- **新增清空分支**：8 个属性框全部留空保存 → RemoveBuff×8 清除之前的临时属性，弹提示「已清除临时属性」。
- 注释完整记录「为何不能用 0 时长 / 为何不能用 Remove+Add 组合」，防回归。

## 已知残留

- buff 持续时长为 int.MaxValue（本会话内永久），属「临时属性」设计：死亡/下线即失效、不写存档——这是方案 B 的既定语义，非缺陷。

## 回滚方法

- 代码：`git revert <本次commit>`；或恢复 ApplyStatsBuff 为「Remove+Add、duration=0」旧写法（不推荐，会复现 1 秒失效问题）。
- 部署：重编译后把 Build\Server\Release 下 9 件拷回部署区，重启服务端。
