# 20261119修复英雄宠物系统缺陷

## 现象

对从未系统审计的「英雄/宠物/灵宠/召唤兽」维度深度审计，回报 2 个 P1 + 3 个 P2 真实缺陷：

1. **P1 满级经验刷级卡死**（HeroObject.cs + PlayerObject.cs）：英雄/玩家经验表达到上限（500 级）后，升级 while 循环把等级一路刷到 65535（约 6.5 万次属性重算卡主线程，属性爆炸）。
2. **P1 死英雄无法用复活卷轴自救**（HeroObject.cs UseItem）：方法入口的 `Owner.Hero.Dead` 提前拦截使复活卷轴分支成死代码。
3. **P2 CurrentHero setter 空引用**（PlayerObject.cs）：英雄封印/删除后 `Info.Heroes[x]=null` 留空洞，遍历未判空 → 登录/换英雄 NRE。
4. **P2 SetAutoPotValue 参数未校验**（PlayerObject.cs）：客户端可传任意 Stat 值，全部走到改写 MP 百分比分支。
5. **P2 HeroInfo.Load 背包数量无钳制**（HeroInfo.cs）：损坏/篡改存档的巨大 count 可致 Array.Resize OOM。

## 排查过程

逐项读现场核实（历史多次出现子代理误报，必须验证引用链）：
- P1 刷级：读 `GainExp` 循环 + `RefreshMaxExperience`（`MaxExperience = Level < List.Count ? List[Level-1] : 0`）+ `RefreshLevelStats` 内调用刷新——确认满级时 MaxExperience=0，`while(experience>=0)` 恒真且 `experience-=0` 不变，靠 `Level>=ushort.MaxValue` 才停。PlayerObject 同结构（ExperienceList 同为 500 项）。
- P1 复活卷轴：读 UseItem :329 提前 `return` + :345「Dead 且非卷轴 shape6 拒绝」+ :487-499 复活卷轴分支 `if(Dead) Revive(...)`——确认 :329 使后两者不可达。
- P2 三项：读 CurrentHero setter、SetAutoPotValue、HeroInfo.Load，均确认现场与报告一致。

**核查后确认非缺陷（不修）**：ChangeHero 索引越界/SetHeroBehaviour 枚举校验/ChangePMode 校验已修；HeroBehaviour 7 状态机完整无死锁；IntelligentCreature Die 已捕获 Master 防无限刷；ManualPickup 范围校验已加；英雄装备/背包/灵宠数量上限均有校验；WinExp 主从分成无重复结算；HeroInfo 版本门读写对称；DeathDrop 分堆已用 Clone。

## 修复内容

1. **满级刷级**（HeroObject.cs + PlayerObject.cs GainExp）：入口加 `if (MaxExperience <= 0 || Experience < MaxExperience) return;`——满级后直接返回不再升级（经验仍累加显示），行为等价收敛。
2. **复活卷轴**（HeroObject.cs UseItem :329）：删除 `if (Owner.Hero != null && Owner.Hero.Dead) return;` 提前拦截，统一由 :343 的 `Dead && 非复活卷轴` 判断精确管控，死英雄可用卷轴自救。
3. **CurrentHero setter**（PlayerObject.cs）：遍历加 `if (Info.Heroes[i] == null || ...) continue;` 判空。
4. **SetAutoPotValue**（PlayerObject.cs）：改为显式 `if(HP)... else if(MP)... else return;`。
5. **HeroInfo.Load**（HeroInfo.cs）：`int count = Math.Clamp(reader.ReadInt32(), 0, 42);`（英雄背包上限 42）。
