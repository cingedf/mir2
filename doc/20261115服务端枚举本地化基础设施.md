# 20261115服务端枚举本地化基础设施

> 顺带汉化线基础设施步（用户 @717@「继续实施基础设施 + 批量列头汉化。逐个落盘，确保不要遗漏任何。」）。为 server.exe 编辑器 UI 的英文枚举显示（Stat 列头 MinAC/HP、BindMode/SpecialItemMode 下拉、LightSetting 等）提供本地化查询通道；后续 H1-H8/H12 列头汉化逐窗体消费本设施。

## 现象

- server.exe 数据库编辑器各窗体的动态列头/下拉直接 `Enum.ToString()`/`SeperateCamelCase` 显示英文（MinAC/MaxAC/BindOnEquip/Normal/Dawn 等），管理员界面大面积英文。
- 服务端本地化基础设施缺位：`GameLanguage.ServerTextMap.Enum` 为空字典、`localizationEnumTypes` 缺 BindMode/SpecialItemMode/LightSetting/RequiredType 四类、无服务端枚举本地化查询扩展方法——即使 json 写了 Enum 段也会被启动加载逻辑抹掉。

## 排查过程

- 全景取证（explore 子代理 ses_e22f0ee13ffe530eSJ6EBO8jwK）：英文显示点 H1-H14 全清单 + 不建议汉化的契约层 N1-N9（Stat 枚举名是 INI 节名/SetBuffs 键/@增益参数/NPC 脚本键/CSV 列名五层共用解析契约，只能改显示映射）。
- Language.cs 精读发现加载逻辑两处反向行为：①`LoadServerLanguage` 的 Enum 覆盖循环以**内存字典为基准**迭代——内存 Enum 字典为空时循环体不执行，json 里的键全部丢失；②随后的数量不等判断（json 键数>内存 0）触发 `SaveServerLanguage` 重写文件——**把 json Enum 段直接抹掉**。即当前架构下服务端 json 加 Enum 段必被启动过程清除。
- 枚举成员全表取证（json 映射键需精确）：LightSetting 5 成员/BindMode 17/SpecialItemMode 13/RequiredType 12/Stat 英文键 14（MinAC..MP+Hero/Unknown）。
- `ToLocalizedString`（4272-4280）只查 ClientTextMap.Enum——客户端专用；服务端需平行通道避免污染客户端语义。

## 修复内容（`Shared\Language.cs` 三处）

1. **`localizationEnumTypes` 补 4 类**：`typeof(RequiredType)/typeof(BindMode)/typeof(SpecialItemMode)/typeof(LightSetting)`（客户端与服务端预填充同步受益）。
2. **新增 `PopulateEnumToServerTextMap`**（与客户端版同构 TryAdd）+ 静态构造函数同步调用——启动时把 12 类枚举全部成员以 `类型_成员名 → 成员名` 预填充进 `ServerTextMap.Enum`。
3. **`LoadServerLanguage` 重写合并逻辑**：Enum 段改为**以 json 键集为基准** `ServerTextMap.Enum[item.Key] = item.Value`（json 有则覆盖/新增），删除「数量不等触发 SaveServerLanguage 重写」分支（该分支会抹掉 json Enum 段）；同时把 json Enum 键同步灌入 `ClientTextMap.Enum`（服务端进程内 `ToLocalizedString` 查询路径也受益，客户端语义不变）。
4. **新增 `ToLocalizedServerString(this Enum)`**：查 `ServerTextMap.Enum`（键=类型_成员名），查不到回退 `ToString()`，与客户端 `ToLocalizedString` 语义一致——后续窗体列头/下拉统一消费此方法。
