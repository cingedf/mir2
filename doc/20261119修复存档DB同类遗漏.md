# 20261119修复存档DB同类遗漏

## 现象

存档/数据库层深度审计回报 5 项缺陷，其中 3 项为「同类遗漏」——同层其它路径已加固、唯独这几处漏改，可导致活档永久丢失/账号数据丢弃/GT 地图数据重启回滚：

1. **P0 SaveAccounts 裸原子替换**（Envir.cs SaveAccounts）：中途异常 → MirADB 活档永久丢失（全账号/角色/金币/仓库）。
2. **P1 归档致 0 角色账号被丢弃**（LoadAccounts）：角色被归档后账号因「0 角色」被整条跳过 → Storage/Gold/密保/Admin 全部丢失。
3. **P1 GTMapList 写不读**（SaveDB 写 / LoadDB 不读）：GT 地图信息每次重启回滚为默认值。
4. **P2 SaveGoods NeedSave 不清**：每周期重复全量重写所有改过商品的 NPC。
5. **P2 LoadDB/LoadAccounts 损坏档零容错**：主档物理损坏启动崩溃。

## 排查过程

1. **SaveAccounts** 现场：三步舞步 `File.Create(AccountPath+"n")` → 写 → `File.Move(活档, "+o")` → `File.Move("n", 活档)` → 删 "+o"；catch 仅 `MessageQueue.Enqueue(ex)` 无回滚。对比 BeginSaveAccounts（有 GUID .bak + File.Copy 保留活档）、EndSaveAccounts（catch 内 +o→活档回滚）——唯一未加固路径。
2. **归档丢弃**：AccountInfo(BinaryReader) 三处归档分支（删除超期/从未登录超期/离线超期）`SaveArchivedCharacter` 后 continue 不加入 Characters；LoadAccounts `if (i>0 && Characters.Count==0) continue` 把归档致空账号当空系统账号跳过，不进 AccountList；下次 SaveAccounts 只写 AccountList → 该账号数据永久丢失。
3. **GTMapList**：SaveDB 尾部无条件写 `GTMapList.Count` + 各 `GTMap.Save`；LoadDB 读到 RespawnTick 后块尾直接返回，不读 GTMapList。GTMap(reader) 构造器与 Save 对称存在；建图时 `GTMapList.FirstOrDefault(x=>x.Index==GTIndex)` 复用已存 GT。
4. **SaveGoods**：`if(!npc.NeedSave) continue` 写盘后不清标志（NeedSave 仅 NPCObject.cs:110 置 true）；对比 SaveGuilds/SaveConquests 写盘后清零已加固。
5. **损坏档容错**：直接 `File.OpenRead + ReadInt32` 无 try/catch。

## 修复内容

1. **F1 SaveAccounts**（Envir.cs）：整段包 `lock(LoadLock)`（可重入）；File.Create 前对已存在活档做带 GUID 的 .bak 备份到 AccountsBackUpPath；catch 内补 +o→活档回滚（嵌套 try/catch 保护回滚本身）。
2. **F2 归档丢弃**（Envir.cs + AccountInfo.cs）：AccountInfo 加内存字段 `public bool CharactersArchived;`（不参与序列化，不改存档格式）；三处归档分支 continue 前置 `CharactersArchived = true;`；LoadAccounts 跳过规则加 `&& !NextAccount.CharactersArchived`——真正空系统账号仍跳过（行为等价），归档致空账号保留。
3. **F3 GTMapList**（Envir.cs LoadDB）：lock 内、Settings.LinkGuildCreationItems 之前补读——`if (reader.BaseStream.Position < reader.BaseStream.Length)` 判剩余字节（兼容旧档无此段），`gtCount` 合理性校验 [0,10000] 防损坏档 OOM，try/catch 兜底；GTMap(reader) 读 9 字段与 Save 对称。
4. **F4 SaveGoods**（Envir.cs）：写盘 BeginWrite 后 `npc.NeedSave = false;`（异步回调只拿 fStream 无法定位 npc，故不做失败复位，仅降低重复重写）。

**不修（登记利弊）：**
- **F5 损坏档零容错**：改动面大涉及启动流程，存档损坏本就需人工介入，自动降级选错备份风险高；保持现状 + 依赖 F1 的 .bak 备份与人工恢复。
- **F1 Saving 并发互斥**：加 `Saving=true` 与 shutdown 等待存在互锁风险，且文件操作窗口极短；保留 while 等待原样。
- **F4 异步失败复位**：回调拿不到 npc 引用，复位需重构回调参数传递，收益有限。

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：**0 警告 0 错误**；
- 行为复核：正常存盘/加载路径不变；归档账号数据不再丢弃；GT 地图数据重启后正确恢复；损坏档补读有 try/catch 兜底不会崩启动；
- 待实测：归档角色后账号金币/仓库保留；GT 地图房价/会长等数据重启不回滚。
