# 20261119修复任务日常活动缺陷

## 现象

任务/成就/日常活动维度审计回报 5 项 P2/P3，核心是跨天重启后每日任务永久无法刷新，以及任务旗标边界漏判、列表清理跳项：

1. **F1 跨天重启每日重置永久失效**：服务器在午夜前停止、午夜后重启，则当日所有玩家的每日任务再也无法自动刷新（CompletedQuests 中的每日记录永不清除、Daily NPC 永不触发）。
2. **F2 重复任务作前置致任务链死**（配置面窄，登记不修）。
3. **F3 FLAGTASKS 旗标 999 边界漏判**：编号取到上限的任务旗标永远无法判定完成。
4. **F4 每日重置时刻为 UTC 0 点（北京 8 点）**（设计选择，登记不修）。
5. **F5 ClearDailyQuests 正序 RemoveAt 跳项**：连续重复的每日完成记录清理不净。

## 排查过程

- **F1**（逐层读全确认）：
  - `Envir.cs:274 dailyTime = DateTime.UtcNow.Day`（静态初始化仅在进程启动时赋值）；
  - `Envir.cs:1047 Process()` 中 `if (Now.Day != dailyTime) { dailyTime=Now.Day; ProcessNewDay(); }` 是日切换的**唯一触发点**；
  - `Envir.cs:3894 ProcessNewDay()` 遍历 CharacterList → ClearDailyQuests + `NewDay=true` + 在线玩家 CallDefaultNPC(Daily)；
  - `CharacterInfo.cs:69 NewDay` **未参与序列化**（Save :405-424 / Load 均无 NewDay），重启后一律 false；
  - `PlayerObject.cs:1239` 登录时 `if (Info.NewDay) CallDefaultNPC(Daily)`——但 NewDay 恒 false 故不触发；
  - `PlayerObject.cs:282` 构造函数每次登录立刻把落盘 `LastLoginDate` 覆盖为 `Envir.Now`。
  - 结论：停机跨午夜 → 重启时 dailyTime 已是新的一天 → Process() 日切换永不触发 → NewDay 恒 false → 每日任务永久卡死。落盘 `LastLoginDate`（CharacterInfo.cs:35 声明、:160 读、:418 写）是唯一可判据。
- **F3**：`QuestProgressInfo.cs:414 for (j < Flags.Length-1000)`；`QuestInfo.cs:339 ParseFlag` 允许 `number ≤ FlagIndexCount-1000`（=Flags.Length-1000），循环上界开区间漏掉最后有效 index。
- **F5**：`Envir.cs:4061 ClearDailyQuests` 内 `for(i...) { if(...) RemoveAt(i); }` 正序删除会跳过紧邻后继元素。

## 修复内容

1. **F1**（PlayerObject.cs + Envir.cs）：
   - 构造函数中、`:282 Info.LastLoginDate = Envir.Now` **覆盖之前**插入：`if (info.LastLoginDate.Date != Envir.Now.Date) info.NewDay = true;`——用落盘上次登录日期判定跨天，置 NewDay 标记（同日重登落盘已是今天，不重复触发）。
   - 登录流程 `if (Info.NewDay)` 分支内，CallDefaultNPC(Daily) 前补 `Envir.Main.ClearDailyQuests(Info);`——补做 ProcessNewDay 未执行时的每日任务清理（RemoveAll 幂等，重复清理无害）。
   - `Envir.ClearDailyQuests` 由 private 改 public 供登录流程调用。
2. **F3**（QuestProgressInfo.cs:414）：`j < Flags.Length - 1000` → `j <= Flags.Length - 1000`（含上界），附中文注释。
3. **F5**（Envir.cs ClearDailyQuests）：正序 `RemoveAt(i)` 改 `info.CompletedQuests.RemoveAll(index => index == quest.Index);`（一次清净，无跳项）。

**不修（登记利弊）：**
- **F2 重复任务作前置**（PlayerObject.cs:11995 重复任务不写 CompletedQuests + QuestInfo.cs:355 CanAccept 依赖 CompletedQuests）：属编辑器配置错误（把"重复任务"设为其它任务的前置本身不合理），触发面极窄，改动会牵动任务链判定语义，收益不抵风险。
- **F4 每日重置 UTC 0 点 = 北京 8 点**：全局 UTC 时间基准是既有设计（Envir.Now 等均 UTC），单改日切换基准会造成时间口径不一致，属设计层调整，不动。

## 验证证据

- `dotnet build Server.MirForms\\Server.csproj -c Release`：**0 警告 0 错误**；
- 行为复核：正常跨午夜运行路径不变（ProcessNewDay 已清 + 设 NewDay，登录补做清理幂等）；停机跨午夜重启后首次登录补清每日任务并发奖、NewDay 随后置 false；同日多次登录不重复发奖；旗标上界任务可正常完成；
- 待实测：跨天重启后每日任务正常刷新、旗标 999 任务可完成。
