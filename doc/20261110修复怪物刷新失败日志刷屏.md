# 20261110修复怪物刷新失败日志刷屏

## 现象

- `Logs\Spawn\Spawn (10-11-2026).log` 从开机起每分钟成片刷「怪物刷新失败」，单日累计 97KB+，涉及地图 452/453（般若神殿5层东/西），后续复验又发现 202（祖玛神殿一层）、237（石墓四层）同类问题。
- 服务端无人在线时每分钟产生数十条失败重试日志（日志门：Map.ProcessRespawns 失败冷却 1 分钟，ErrorCount 达 5 记日志一条，直到成功为止——失败不成功日志永不停）。

## 排查过程

1. **失败判定链**（Map.cs）：`MapRespawn.WalkableCells = 全图可行走格 ∩ 刷怪框(Location±Spread)`；`MonsterObject.Spawn` 失败仅两条件：Map==null（不可能）或 **框内可行走格=0**。
2. **诊断工具**：新写无头探针 `tools\SpawnProbe`（LoadDB + Map.Load 复算每个刷怪框的可行走格数），直读部署区真实 Server.MirDB + Maps。
3. **根因实测（四图各异）**：
   - **452/453**（D2075/D2076）：.map 实际尺寸 **200×200**，但 DB 刷怪点按 **400×400 设计网格**布置——46 点/图，坐标 (50/150/250/350)²、spread=100。凡坐标含 350 的框全部落图外（框内格=0），250 系框也越界一半。每图 **18 个死框**。
   - **202**（D501，400×400）：怪 117 三个残点 (100,660)/(660,100)/(660,660)±120——660 系坐标超出 400 图幅（疑似其他服务器大图配置残留）。
   - **237**（D714，400×400）：怪 236/240/192 三组同点 (309,19)±40——坐标在图幅内但落在地图顶部实心墙区。
4. 全库扫描确认其余 813 张地图刷怪框正常。

## 修复内容

### ① DB 修正（工具执行，非手改）

新写迁移工具 `tools\RespawnFix`（仿 GameShopMigrate：无头 LoadDB→变换→逐框复验→SaveDB；内置安全检查：Server.exe 运行时拒绝执行、任何框变换后仍为 0 拒绝保存）。两种策略：

- **fix（×0.5 等比映射）**→ 用于 452/453：坐标与 spread 同时折半（400×400 设计网格 → 200×200 实际地图），18+18=**36 点**映射后框内可行走格 1563~4411 全部 >0。
- **snap（坏框中心吸附最近可行走格，spread 不变）**→ 用于 202/237：贴近原设计分布，3+3=**6 点**吸附后框内格 1259~10710 全部 >0。

执行顺序：停服 → 手动备份 `C:\1.40\mir2-deploy\_backup-Server.MirDB-20261110-193519.bak`（917KB）→ fix 452 453 → snap 202 237 → SpawnProbe 复验四图 0 死框 → 重启。

### ② 诊断/修复工具入库

- `tools\SpawnProbe`：刷怪框死框探针（plan/复验两用）。
- `tools\RespawnFix`：刷怪点迁移修复工具（fix/snap 两策略，写库前双重安全门）。

## 验证证据

- SpawnProbe 复验：202/237/452/453 四图合计框内可行走格=0 的数量 **0**（修复前 452/453 各 18 + 202 三个 660 系 + 237 三组墙区点）。
- 服务端重启后：20:xx 时段 Spawn 失败日志 **0 条**；最后一条失败日志停在 19:41:25（修复前旧库），修复后运行 14+ 分钟零新增。
- 服务端状态：PID 3716，7000 LISTENING，空闲 CPU 11s/60s=0.18 核，Private=3354MB 稳定。
- 空闲分配速率复测：8.39 MB/s vs 修复前基线 7.8 MB/s（噪声内持平）→ 证伪"刷怪重试循环是空闲垃圾流来源"假设（垃圾来自主循环遍历的临时对象，与本案无关，如实记录）。
