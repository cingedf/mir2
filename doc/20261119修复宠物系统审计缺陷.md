# 20261119修复宠物系统审计缺陷

## 现象

宠物/坐骑/英雄维度深度审计回报 1 个 P0（灵宠无限刷宠，可刷装备珍珠 + 服务端 DoS）和 3 个 P2（遣散活宠孤儿、英雄行为枚举冻结、灵物配置 NRE）：

1. **P0 灵宠无限刷宠**：利用召唤/遣散竞态，每轮净增 1 只活宠，无上限→刷珍珠经济 + 上千宠 AI 拖垮主线程。
2. **P2 遣散活宠成孤儿**：遣散（ReleaseMe）正在召唤中的灵宠只删配置不 UnSummon，地图活宠继续拾取/产珍珠。
3. **P2 英雄永久冻结**：`SetHeroBehaviour` 接受客户端任意 byte，非法枚举值使英雄 Can* 全 false，无法移动/攻击/施法。
4. **P2 灵物/怪物蛋配置异常 NRE**：非法 Shape 配置致召唤时空引用（配置触发）。

## 排查过程

P0 利用链逐环节读现场核实（全部属实）：

1. `SummonIntelligentCreature`（PlayerObject.cs:12588-12634）：开头已有闸门 `if (CreatureSummoned || SummonedCreatureType != None) return;`——只要标志正确就不会重复召唤。
2. `UnSummonIntelligentCreature`（:12636-12657）：遍历 Pets 只杀第一个类型匹配项，`pet.Die()` 后**无条件**清 `CreatureSummoned=false; SummonedCreatureType=None`，未跳过已死亡/已 Despawn 的宠。
3. `IntelligentCreatureObject.Die()`（:830-842）：`base.Die()` 后直接 `CurrentMap.RemoveObject + Despawn`，**不从 Master.Pets 移除**。
4. `MonsterObject.Die()`（:1134）：`Master = null;`——base.Die 中已把 Master 清空。
5. `IntelligentCreatureObject.Process()`（:118-129）：`if (Master != null) Master.Pets.Remove(this)` 因 Master 早已在 base.Die 置 null 而成**死代码**；且 Die() 已 Despawn 使 Node=null 后不再 Process。

**结论**：死宠永久滞留 Master.Pets → UnSummon 循环命中死宠、`pet.Die()` 因 `if(Dead)return` 空转、但仍清标志 → Summon 闸门因标志被清失效 → 再 Add 新宠 → 每轮净增 1 活宠。多活宠各有独立 PearlTicker（1000 次拾取产 1 珍珠）→ 珍珠翻倍；上千宠每 tick 跑 AI → 主线程卡顿。Summon 闸门本身存在（子代理建议的幂等检查已被部分覆盖），核心是死宠滞留 + UnSummon 空转清标志。

## 修复内容

**Server\MirObjects\IntelligentCreatureObject.cs：**
1. **P0 Die()**（:830-842）：`if (Dead) return;` 后、`base.Die()` 前捕获 `var master = Master;`（因 base.Die 内 MonsterObject.Die 会置 Master=null，必须先存），base.Die() 后 `if (master != null) master.Pets.Remove(this);`——从源头移除死宠，根治滞留。

**Server\MirObjects\PlayerObject.cs：**
2. **P0 UnSummonIntelligentCreature**（:12644-12645）：`if (pet.PetType != pType) continue;` 后加 `if (pet.Dead || pet.Node == null) continue;`——跳过已死亡/已 Despawn 的宠，避免命中死宠空转仍清标志（双保险）。
3. **P2 ReleaseIntelligentCreature**（:12661 后）：开头加 `if (CreatureSummoned && SummonedCreatureType == pType) UnSummonIntelligentCreature(pType, false);`——遣散正在召唤中的宠时先 UnSummon，消除活宠孤儿。
4. **P2 SetHeroBehaviour**（:10168 后）：加 `if (!Enum.IsDefined(typeof(HeroBehaviour), behaviour)) return;`——拦截客户端传入的非法枚举值，防英雄永久冻结。

**不修（记录在案）：**
- **P2 灵物/怪物蛋配置异常 NRE**（PlayerObject.cs:6671-6688/6711-6737）：非法 Shape 配置触发，NRE 落在 WorkLoop 逐对象隔离 catch（Envir.cs:752-764），连续 5 次仅 Despawn 不致全服停机，属低优先配置容错；保持现状 + 依赖 GM 正确配置。
