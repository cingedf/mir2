# 20261116修复宠物捡物过滤取消污染与链路核查

## 现象

玩家反馈：宠物捡物过滤窗点「全部」后，宠物不捡任何物品（或行为与所选过滤不符）。

## 排查过程

对整条宠物捡物链路逐环取证：

1. **服务端 AI 正常**（IntelligentCreatureObject.cs）：`FindTarget :302-313` 只在 `AutoPickupEnabled && CurrentPickupMode==Automatic` 自动找物；`FindItemTarget :315-375` 按 `CheckItemAgainstFilter`（:636-663，`PetPickupAll` 直通 true）+ `PickupGrade` 门槛（:350，`item.Grade >= PickupGrade`）+ `CanGainItem` 过滤；`PickUpItem` 本身不过滤。饱食度 `Fullness < MinimalFullness` 时完全不找物（:306，设计行为）。
2. **模板规则正确**（IntelligentCreatureInfo.cs 静态 ctor）：19 种宠物硬编码规则，小猪/小猫仅半自动（range 3），其余有自动+半自动；`CreateClientIntelligentCreature :198-208` 把模板 Rules 完整下发给客户端。
3. **封包序列化对称**（Shared/Data/IntelligentCreatureData.cs）：`C.UpdateIntelligentCreature` 走 `ClientIntelligentCreature(reader)` 完整读回 Filter（9 bool 循环对称、PickupGrade 单独尾随）；`IntelligentCreatureItemFilter.Save/BinaryReader ctor` 逐 bool 对称，无错位。
4. **服务端更新与活体同步正常**（MirConnection.cs:3451-3504）：`UpdateIntelligentCreature` 按 PetType 匹配后整体替换 `Info.IntelligentCreatures[i].Filter/petMode`，且若该宠物正被召唤则 `UpdateSummonedCreature`（PlayerObject.cs:12552-12578）把 Filter/petMode 推给活体对象——改过滤即时生效，无需重召。
5. **品质窗无引用问题**（IntelligentCreatureOptionsGradeDialog）：`Show(grade)` 传值，`GradeType` 保存时才并入 Filter，无污染路径。
6. **真缺陷定位**（IntelligentCreatureDialogs.cs）：选项窗 `Show(filter) :1320-1326` 把 `User.IntelligentCreatures[i].Filter` 的**活引用**传入，`CheckBoxClick :1262-1271` 勾选直接改写活对象（`Filter.SetItemFilter(i)`）；点「保存」才发包同步服务端。**点「取消」:1252-1260 只把对话框本地引用换成 `new IntelligentCreatureItemFilter()`，活对象已被勾选污染**——客户端本地状态与服务端永久不一致，之后任意一次保存（改名字、切模式等触发的 needUpdate 或再开过滤窗点保存）都会把污染状态发给服务端。典型复现：打开过滤窗乱点几下→取消→此后宠物捡物行为与界面显示不符，看起来就像「点了全部也不捡」。

## 修复内容

1. `Shared\Data\IntelligentCreatureData.cs`：`IntelligentCreatureItemFilter` 新增 `Clone()` 方法（9 bool + PickupGrade 逐字段副本）。
2. `Client\MirScenes\Dialogs\IntelligentCreatureDialogs.cs`：选项窗 `Show(filter)` 改为 `Filter = filter.Clone()`——传入副本编辑，勾选不再直接改写 `User.IntelligentCreatures` 的活对象；「保存」路径不变（`SaveItemFilter(Filter)` 把副本整体写回并发包），「取消」路径天然恢复语义（丢弃副本，活对象保持与服务端一致）。

行为等价收敛：保存路径的最终状态与原实现完全一致；取消路径从「污染」收敛为「回滚」，属于缺陷修复而非行为变更。

## 验证证据

- 服务端 `dotnet build Server.MirForms\Server.csproj -c Release`：0 警告 0 错误。
- 客户端 `dotnet build Client.csproj -c Release`：0 错误（MSB3277 WindowsBase 版本冲突为工程既有警告，与本次改动无关）。
- 逻辑复核：Clone 后副本与活对象彻底解耦；保存路径 `SaveItemFilter` 写回的就是编辑后的副本，随后发包 `C.UpdateIntelligentCreature`；服务端整体替换 Filter 并同步活体——全链路闭环。
- 另注意（设计行为，非缺陷）：半自动模式下宠物不自动找物，需按手动捡物键（X / Ctrl+?+A）；饱食度低于门槛时宠物完全不捡。
