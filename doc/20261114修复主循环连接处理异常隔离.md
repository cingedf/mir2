# 20261114修复主循环连接处理异常隔离

> ⑤容错加固第二步第 5 段（段位隔离清单最后一个 WorkLoop 内联段）。延续 `aba3b12`（怪物线程恢复式容错）→ `36b1b84`（切片每对象）→ `e909487`（每地图）→ `d5e8bc5`（龙系统）→ `a24da0d`（全局系统）的统一隔离模式，本段覆盖 WorkLoop 每秒连接处理段。

## 现象

`Envir.WorkLoop` 每秒连接段（`Envir.cs` 615-635，`conTime != Time` 门控）对全部玩家连接与状态连接逐个 `Process()`，**无任何隔离**——任一连接在收包解析/状态机推进/玩家操作分发中抛出异常（竞态 NRE、数据边界、第三方插件脚本），异常冒泡至内层致命兜底 catch（705-721）→ **全服有序停机踢人**。单个坏连接的偶发异常 = 全服玩家掉线，与「一炸全停」致命面 (a) 同源。

## 排查过程

- 读现场确认结构：615-635 为 `conTime != Time` 门控内的两个 `lock` 块——`lock (Connections)` 倒序 `for` 逐连接 `Process()`、`lock (StatusConnections)` 倒序同构。
- **引用逻辑链核查（改动安全性依据）**：
  - 全仓 grep `Connections.Remove|Connections.RemoveAt|StatusConnections.Remove`，命中两处：`MirConnection.cs:1578` 与 `MirStatusConnection.cs:340`，均为 `lock (Envir.Connections/StatusConnections)` 内 `Remove(this)`——即连接在自身 Process 调用链内（SoftDisconnect→SoftClose）**自移除**。
  - **倒序迭代 + 自移除**：`Connections[i]` 先取引用再调 Process，Process 内 Remove(this) 使数组收缩，i 之后由 for 自然递减仍指向未处理元素——倒序迭代天然免疫，无跳过/越界。
  - **catch 不得再索引数组**：异常抛出时该连接可能已被自移除，`Connections[i]` 在 catch 中会错位——因此提前 `var conn = Connections[i];` 捕获引用，catch 内只引用局部变量。
  - MirConnection 无稳定公开 ID 字段（grep ObjectID/ConnectionID 无命中），日志 key 沿用既有 `WorkLoopMap:` + i 风格（`WorkLoopConnection:`/`WorkLoopStatus:` + i），key 仅用于 ErrorThrottle 节流（同 key 10 秒窗口一条），索引漂移不影响功能。
  - 单连接 catch 后留在列表，下周期由 `conTime` 门控（每秒）自然重试；防洪/状态机对坏连接自有处置（MaxReceiveQueue/MaxSendQueue 超限 → BeginDisconnect），无需额外重试节流。
- `AdjustLights()`（619，锁外）不属于本段范围，按「逐个逐个修复」纪律不扩 scope，其异常仍走内层致命兜底。

## 修复内容

**`Server\MirEnvir\Envir.cs`**（615-635 段，仅此一处）：

1. `lock (Connections)` 内：循环体改为 `var conn = Connections[i];` 提前捕获 → `try { conn.Process(); }` → `catch (Exception ex) { ErrorThrottle.Notify("WorkLoopConnection:" + i, () => MessageQueue.Enqueue($"主循环连接处理异常 [{i}] => {ex}")); }`——倒序与锁结构逐字保留，`Process()` 语义零改动。
2. `lock (StatusConnections)` 内：同构处理，key `WorkLoopStatus:` + i，局部变量名 `statusConn`（避免与外层 `conn` 混淆，虽不同作用域但命名自明）。
3. 两处 catch 均不吞循环推进（i 由 for 自然递减），与切片段「推进绝不能被 catch 吃掉」原则一致。

复用 `aba3b12` 落地的 `ErrorThrottle` 节流器，无新增字段/类。

## 验证证据

- 逻辑复核：倒序迭代 ×自移除窗口（1578/340 均在锁内、与主循环同锁互斥）× catch 引用局部变量三条引用路径均安全；Process 内部逻辑未动，行为等价收敛 + 防御增强。
