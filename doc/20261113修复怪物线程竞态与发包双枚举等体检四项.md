# 20261113修复怪物线程竞态与发包双枚举等体检四项

## 现象

深度性能体检（只读核查）发现四个遗留问题：

1. **ThreadLoop 怪物链表竞态（正确性 bug）**：`Settings.Multithreaded=true` 时怪物线程 `Envir.ThreadLoop` 对 `Info._current.Value` 直接解引用无 null 判；`MapObject.Despawn` 从 `MobThreads[SpawnThread].ObjectsList` 移除节点时不检查 `_current` 是否正指向该节点。节点被移除后 `_current.Value` 为 null → NullReferenceException → 被外层 catch 吞掉 → 该怪物线程整个退出、其上怪物停止 Process（只剩主线程 fallback），仅 MessageQueue 报一条错。
2. **发包热路径双枚举**：`Packet.GetPacketBytes()` 实际返回 `byte[]` 却声明为 `IEnumerable<byte>`，`MirConnection.TryBeginSend` 里 `packetBytes.Count()`（LINQ 枚举一遍，byte[] 走装箱枚举器）+ `data.AddRange(packetBytes)`（再枚举一遍）——每个发包字节被遍历两次。PlayerObject 555 处 Enqueue，全服最热路径之一。
3. **ReportCellIssue 异常构造开销**：`Cell.ReportCellIssue` 用 `throw new InvalidOperationException(message)` 再 catch 只为入队日志，每次构造 StackTrace。
4. **Visible Buffs LINQ 重复模式**：`Buffs.Where(d=>d.Info.Visible).Select(e=>e.Type).ToList()` 在 MonsterObject/HeroObject/PlayerObject/IntelligentCreatureObject/HornedMage 五处重复（GetInfo 序列化路径，广播热路径上有枚举器/委托/闭包分配）；SepHighArcher 另有 `Buffs.Where(...).ToList().Count() > 0` 反模式（先物化整表再数数）。

## 排查过程

- ThreadLoop（Envir.cs 750-780）与 MapObject.Spawned/Despawn（344-373）逐行对读，确认 `MobThreads[x].ObjectsList`（怪物线程链表）与 `Envir.Objects`（主链表）是两套独立链表、节点字段分别是 `NodeThreaded` 与 `Node`；竞态窗口在「怪物线程正停在节点 N 上 vs. 并发 Despawn 把 N 从链表移除」。`LinkedListNode.Value` 在节点被移除后返回 null（不是抛异常），随后 `.OperateTime` 解引用炸 NRE。
- `GetPacketBytes` 全仓仅两处调用：服务端 `MirConnection.cs:655`、客户端 `Network.cs:670`（`AddRange(byte[])` 天然兼容），返回类型改强类型无第三方影响。
- `MessageQueue` 已有 `Enqueue(string)` 重载（MessageLog+Logger.Info），ReportCellIssue 直接入队字符串不丢日志信息。
- `BuffType` 为全局枚举（Shared\Enums.cs:1542，无命名空间），基类 MapObject 加 protected 辅助方法即可被五个子类共用（不重复造车）。
- 体检同时确认三项 11-10 已修复项不复发：WorkLoop 空闲 Sleep(100)、Cell.Objects 共享空列表懒分配、Map.Process 空图门控。
- 附带发现：服务端编译冒出 CS0169 `MirConnection._receiveBytes` 从未使用（`_sendBytes` 有累加写入，`_receiveBytes` 纯声明）——按零弊端小瑕疵原则顺手删除。

## 修复内容

| 文件 | 改动 |
|---|---|
| `Shared\Packet.cs` | `GetPacketBytes()` 返回类型 `IEnumerable<byte>` → `byte[]` |
| `Server\MirNetwork\MirConnection.cs` | 局部变量改 `byte[]`，`packetBytes.Count()` → `packetBytes.Length`（去双枚举）；删除未使用字段 `_receiveBytes`（CS0169） |
| `Server\MirEnvir\Envir.cs` | ThreadLoop 循环内加防御：`Info._current.Value == null` 时回绕到 `ObjectsList.First` 并 continue，线程不再被并发移除炸死 |
| `Server\MirObjects\MapObject.cs` | ①`Spawned`：AddLast 后若该线程 `_current` 失效（null/Value==null）则指向新节点；②`Despawn`：移除节点前若 `mt._current == NodeThreaded` 则前移到 `NodeThreaded.Previous ?? ObjectsList.First`，移除后 `NodeThreaded = null`；③新增 `protected List<BuffType> GetVisibleBuffTypes()`（手写循环，无 LINQ 分配） |
| `Server\MirEnvir\Map.cs` | `ReportCellIssue` 改为直接 `MessageQueue.Instance.Enqueue(message)`，不再 throw-catch |
| `Server\MirObjects\MonsterObject.cs`、`HeroObject.cs`、`PlayerObject.cs`、`IntelligentCreatureObject.cs`、`Monsters\HornedMage.cs` | 五处 `Buffs.Where().Select().ToList()` → `GetVisibleBuffTypes()` |
| `Server\MirObjects\Monsters\SepHighArcher.cs` | `Buffs.Where(x=>x.Type==毒魔闪).ToList().Count()>0` → `Buffs.Exists(x=>x.Type==BuffType.毒魔闪)` |

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**（CS0169 消除，MSB3277 本就不在此项目）。
- `dotnet build Client\Client.csproj -c Release`：**0 错误**（改 Shared\Packet.cs 后客户端同步验证通过）。
- 三层防护闭环：Despawn 主动前移 `_current`（第一层）→ ThreadLoop 每轮 `Value==null` 回绕（第二层）→ Spawned 修复失效 `_current`（第三层），单层失效仍有兜底。
