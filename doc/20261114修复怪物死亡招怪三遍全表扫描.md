# 20261114 修复怪物死亡招怪三遍全表扫描

## 现象

`Server\MirObjects\Monsters\Jar1.cs` 的 `SpawnSlave()`（死亡后 1 秒由 `CompleteDeath` 触发招唤小怪）：

```csharp
var monsters = Envir.MonsterInfoList.Where(x => x.Level <= Level && x.Level >= (Level - 10));

if (monsters.Count() > 0)                       // 第 1 遍全表枚举
{
    var idx = Envir.Random.Next(monsters.Count());  // 第 2 遍全表枚举
    var monster = monsters.ElementAt(idx);         // 第 3 遍全表枚举
    ...
}
```

`Where` 返回的是**惰性** `IEnumerable`，本身不执行。但后续 `Count()`（LINQ 扩展，O(n)，不是 `List.Count` 属性）、再一次 `Count()`、`ElementAt(idx)`（对 IEnumerable 从头枚举到 idx）各自完整触发一次全表扫描。即：

- 同一个筛选条件**枚举 3 遍** `Envir.MonsterInfoList`（资料表几千条量级）；
- 额外分配 3 个迭代器 + 闭包捕获（`Level` 的委托）；
- 随机分布不变（`Next(Count)` 后 `ElementAt` 等价于收集后索引），纯属白干。

触发频率：Jar1 自身死亡一次 → 1 次（CompleteDeath）。属低频，但写法是明确的分配/扫描反模式，且修法零风险、行为等价。

## 排查过程

- 读 `Jar1.cs` 全文（73 行）：`Die()` 仅加入 1 秒后的 `DelayedType.Die` 动作并调用 `base.Die()`；`CompleteDeath` 只调 `SpawnSlave()`；无其他调用点持有该 LINQ 链。
- 确认 `Envir.MonsterInfoList` 为 `List<MonsterInfo>`（`Envir.cs` 声明），元素顺序稳定；收集后按下标取用与 `ElementAt` 语义一致。
- 核查原方法其余行（`ActionTime` / `AttackTime` 赋值、`GetMonster`、`Spawn`、`Target` 绑定、`ActionTime +2000`、`mob == null` 早退）——本次只替换筛选与取元素三段，其余逐字保留。
- 确认 `Jar1.cs` 已 `using Server.MirDatabase;`（MonsterInfo）与 `using Server.MirEnvir;`（Envir），`System.Collections.Generic` 由 ImplicitUsings 提供（同文件 `IList<object>` 已在用）。

## 修复内容

**`Server\MirObjects\Monsters\Jar1.cs`**（`SpawnSlave` 内筛选段）：

```csharp
// 体检遗留项：原 Where 惰性链在 Count()/Count()/ElementAt() 处各枚举全表一次（共 3 遍 + 迭代器/闭包分配）；
// 改为单遍 for 收集，仍逐条比较同一等级窗口，元素顺序与随机分布完全等价
var monsters = new List<MonsterInfo>();
var infoList = Envir.MonsterInfoList;
for (int i = 0; i < infoList.Count; i++)
{
    MonsterInfo info = infoList[i];
    if (info.Level <= Level && info.Level >= (Level - 10))
        monsters.Add(info);
}

if (monsters.Count > 0)
{
    var monster = monsters[Envir.Random.Next(monsters.Count)];

    var mob = GetMonster(monster);
    ...
}
```

- 筛选条件 `info.Level <= Level && info.Level >= (Level - 10)` 与 `Where` 逐字等价（同一 `Level` 属性、同一闭包捕获语义，现改为方法内直读）。
- 枚举顺序 = `MonsterInfoList` 下标顺序 = 原 `Where` 枚举顺序 ⇒ `Random.Next(Count)` 选中的元素与原实现完全一致。
- `Count()` 扩展方法 → `List.Count` 属性；`ElementAt(idx)` → 索引器：均 O(1)。
- 3 遍全表扫 + 3 个迭代器/闭包分配 ⇒ 1 遍 + 1 个 List。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**。
- 逻辑复核：`infoList` 为非 null 的 `List<MonsterInfo>`（Envir 构造/加载期初始化），for 边界安全；空结果走 `monsters.Count > 0` 假分支，与原 `Count() > 0` 一致；`GetMonster(monster)` 参数类型与原 `MonsterInfo` 相同，无重载歧义；`mob == null` 早退保留。
- 并发复核：`SpawnSlave` 在怪物自身线程执行，`MonsterInfoList` 仅在加载/编辑器路径增删（运行期不删普通怪资料），与既有其他怪物的直读模式一致，不新增并发面。
