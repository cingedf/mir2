# 20261116修复平衡设置英雄页网格列头不可见

## 现象

平衡设置（BalanceConfigForm）英雄页左侧表格没有列头行（类型/方案/基础/增益/增益率/最大 6 列名全部看不到）；对照职业页左侧表格既有列头又有顶部职业下拉框，观感不一致。

## 排查过程

1. 读 Designer 对比两页布局：职业页 `panel2`（Dock.Left 575×918）内 `classGridView` Location=(0,42)、Size 575×876，顶部留给 `ClassComboBox`（(4,4) 107×25），网格从 y=42 起，列头完整可见。
2. 英雄页 `panelHeroLeft`（同布局 575×918）内 `heroGridView` 却是 **Location=(0,-30)、Size 575×948**——网格顶被顶到 y=-30，列头（ColumnHeadersHeightSizeMode=AutoSize，约 20+px 高）整体越出 panelHeroLeft 可视区上沿被裁掉；网格底部 948 也超出面板 918。
3. 列头定义本身完好：6 列 HeaderText（类型/方案/基础/增益/增益率/最大）均在 Designer 定义，`ColumnHeadersVisible` 未被关闭（DataGridView 默认 true）——纯坐标问题，不是功能缺失。
4. 判断为设计器坐标残留（Dock.Bottom 模式下手工拖动导致的负 Location+膨胀 Size）。

## 修复内容

`Server.MirForms\BalanceConfigForm.Designer.cs`（heroGridView 段）：

- `heroGridView.Location`：`new Point(0, -30)` → `new Point(0, 42)`（对齐职业页 classGridView，给顶部 HeroClassComboBox 让位）；
- `heroGridView.Size`：575×948 → 575×876（918-42，与职业页一致）；
- 附 20261116 注释说明。

纯 Designer 坐标修改，无代码逻辑变更；HeroClassComboBox (4,4) 不动，与职业页布局完全对齐。

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：0 警告 0 错误。
- 布局复核：网格顶 y=42 ≥ 列头起点，列头落入可视区；底部 42+876=918=面板高，无溢出。
- 与职业页对照：两页网格坐标模式一致（y=42/高 876），观感统一。
