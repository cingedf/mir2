# 20261113修复主循环切片对象异常隔离

> ⑤容错加固第二步第一段（用户拍板「继续第二步，从切片每对象开始」后实施）。第一步（ThreadLoop 恢复式容错，commit aba3b12）已根除 mob 线程异常死亡致命面；本段隔离主循环 20ms 切片的逐对象异常。

## 现象

主循环 WorkLoop 的 20ms 切片段（Envir.cs，`while (!TheEnd && Stopwatch.ElapsedMilliseconds - Start < 20)`）对每个对象调用 `current.Value.Process()`——任何一个对象的 Process 抛异常（竞态 NRE/数据边界），直接冒泡到内层致命 catch → 全服踢人停机。一个毒对象即可把全服「一炸全停」。另原实现 `current.Value.SetOperateTime()` 在 Process 之后再次解引用 `current.Value`，与 Process 内可能发生的并发 Despawn 存在同窗口风险。

## 排查过程

- 承接第一步（aba3b12）：ThreadLoop 已恢复式容错（逐对象 try + 外层 catch 回绕复位），mob 线程不再死亡；主循环侧的致命面尚未隔离，本段为第二步段位隔离清单的第一段。
- 现场核查切片段结构：`var next = current.Next;` 先取游标推进目标（原作者设计已保证 Process 中节点被移除也能安全推进）→ 条件 `!Settings.Multithreaded || Race != Monster || Master != null` 判断是否主线程处理 → `Time > OperateTime` 时 Process()+SetOperateTime() → `processCount++` → `current = next;`。
- 确认推进链安全性：LinkedList 游标 + 先取 next 的模式，即使当前对象在 Process 中被 Despawn（节点移除），`current = next` 依然正确——隔离 catch 只要不吞掉推进语句，结构即无损。
- 复用第一步已落地的 `ErrorThrottle` 节流器（同 key 默认 10 秒窗口只输出一条日志），毒对象不会每 20ms 刷屏。

## 修复内容

**`Server\MirEnvir\Envir.cs`**（WorkLoop 切片段，单文件）：

1. `var next = current.Next;` 之后新增 `var sliceObj = current.Value;` ——**提前捕获对象引用**：catch 分支内不再二次解引用 `current.Value`（若 Process 中对象被并发 Despawn，`current` 已指向别处，二次解引用会拿错对象甚至 NRE）。条件判断与 Process/SetOperateTime 全部改用 `sliceObj`。
2. Process 与 SetOperateTime 包 try/catch：
   ```
   catch (Exception ex)
   {
       ErrorThrottle.Notify("WorkLoopSlice:" + sliceObj.ObjectID,
           () => MessageQueue.Enqueue($"主循环切片对象处理异常 [{sliceObj.ObjectID}] => {ex}"));
       sliceObj.OperateTime = Time + 5000;
   }
   ```
   ——异常对象 5 秒后重试（与 ThreadLoop 段同策略），日志节流防刷屏。
3. **`processCount++;` 与 `current = next;` 保持 try 之外**——游标推进绝不能被 catch 吃掉，否则同一节点死循环；计数语义不变。
4. 切片对象范围不变：非 Multithreaded 时含全部对象（含怪物/玩家）；Multithreaded 时主线程只处理非怪物或 Master!=null（宠物）。存档段（BeginSaveAccounts/SaveDB/SaveGuilds/SaveGoods/SaveConquests）不隔离，保持停机语义。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**。
- 逻辑复核：切片段唯一职责（按 OperateTime 处理对象 + 推进游标）保持原序——取 next → 捕获 sliceObj → 条件判断 → 处理（现带隔离）→ 计数 → 推进；异常只影响当前对象，处理流不断头。
