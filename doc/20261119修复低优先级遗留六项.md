# 20261119修复低优先级遗留六项

## 现象

四路子代理审计（bug/性能/内存/启动）共发现 46 项，前 25 项已分 5 批闭环，另有 17 项因"低优先级"暂缓。用户问「低优先级未动 17 项，是否要修？」——经拍板：其中 6 项成本极低（每帧分配/除零崩溃/无界增长），本次修复；1 项（LoadGameLibraries 并行 Initialize）需进一步评估共享状态；其余 10 项收益/风险不成比例，登记不修。

## 排查过程

逐项复核 6 项现场，确认真实影响与修法：

1. **合成除零**（NPCScript.cs:1415）：`goods.Info.StackSize / goods.Count`，`goods.Count` 来自配置/异常物品可为 0 → 除零异常中断整个合成处理。
2. **英雄 AI HasRangedSpell**（WizardHero.cs:203 / TaoistHero.cs:192 / ArcherHero.cs:17）：`Info.Magics.Select(x=>x.Spell).Intersect(Globals.RangedSpells).Any()`，每次访问属性都重建 LINQ 集合+枚举器+HashSet；该属性在 Process 每帧多分支读取（如 WizardHero.cs:14/47/187/199），每帧多次无谓分配。`Globals.RangedSpells` 实为 `Spell[]`（Shared\Globals.cs:54）。
3. **Pets.Count()**（HumanObject.cs:365）：`Pets` 本身是 `List<MonsterObject>`，`Count()` 走 LINQ 扩展多余，Process 每帧调用。
4. **用户名/排行榜缓存无上限**（GameScene.cs:10695 的 UserIdList.Add / :10719 的 RankingList.Add）：随游戏时长单调累积，长期运行内存持续膨胀。排行榜若在中途 foreach 内 Clear 会导致下方 `RankingList[id]` KeyNotFound（:10723），故必须放在收包起始整体清理。
5. **MLibrary 目录扫描两遍**（Client\MirGraphics\MLibrary.cs:216-218）：`OrderBy` 是延迟枚举，`allFiles.Count()` 与 `allFiles.Last()` 各触发一次完整枚举 = 两次目录扫描 + 两次正则数字排序。
6. **分辨率哈希查找**（Client\Resolution\DisplayResolutions.cs:19/30）：`Enum.GetNames` 返回 `string[]`，`supportedResolutions.Contains(...)` 在 EnumDisplaySettings 循环内逐模式线性扫。

## 修复内容

1. **NPCScript.cs:1415**：条件前置 `goods.Count == 0 ||`，除零时直接 `player.Enqueue(p); return;`（合成失败但服务不崩）。
2. **三个英雄 HasRangedSpell**：改为无分配 getter——`for (int i=0; i<Info.Magics.Count; i++) if (Array.IndexOf(Globals.RangedSpells, Info.Magics[i].Spell) >= 0) return true; return false;`（数组二分查找语义等价 Intersect，零 LINQ 分配）。
3. **HumanObject.cs:365**：`Pets.Count()` → `Pets.Count`。
4. **GameScene.cs**：`UserIdList.Add` 前 `if (UserIdList.Count >= 1024) UserIdList.RemoveAt(0);`（淘汰最旧，再次查询会重发请求无功能损失）；`Rankings()` 收包起始 `if (RankingList.Count > 2048) RankingList.Clear();`（避开 foreach 中途清空导致 KeyNotFound）。
5. **MLibrary.cs:216-218**：`OrderBy(...).ToArray()` 物化一次，`Count()/Last()` 改 `Length/[Length-1]`，目录扫描与正则排序只做一遍。
6. **DisplayResolutions.cs:19**：`new HashSet<string>(Enum.GetNames(...), StringComparer.Ordinal)` 替代 `string[]`，模式匹配从 O(n) 线性扫降为 O(1) 哈希查找，大小写语义（Ordinal）保持。

## 登记不修的 10 项（利弊）

- MapInfoList 只 Add：地图数固定，不会无限增长，加 Clear 反而可能误清。
- Envir.Timers 角色名键登出不主动清：最终自清，提前清需改生命周期。
- 聊天 Update 全量重建：FullHistory 已限 500，n 有界，改造收益低。
- GroupHealthPanel 每帧 O(成员×玩家)：队伍成员少且面板非每帧可见。
- LoadGuilds/Conquests/GTInfo 线性扫：改字典会改变"首匹配"语义，风险 > 收益。
- IniReader.FindValue 字典化：需同步维护 Write/FindIndex 语义，改动面大。
- MagicExists O(Magic²)：实测 <10ms。
- LoadVersion MD5：VersionPath 实为单 exe，并行无收益。
- CanStartEnvir：实测 <10ms。
- 可忽略项：无实际影响。
- **LoadGameLibraries 并行 Initialize（评估项）**：收益较大（客户端进场 0.5-3s）但需先核实各库 Initialize 是否访问共享静态状态，本批不动，留待专项评估。
