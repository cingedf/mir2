# 20261110修复商城货架加载回落物品表

## 现象

无头工具（tools/GameShopMigrate 等直接引用 Server.Library 的进程）读取 Server.MirDB 的 GameShopList（游戏商店货架）时，读盘逻辑会把货架条目**静默丢弃**：count 读对了，但逐条绑定失败，最终内存里 GameShopList 变成空表，一保存就把货架清掉。此前铺货验证时发现"seed 写入成功、export 读回 0 条"，即由此引起。

## 排查过程

1. 逐行审查 `Server/MirEnvir/Envir.cs`：
   - `LoadDB()` 在 LoadVersion ≥ 63 段读取 GameShopList（约 1438–1450 行），每条 `new GameShopItem(reader, …)` 后调用 `Main.BindGameShop(item)`，**绑定失败即不加入列表**（静默丢）。
   - `BindGameShop(GameShopItem item, bool editEnvir = true)`（约 3077 行）**形参 `editEnvir` 从未被使用**——函数体无条件遍历 `Envir.Edit.ItemInfoList`（编辑器数据槽）。这是重构半途的半成品。
2. 数据流向确认：`Edit.ItemInfoList` 只有在 Server.MirForms 的 SMain 里才会先被 `EditEnvir.LoadDB()` 填充（SMain.cs 约 415 行）。无头进程没人加载 Edit → `Edit.ItemInfoList` 恒为空 → 所有序号都绑定失败。
3. 游戏端不受此 bug 影响：SMain_Load 先加载 Edit 再 `Envir.Start()`，服务端逐包 `S.GameShopInfo` 下发（PlayerObject.GetGameShop），客户端 GameScene 只消费数据包。
4. 全库交叉检索确认货架**只有 DB 一个数据源**，不存在 txt 配置加载路径：
   - 代码侧：LoadDB 之外的 GameShopList/BindGameShop 引用仅 Shared 数据包定义、编辑器窗体、客户端展示层。
   - 资源包侧（Desktop\Mir2\20261001版）：无任何名称或内容含 GameShop 的配置文件；物品 CSV 描述与 NPC 脚本中出现的"商城"字样均为展示文案（如"商城物品"、"只在商城中出售"、NPC 脚本"可在游戏商城购买"），非加载逻辑。

## 修复内容

改动文件：`Server/MirEnvir/Envir.cs`（一处函数）；`tools/GameShopMigrate/Program.cs`（注释与函数体降级为单次加载，免改 5 处调用点）。

`Envir.cs` 的 `BindGameShop` 改为按形参数据意图绑定并在两张物品表之间回落（新增私有 `BindGameShopSource`）：

```csharp
public bool BindGameShop(GameShopItem item, bool editEnvir = true)
{
    // 先按调用方意图的物品表绑定；未命中则回落到另一张表。
    // 无头工具（Server.MirForms 未加载 Edit 数据）也能正确绑定货架。
    if (BindGameShopSource(item, editEnvir ? Edit.ItemInfoList : ItemInfoList)) return true;
    return BindGameShopSource(item, editEnvir ? ItemInfoList : Edit.ItemInfoList);
}

private bool BindGameShopSource(GameShopItem item, List<ItemInfo> source)
{
    for (var i = 0; i < source.Count; i++)
    {
        var info = source[i];
        if (info.Index != item.ItemIndex) continue;
        item.Info = info;
        return true;
    }
    return false;
}
```

编辑器原有行为完全不变（编辑器先填 Edit，primary 命中即返回）；无头进程 primary 为空表时回落到自身加载出的 `ItemInfoList` 命中。
