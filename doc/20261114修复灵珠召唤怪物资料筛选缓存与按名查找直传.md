# 20261114 修复灵珠召唤怪物资料筛选缓存与按名查找直传

## 现象

`Server\MirObjects\Monsters\PowerBead.cs:166-184` 的 `SpawnRandom`（灵珠系 Boss 技能随机召唤小怪）每次调用：

```csharp
var beads = Envir.MonsterInfoList.Where(x => x.AI == 375).ToList();   // ① 全表筛选 + 新 List
...
var mob = GetMonster(Envir.GetMonsterInfo(randomBead.Name));          // ② 按名全表线性扫
```

1. `AI == 375` 是**静态资料属性**（加载后不变），却每次调用都全表 `Where` + `ToList` 重新筛一遍；
2. 已持有 `randomBead`（`MonsterInfo` 实例），却又用其 `Name` 走 `GetMonsterInfo(string)` 按名全表线性扫（`Envir.cs:3412-3430`，大小写不敏感 + 去空格双比较）——白扫一遍大表。

热度：调用点 `DarkOmaKing.cs:65`（每次技能 count=2 × attempts 最多 4 ⇒ 最多 8 次）、`DarkCaptain.cs:81`（attempts 最多 4 次），失败重试、命中即 break。即**每次 Boss 放技能最多 8 轮全表 Where+ToList + 8 轮按名全表扫**，怪物资料表越大越贵。

## 排查过程

- 全仓 grep `MonsterInfoList` 的变更点（缓存失效必须全覆盖）：
  - `Envir.cs:1573` 资料重载：`MonsterInfoList.Clear()`（后接逐条 `new MonsterInfo(reader)` 重填）；
  - `Envir.cs:3019` `CreateMonsterInfo()`：运行期 `MonsterInfoList.Add(new MonsterInfo { Index = ++MonsterIndex })`（AI 默认值，不可能是 375，但列表长度变了仍须失效）；
  - `Envir.cs:3057` `Remove(MonsterInfo info)`：`MonsterInfoList.Remove(info)` + `_monsterInfoIndexCache.TryRemove`（体检第四轮钩子）；
  - `Server\MirDatabase\MonsterInfo.cs:281` 编辑器 `EditEnvir.MonsterInfoList.Add(info)`（低风险，编辑器路径）。
- 确认 `MonsterObject.GetMonster` 存在 `MonsterInfo` 重载（`Server\MirObjects\MonsterObject.cs:11`）⇒ `GetMonster(randomBead)` 直传可行，无需按名反查。
- 缓存生命周期设计：与体检第四轮五类资料索引同模式——惰性构建 + 明确的失效钩子；不用 `static` 字段（`MonsterInfoList` 会在重载时 Clear 重建，static 易持有旧实例）。
- 并发：`SpawnRandom` 可在怪物（mob）线程执行，读缓存需线程安全 ⇒ 沿用 `lock` 保护惰性构建；构建后返回的 List 只读使用（调用方仅 `Count` / 索引），不再改动。

## 修复内容

**`Server\MirEnvir\Envir.cs`**（紧随体检第四轮资料索引字段区，约 3336-3367 行）：

```csharp
// 体检遗留项：PowerBead 召唤目标（AI==375 灵珠系）列表惰性缓存——原每次 SpawnRandom 全表 Where+ToList。
// 失效点：资料重载 MonsterInfoList.Clear、运行期 Remove(MonsterInfo)、CreateMonsterInfo 新增。
private List<MonsterInfo> _powerBeadMonsterCache;
private readonly object _powerBeadMonsterCacheLock = new object();

/// <summary>体检遗留项：AI==375 怪物资料列表（PowerBead.SpawnRandom 专用）；首次构建后缓存，资料增删/重载时失效。</summary>
public List<MonsterInfo> GetPowerBeadMonsterInfos()
{
    lock (_powerBeadMonsterCacheLock)
    {
        if (_powerBeadMonsterCache != null) return _powerBeadMonsterCache;

        var list = new List<MonsterInfo>();
        for (int i = 0; i < MonsterInfoList.Count; i++)
        {
            MonsterInfo info = MonsterInfoList[i];
            if (info.AI == 375) list.Add(info);
        }

        _powerBeadMonsterCache = list;
        return list;
    }
}

private void InvalidatePowerBeadCache()
{
    lock (_powerBeadMonsterCacheLock) _powerBeadMonsterCache = null;
}
```

**失效钩子三处**（覆盖全部运行期变更路径）：
1. 资料重载 `MonsterInfoList.Clear()` 后：`InvalidatePowerBeadCache();`（重载时同步失效）；
2. `CreateMonsterInfo()` 内 `MonsterInfoList.Add(...)` 后：失效（新增资料同步）；
3. `Remove(MonsterInfo info)` 内 `MonsterInfoList.Remove(info)` 后：失效（移除资料同步）。

**`Server\MirObjects\Monsters\PowerBead.cs`**（`SpawnRandom`）：

```csharp
var beads = Envir.GetPowerBeadMonsterInfos(); // 惰性缓存，原每次全表 Where+ToList
...
var mob = GetMonster(randomBead); // 直接传 MonsterInfo 实例，省一次按名全表线性扫
```

- 筛选条件 `x.AI == 375` 逐字保留在构建函数内；元素顺序 = `MonsterInfoList` 顺序 ⇒ `Random.Next(Count)` 分布不变。
- `GetMonster(randomBead)` 与原 `GetMonster(Envir.GetMonsterInfo(randomBead.Name))` 等价：原按名查到的正是同一实例（缓存列表元素直接取自 `MonsterInfoList`）。
- 缓存返回同一 List 引用，调用方只读——无需每次拷贝。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**（20.53s）。
- 失效面复核：grep 全仓 `MonsterInfoList` 的 `Clear`/`Add`/`Remove` 共 4 处（含编辑器路径）——运行期 3 处全部挂钩子；编辑器路径不影响服务端进程内实例。
- 语义复核：缓存内容 = 原 `Where` 结果（顺序一致、同一批实例引用）；`beads.Count > 0` 分支、Spawn 失败返回 false 路径逐字保留。
- 线程复核：mob 线程并发调用 `GetPowerBeadMonsterInfos` 由 `lock` 串行；返回后只读，无写竞争。
