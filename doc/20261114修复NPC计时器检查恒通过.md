# 20261114修复NPC计时器检查恒通过

> 死接线审计（子代理 P2-1）产出：CHECKTIMER 脚本命令在计时器存在时跳过比较恒返回通过。用户拍板第一批修复。

## 现象

NPC 脚本 `CHECKTIMER 比较符 秒数`（NPCSegment.cs CheckTimer case）：当计时器**存在**时（global `_-名字` 或玩家个人计时器），代码算出剩余秒后直接 `break` 跳过其后的 `Compare` 比较——即只要计时器存在，无论剩余多少秒，检查恒通过。计时器不存在时（remainingTime=0）比较逻辑反而是正常的。比较符号 `<`/`>`/`<="/">="/"!=` 全部失效。

## 排查过程

- 现场（NPCSegment.cs:2910-2949）：`long.TryParse(param[1])` 失败→failed=true 正常；`if (timer != null) { remainingTime = (timer.RelativeTime - Envir.Time) / 1000; break; }`（原 2935-2939）→ `failed = !Compare(param[0], remainingTime, time);`（原 2941）在 if 之外，仅 timer==null 时可达。
- `Compare<T>`（5304-5316）：static 泛型比较器，支持六种操作符，default 分支抛 ArgumentException（由 case 内 catch 2943-2947 记日志）。param[0]=比较符，与部署区 `NPC命令说明.txt:80` 文档一致。
- 现网影响面：部署区 `Envir\NPCs` 递归 grep `CHECKTIMER` 仅命中命令说明文档一处——**无任何脚本在用**，修复无现网行为依赖（防带出新问题核查）。

## 修复内容

- `Server\MirObjects\NPC\NPCSegment.cs` CheckTimer case：把 `failed = !Compare(param[0], remainingTime, time);` 移入 `if (timer != null)` 块内、`break` 之前；块外的原比较语句保留（timer==null 时 remainingTime=0 的既有语义逐字不变）。实际效果：两条路径都执行比较，仅 `break` 提前退出分支。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**。
- 逻辑复核：timer!=null → 计算剩余秒 → 比较 → break（修复）；timer==null → remainingTime=0 → 比较（原语义不变）；比较符非法 → Compare 抛 ArgumentException → catch 记日志（不变）。
- 部署区零脚本使用，无现网行为变化风险；修复后脚本可用 `CHECKTIMER > 10` 正确表达「剩余秒数大于 10 才通过」。
