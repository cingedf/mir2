# 20261117修复客户端热键解析异常与连接弹窗跨线程

## 现象

第五轮深度审计（客户端非渲染路线）回报 2 项 P1 缺陷：

1. **TargetSpellLockOn 热键解析崩溃**（CMain.cs:153-160 / :214-221）：按键设置界面为「目标技能锁定」绑定带修饰键的组合键（如 Shift + F1）后，按下该键时按键处理中断，甚至进程异常退出。
2. **连接失败弹窗跨线程**（Network.cs:346-349）：客户端多次连接失败后，异步连接回调线程直接创建并显示 MirMessageBox，操作无锁的 MirControl 静态控件列表，存在线程安全风险。

## 排查过程

1. **P1-1**：`InputKeys.GetKey(KeybindOptions.TargetSpellLockOn)` 返回的是供 UI 显示的**拼装字符串**（KeyBindSettings.cs:386-413 拼成 "Shift + F1" 形式）。原代码直接 `Enum.Parse(typeof(Keys), 拼装串, true)`——`Keys` 枚举不含带 " + " 的合法成员，必抛 `ArgumentException`。更致命的是这段代码位于 `try`（KeyDown 的 :166、KeyUp 的 :243）**之前**，异常不被捕获，导致后续按键处理（含 Alt+Enter 全屏、场景 OnKeyDown/OnKeyUp）整段中断。
2. **P1-2**：`HandleConnectionAttemptsExceeded()` 由异步连接回调 `Connection()`/`HandleConnectFailure()` 调用，运行在线程池回调线程上。:346-349 直接 `new MirMessageBox(...)` + `errorBox.Show()`——MirControl 体系依赖静态控件列表（`DXManager.ControlList`）且无锁，UI 线程与回调线程并发操作可能破坏列表/引发渲染异常。对比同方法内 :338-341 的 `notifyLostConnection` 分支已经用了 `Interlocked.Exchange(ref _connectionLostNotification, 1)` 标志 + UI 线程 `Network.Process()`（:1104-1116）统一弹窗的正确模式，初次连接错误却走了直弹路径。

## 修复内容

**1. CMain.cs（两处，KeyDown/KeyUp 同款）**：
- 原 `Enum.Parse(拼装串)` 改为：取 `fullKey.Split('+')` 的最后一段主键（`Trim()` 后），用 `Enum.TryParse(..., true, out Keys lockKey)` 安全解析；解析成功且 `e.KeyCode == lockKey` 才置 `SpellTargetLock=true`，失败置 false。
- 整段包 `try/catch`，异常时 `SpellTargetLock=false`，保证任何按键解析异常都不再中断按键处理。
- 未用 LINQ（CMain.cs 无 using System.Linq），以数组取末元素实现。

**2. Network.cs（三处）**：
- 字段区新增 `private static int _initialConnectionErrorNotification;`。
- `HandleConnectionAttemptsExceeded()`：删去异步线程里的 `new MirMessageBox`/`Show()`，改为 `if (showInitialConnectionError) Interlocked.Exchange(ref _initialConnectionErrorNotification, 1);`。
- `Network.Process()`（UI 线程）:1116 后新增检查段：`if (Interlocked.Exchange(ref _initialConnectionErrorNotification, 0) != 0)` 时创建并显示原样的 ErrorConnectingToServer / MaximumConnectionAttemptsReached 消息框（含 `Program.Form.Close()` 回调），与既有 lost-connection 标志模式一致。

## 验证证据

- `dotnet build Client\Client.csproj -c Release`：**0 错误**（1 个存量 MSB3277 警告，与本次无关）；
- 行为复核：合法单键/组合键绑定的目标技能锁定逻辑等价（取主键 + 忽略修饰键状态，与修饰键由 e.Shift/e.Alt/e.Ctrl 单独维护的模型一致）；连接失败弹窗内容/回调不变，仅改由 UI 线程创建；
- 待实测：绑定 Shift+F1 后按该键不再崩溃；多次连接失败时弹窗正常显示且无跨线程异常。
