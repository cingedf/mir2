# 20261116Map编辑器五项汉化与显示修复

## 现象

用户实测汉化并部署后的地图编辑器（C:\1.40\mir2-deploy\Client\Map Editor.exe），报告 5 个问题：

1. 标签页 WemadeMir2 / ShandaMir2 / WemadeMir3 / ShandaMir3 仍是英文（此前汉化时按"版本专有名词保留"原则未译，用户明确要求汉化）。
2. "物件"标签页左右区全部空白，什么都不显示。
3. "图块"标签页下数字编号对应的图像全部空白。
4. 几个有左右分割的标签页（图库页等），右侧预览区被挤得快看不到了。
5. "帮助"标签页全是英文（背景大图上的操作说明）。

## 排查过程

### 问题① 标签页英文

- Main.Designer.cs 中 4 个 Tab 的 Text 为英文：tabWemadeMir2.Text="WemadeMir2"(L796)、tabShandaMir2.Text="ShandaMir2"(L908)、tabWemadeMir3.Text="WemadeMir3"(L1020)、tabShandaMir3.Text="ShandaMir3"(L1132)。
- 行为耦合检查：tabControl1_SelectedIndexChanged (Main.cs) 为空方法；Main.cs 全文无任何 SelectedTab.Text / TabPages 按文本比较（仅有 SelectedIndex 数字索引与字段引用比较，快捷键 L2790-2824 直接引用 tabHelp/tabObjects/tabTiles 字段）。改 Text 安全。

### 问题② 物件页空白

- 物件页数据链：ReadObjectsToListBox (Main.cs L2373-2386) 枚举 Libraries.ObjectsPath=@".\Data\Objects\" 下的 *.X 文件填充 ObjectslistBox。
- 实查 C:\1.40\mir2-deploy\Client\Data\Objects 目录存在但为空（count=0），全客户端无任何 .X 物件文件。
- 结论：**数据缺失，非程序 bug**。.X 是编辑器自定义格式（在地图上框选后"将选区另存为物件(.X)"生成，SaveObjectsFile Main.cs L2200），物件页展示的就是这些保存的物件组合。没有任何 .X 文件时列表自然为空。

### 问题③ 图块页空白

- 数据链：图库页选定 .lib → Xxx_SelectedIndexChanged 设 TileslistView.VirtualListSize=Images.Count/Mir2BigTileBlock → TileslistView_RetrieveVirtualItem (Main.cs L4459-4474) 取预览图。
- 探针工程验证（net8.0 控制台引用 Map Editor.dll + SlimDX.dll，反射调 internal DXManager.Create 建设备）：图库数据与预览生成本身完全正常——Tiles.Lib 加载 177,966 张；GetTilesPreview 复刻链路每组 drawn=9、非透明像素 55296；CheckImage(5) 后 Image=96x64、TextureValid=True；GetPreview(5) 64x64 有内容。**排除数据/解析问题，锁定显示层 bug。**
- 根因（上游 bug，5 处同源）：Main.cs L72 `private int drawY, drawX, libIndex, index;` 共享字段。每个 RetrieveVirtualItem 处理器中：缓存未命中时 `_xxxIndexList.Add(e.ItemIndex, XxxImageList.Images.Count)` 记录新图位置 → Add 预览图 → `e.Item = new ListViewItem { ImageIndex = index, ... }` 用的是 TryGetValue 的 out 参数 index——缓存未命中时恒为 0，而非刚记录的新索引。后果：第 1 项显示正确，第 2 项起全部显示第 1 张图/错位，视觉上即"全空/全错"。
- 5 处同源位置：ShandaMir2LiblistView_RetrieveVirtualItem (~L1583)、WemadeMir2LibListView_RetrieveVirtualItem (~L1600)、WemadeMir3LibListView_RetrieveVirtualItem (~L1627)、ShandaMir3LibListView_RetrieveVirtualItem (~L1671)、TileslistView_RetrieveVirtualItem (~L4472)。
- 记录不修（上游缺陷，不影响本次问题）：GetTilesPreview L4315/4349/4388/4449 用共享字段 libIndex/index（而非 selectListItem.Value）将 `Libraries.MapLibs[libIndex].Images[index] = null`，会清错库的图；TileslistView_RetrieveVirtualItem L4473 `Images[e.ItemIndex]=null` 保留原逻辑。

### 问题④ 右侧预览区被挤没

- Main.Designer.cs L1761-1763：AutoScaleDimensions=(8F,19F)（按原英文字体 9pt 度量基准）+ AutoScaleMode=Font + Font=Microsoft YaHei 10.5F（汉化时为显示中文而换）。
- Font 模式自动缩放以"当前字体实际度量 / AutoScaleDimensions 基准"计算缩放因子（YaHei 10.5 ≈1.15 倍），把全部子控件坐标等比放大。主窗体 tabControl1(Dock=Left, 设计宽 1729) + TreeViewBox(绝对定位 x=1729, 宽 253) 原设计在 1982 宽客户区刚好并排；缩放后 tabControl1 宽 ≈1988 超过实际屏幕客户区（1920 等），右侧 TreeViewBox（含路径框+加载按钮+地图树）及各图库页右侧预览图被推出屏幕外/裁剪。
- 修复：AutoScaleMode = Font → None（L1762），控件坐标全部按设计值原样呈现，Dock/Anchor 自适应窗口，消除字体度量缩放。AutoScaleDimensions 保留不动。副作用仅是高 DPI 屏上 UI 偏小，本机无碍。

### 问题⑤ 帮助页全英文

- tabHelp 无子控件，帮助内容是 Main.resx 嵌入的背景大图 tabHelp.BackgroundImage（2501x1380，英文标注的操作说明图，OCR 已确认全部内容：显示开关、编辑层下拉、快捷键、缩放/撤销/小地图、TileCutter、Object.X、Mir3 反转层等）。
- AI 直接重绘含大量文字的整图不可行（生成图文字会乱），拍板改为**代码方案**：去掉背景图，用中文 RichTextBox 重写帮助内容。
