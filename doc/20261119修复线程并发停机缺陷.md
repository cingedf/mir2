# 20261119修复线程并发停机缺陷

## 现象

新一轮「线程并发与定时器」维度审计 + 地图 AI 路交叉，回报多项跨线程/停机相关缺陷，其中 4 项 P1（服务假死、存盘并发修改、Reboot 线程重叠、配置越界崩服）已修复，其余为改动面过大或设计层，登记不修：

1. **P1 WorkLoop 致命路径无 Running=false**：主循环致命异常后服务假死显示"运行中"，`Start()` 被永久拦截，只能重启进程。
2. **P1 AccountLock/LoadLock 不统一**：HTTP 线程建账号与存盘枚举并发修改 `AccountList` → 存盘失败。
3. **P1 Reboot 新旧 mob 线程重叠**：Stop 只 Interrupt 不 Join，Reboot 立即 Start → 新旧线程重叠重复刷怪/掉落。
4. **P1/P2 Spawned 越界**：`ThreadLimit=0` 时 `MobThreads` 空数组，`MapObject.Spawned` 访问越界崩服。
5. **P2 Saving 非 volatile**：跨线程读写无可见性保证。

## 排查过程

- **致命路径假死**：WorkLoop（:593）内层 try/catch 捕获致命异常后，:886-890 执行 StopNetwork/StopEnvir/SaveAccounts 等有序收尾，:904 `_thread=null`；但全程无 `Running=false`、无 `http.Stop()`、无 mob 线程中断。`Start()`（:2134）`if (Running || _thread != null) return` 因 Running 仍为 true 永久拦截，服务无法自恢复。
  - **关键陷阱**：不能在致命路径直接调 `Stop()`——`Stop()` 末尾 `while (_thread != null) Thread.Sleep(1)`（:2168）等待的正是当前 WorkLoop 线程自身，子线程调它会死锁。故须内联 Stop() 前半段（Running=false + PulseAll + mob Interrupt + http.Stop），保留 :886 起收尾。ThreadLoop 的 catch（:995）已对 `ThreadInterruptedException` 直接 return，Interrupt 安全。
- **AccountList 并发**：写端 HTTPNewAccount（:2674 `lock(AccountLock)` 内 Add）和正常 NewAccount（:2622 同锁 Add）在锁内；读端 SaveAccounts(Stream)（:1367-1369 枚举 AccountList）只持 LoadLock 不持 AccountLock → List 并发修改异常。调用链：SaveAccounts()→lock(LoadLock)→SaveAccounts(stream)，写端只持 AccountLock 不取 LoadLock，无反向锁序。
- **Reboot 重叠**：Stop()（:2142）对 mob 线程只 Interrupt（:2162）不 Join，Reboot（:2178）Stop 后立即 Start → 旧线程尚未退出即建新线程。
- **Spawned 越界**：MapObject.Spawned（:378）无条件 `Envir.MobThreads[SpawnThread]`；MobThreads 数组大小 = Settings.ThreadLimit（Envir.cs:229），ThreadLimit 从 ini 读入（Settings.cs:393）无下限钳制，配 0 → 空数组越界。
- **Saving 可见性**：Envir.cs:209 `public bool Saving`，HTTP 线程/UI 写、SaveAccounts `while(Saving)` 读，无 volatile。

## 修复内容

1. **致命路径停机**（Envir.cs WorkLoop 内层 catch 末尾）：在 :883 日志之后、:886 StopNetwork 之前内联 `Running = false; lock(_locker){Monitor.PulseAll(_locker);}` + mob 线程 Interrupt（照搬 Stop() 前半段）+ `try { http?.Stop(); } catch {}`。不调 Stop() 避免自等待死锁。
2. **AccountList 加锁**（Envir.cs SaveAccounts(Stream) :1367）：枚举处包 `lock (AccountLock)`，与写端同锁；锁序 LoadLock→AccountLock 无反向不死锁。
3. **Reboot 线程 Join**（Envir.cs Stop() :2164 后）：Interrupt 循环后补 mob 线程 `Join(2000)`（带超时防 UI 卡死，排除当前线程），确保旧线程退出后 Reboot 才 Start。
4. **ThreadLimit 钳制**（Settings.cs:393）：`ThreadLimit = Math.Max(1, Reader.ReadInt32(...))`，默认 2 不变，行为等价。
5. **Saving volatile**（Envir.cs:209）：`public volatile bool Saving`。

**不修（登记利弊）：**
- **Cell.Objects / Map.ActionList 跨线程无锁**（地图 AI 路 P1）：Cell.Objects 遍历点几十处、ActionList.Add 全仓 40+ 处（多为玩家技能，真正跨线程仅 MonsterObject 2 处），全面加锁改动面过大、行为等价风险高；已有 ErrorCircuitBreaker 熔断 + 逐对象异常隔离兜底（不会全服崩，仅 mob 线程异常被隔离重试）。收益不抵风险，保持现状。
- **Broadcast 无锁遍历 Players**（P2-7）：`Envir.Broadcast` 遍历主线程增删的 Players，彻底修复需同步所有 Add/Remove 站点用同锁，改动面大；HTTP 服务默认关闭（仅回环），暴露面极低。
- **关服三异步存盘 fire-and-forget**（P2-5）、**异步失败复位回调跨线程访问**（P2-8）：改动大/只读异常路径，收益有限。
- **CMain_Deactivate 未重置 CanRun/Moving**（客户端路提示项）：属输入状态机维度，非本批。

## 验证证据
