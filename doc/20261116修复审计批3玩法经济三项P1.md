# 20261116修复审计批3玩法经济三项P1

## 现象

四路深度审计（玩法系统路线）回报 3 项 P1 经济类缺陷，均可被伪造协议包触发玩家资产损失：

1. **SendMail 附件+邮票双蒸发**（PlayerObject.cs:12221-12263 原版）：邮件处理流程「先扣邮票→逐项验附件（边验边删）」，伪造 items[0]=合法物品、items[1]=绑定物品（DontTrade）→ 第 0 项附件已被删除、第 1 项校验失败 return → 邮件不发出，**已删附件 + 已扣邮票全部蒸发**（金币在循环后未扣，金币不丢）。
2. **觉醒金币+材料双蒸发**（PlayerObject.cs:9292-9300 原版）：入口预检未覆盖 CheckAwakening 的类型合法性校验（DontUpgrade 物品配非法 type 组合）；流程=先扣金币→HasAwakeningNeedMaterials 删材料→UpgradeAwake 内 CheckAwakening 失败返 -1→case -1 无退还 → **金币+材料双蒸发**。
3. **技能书无已学查重**（PlayerObject.cs:6487-6499 原版）：`Info.Magics.Add(magic)` 前无查重（对照 HumanObject.cs:1302 有先例）→ 重复吞书堆叠条目/存档污染。

## 排查过程

- SendMail 全流程逐行读（:12178 预检限频/收件人/金币 → :12219 邮票 → :12239 附件循环 → :12275 金币），确认「边验边删+中途 return」无回滚路径；
- 觉醒链路读全：HasAwakeningNeedMaterials（:9553-9658）实为「校验+扣材料」一体；UpgradeAwake（ItemData.cs:1018）入口 :1022 调 CheckAwakening（:958 纯校验无副作用）返 -1；两处 CheckAwakening 调用结果必然一致（无状态依赖）；
- 技能书：比对 HumanObject.cs:1302 已学查重先例，确认 Spell 以 item.Info.Shape 承载。

## 修复内容（PlayerObject.cs）

1. **SendMail 两阶段改造**（:12218 起）：
   - 校验阶段：hasStamp 仅做存在性检查不扣；usedItems（HashSet）防 items 重复引用同一背包物品；**全部** items 先通过 DontTrade/NoMail/RentalInformation-DontTrade 校验并收集 giftItems；任一失败 ReceiveChat+return，不动任何玩家数据；
   - 扣删阶段：邮票（存在才扣）/附件（Inventory ICollection+IndexOf 定位删除）/金币统一执行。
2. **觉醒预检前置**（:9296 后插入）：金币检查后、扣费前先调 `item.Info.CheckAwakening(item, type)`，失败 Enqueue result=-1 直接 return（不扣金币不删材料）；后续 HasAwakeningNeedMaterials/UpgradeAwake 内二次调用行为等价。
3. **技能书查重**（:6503 前插入）：`Info.Magics.Any(t => t.Spell == (Spell)item.Info.Shape)` 已学则提示「已学会该技能，无法重复学习」并 return（物品保留）。
