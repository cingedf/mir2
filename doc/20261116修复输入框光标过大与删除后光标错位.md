# 20261116 修复输入框光标过大与删除后光标错位

## 现象

用户反馈：登录页输入用户名时，鼠标在输入框上变成**长竖条**，比 20px 高的输入框大很多、比例失调；输错删除字符时光标移动等操作**不自然**；进游戏后的输入框也类似。

## 排查过程

1. **光标素材实解**：`Cursor_TextPrompt.CUR`（deploy\Client\Data\Cursors\，4286B）文件头实解析=单图 **32×32** 的 I 形文本光标。加载点 `CMain.cs:790`（LoadMouseCursors 八个 .CUR 之一），挂接点**全仓唯一**=`MirTextBox.cs:262` ctor `TextBox.Cursor = CMain.Cursors[(byte)MouseCursor.TextPrompt]`。32px 光标在 20px 高输入框上显大，**叠加全屏 D3D 拉伸后更显巨大**（与用户在拉伸全屏下测试吻合）。
2. **编辑手感链**（MirTextBox.cs 240-411 全读）：MirControl 包装原生 WinForms TextBox（BorderStyle=None）；全屏才自绘 CreateTexture（DrawToBitmap 抓控件位图+GetCaretPosition 画光标竖线）；纹理重建挂在 NeedRedraw（KeyPress/KeyUp/MouseDown/MouseUp/LostFocus/GotFocus/MouseWheel 七事件）。
3. **删除盲区实锤**：Back/Delete 是控制键**不触发 KeyPress**；KeyUp 触发时 TextBox 内部布局可能尚未同步，`GetPositionFromCharIndex` 返回旧位置 → 删字后自绘光标错位。
4. **引用面核查**：`MouseCursor.TextPrompt` 其他引用仅 CMain.cs:790 加载点（保留，别处光标还用）；`Redraw()` 是 MirControl 虚方法仅冒泡，无副作用。

## 修复内容

`Client\MirControls\MirTextBox.cs` 两处：

1. **ctor :262**：`Cursor` 从自定义 32×32 光标改为系统标准 `System.Windows.Forms.Cursors.IBeam`（尺寸与输入框协调，DPI 自适应；不动 Settings/CMain/光标素材，影响面最小）。
2. **ctor :272-278 事件区**：NeedRedraw 补挂 `TextBox.TextChanged`——文本实际变化后触发，覆盖 Back/Delete/粘贴/IME 提交全部盲区，删字后自绘光标立即重画在正确位置。

GetCaretPosition 的平均字宽猜测逻辑保留（TextChanged 修复后其触发时机已正确，影响面小，不动核心逻辑防带新问题）。

窗口模式不受影响（自绘关闭，原生 caret 本就正常）。
