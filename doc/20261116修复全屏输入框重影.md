# 20261116修复全屏输入框重影

## 现象

用户反馈：全屏画面下，登录框/输入框输入账号密码时出现**重影**——Win 自带控件和游戏画面里的输入框没重合在一起，看起来有两层。

## 排查过程

1. **双绘制机制确认**：MirTextBox 有两套显示路径——
   - 原生 WinForms TextBox（`MirTextBox_Shown` 挂 `Program.Form`，已由上轮 `UpdateNativeBounds()` 按拉伸比例换算到正确物理位置）；
   - **D3D 自绘纹理**：ctor `DrawControlTexture = true` → `CreateTexture()`（:331，仅全屏触发）用 `DrawToBitmap` 抓控件位图写入 D3D 纹理 → `MirControl.DrawControl`（:716-730）把纹理画进游戏画面。
2. **自绘的历史背景**：这套自绘是**旧版 D3D9 独占全屏**的补救——独占模式下原生子控件被 D3D 表面完全盖住看不见，只能把控件内容抓下来画进游戏画面。
3. **重影根因**：全屏改造（2ee1320）后全屏=无边框窗口模式，原生 TextBox 直接合成显示在 D3D 画面之上；自绘纹理仍按逻辑坐标（DisplayLocation）画进游戏画面——**同一输入框内容显示两遍且位置一新一旧** = 重影。
4. 修复方向：关掉自绘，让原生控件独占显示（窗口模式本就如此，全屏对齐窗口行为）。

## 修复内容

`Client\MirControls\MirTextBox.cs` 两处：

1. **ctor :285**：`DrawControlTexture = true` → `false`（附 20261116 注释）——不再把输入框内容画进 D3D 画面，原生 TextBox 独占显示。
2. **CreateTexture :333**：入口加 `if (!DrawControlTexture) return;` 双保险（即使未来别处误开标志也不生成纹理）。

其他机制未动：SetFocus/DialogChanged/NeedRedraw 事件链保留（NeedRedraw 现在只置 TextureValid=false + Redraw 冒泡，无自绘开销）；窗口模式行为不变（原本 `if (!Settings.FullScreen) return` 就不画）。

## 验证证据

- `dotnet build Client\Client.csproj -c Release`：0 错误（1 存量 MSB3277 警告）；
- 逻辑复核：DrawControlTexture=false 时 DrawControl 直接 return，游戏画面不再画输入框内容；原生控件位置已由 UpdateNativeBounds 换算准确；
- 待用户实测：全屏登录框/输入框无双层重影、输入内容正常显示、焦点/光标正常。
