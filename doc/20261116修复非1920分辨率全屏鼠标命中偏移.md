# 20261116修复非1920分辨率全屏鼠标命中偏移

## 现象

用户反馈：设置全屏进入游戏后，**只有 1920×1080 分辨率鼠标点击位置正确**；1024/1280/1366 分辨率下鼠标放在 NPC 上没反应（实际命中点不在 NPC 上），点击走路等也偏。

## 排查过程

1. **鼠标双数据源**：UI 命中走 `CMain.MPoint`（CMain_MouseMove 已按拉伸比例换算，正确）；但 **NPC/怪物命中与绘制走 `MapControl.MouseLocation`**（GameScene.cs :11299/:11313/:11320/:11327 `MouseOver(MouseLocation)` 等）。
2. **独立数据源未换算（根因）**：MapControl ctor :11108 `MouseMove += (o, e) => MouseLocation = e.Location;` 直接吃 WinForms 原生**物理坐标**；而 `MapLocation`（:11022）用 `MouseLocation / CellWidth` 算地图格、`OffSetX`（:11097）= `ScreenWidth/2/CellWidth` 是**逻辑值**——比例≠1 时（1024/1280/1366 全屏）地图格系统性算偏。
3. **为何 1920 恰好正确**：1920 分辨率全屏时 ClientSize=Native=物理屏，拉伸比例=1，物理坐标=逻辑坐标——与用户描述逐字吻合。
4. 下游影响：:12151 `MouseLocation.Subtract(...)`、:12868 等全部依赖同一数据源。

## 修复内容

`Client\MirScenes\GameScene.cs` 一处：

- :11108 `MouseLocation = e.Location` → **`MouseLocation = CMain.MPoint`**（附 20261116 注释）。CMain_MouseMove 在窗体层先触发并更新 MPoint（已按比例换算成逻辑坐标），MapControl.MouseMove 后触发时 MPoint 即最新逻辑坐标；:13114 `MouseLocation = Point.Empty`（ResetMap 清零）保持不变。

其余 `e.Location` 直用点（BigMapDialog:606-616、MainDialogs SoundBar/MusicSoundBar:3076/3140）本轮未动——用户未报相关问题，避免扩大影响面；如后续反馈再按同法修。

## 验证证据

- `dotnet build Client\Client.csproj -c Release`：0 错误；
- 逻辑复核：MPoint 换算公式与 D3D 拉伸比例一致（clientX × ScreenWidth / ClientSize.Width），MapLocation 计算恢复逻辑坐标口径；
- 待用户实测：1024/1280/1366 任一分辨率全屏进游戏，鼠标悬停 NPC 显示名字、点击 NPC 弹对话、点击地面走路落点正确；1920 与窗口模式如旧。
