# 20261115汉化尊者封印buff悬浮显示

> 用户实测反馈：尊者之魂攻击触发的 Mon564NSealing buff 在游戏中悬浮显示为英文枚举名，未汉化。同时用户追加硬性规则：碰到任何游戏内未汉化文案必须顺手汉化（已写入 C:\1.40\mir2\AGENTS.md「协作决策规范」）。

## 现象

- 玩家被尊者之魂（f516e7f 接线的封印技能）命中后，客户端 buff 栏悬浮提示首行显示 `Mon 564 NSealing`（英文枚举名驼峰拆分），无中文 buff 名与效果描述。

## 排查过程

- 显示链：`Client\MirScenes\Dialogs\BuffDialog.cs` `BuffString(ClientBuff)`（286 行起）首行 = `RegexFunctions.SeperateCamelCase(buff.Type.ToString())`——中文枚举名拆分后即中文名，**英文枚举名（Mon564NSealing）原样显示英文**；后续 tooltip 文案靠 switch case 逐个补写。
- 同族参照：`绝对封锁`（407-410 行）有 case：`overridestats = true` + 固定描述「封锁期间禁用药水\n生命值降低 25%\n法力值降低 25%\n」——Mon564NSealing 效果与绝对封锁同族（f516e7f 接线时即复刻其 -25% 生命/法力 stats），图标也复用 61（BuffDialog.cs 629-630）。
- 该 buff 无 tooltip case ⇒ 首行英文 + 无描述双缺失。

## 修复内容（`Client\MirScenes\Dialogs\BuffDialog.cs`，紧跟绝对封锁 case 后新增）

```csharp
case BuffType.Mon564NSealing:
    // 20261115 顺手汉化：英文枚举名会原样显示为 "Mon 564 NSealing"，改为中文名+描述（同绝对封锁家族，效果=生命/法力 -25%）
    text = "尊者封印\n生命值降低 25%\n法力值降低 25%\n";
    overridestats = true;
    break;
```

- `text =`（赋值而非追加）覆盖首行英文枚举名；`overridestats = true` 与绝对封锁一致——stats 描述改由固定文案呈现（-25% 已写入文案，不重复列出）。
- 仅客户端一处改动，无服务端联动（buff 名不落盘、不参与协议字段，悬浮文案纯客户端渲染）。
