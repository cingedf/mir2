# 20261116 修复上线28秒连接超时下线

## 现象

玩家反馈：登录后进图，约 28 秒（甚至更短）即被服务器踢下线，客户端提示「连接超时」。服务器日志显示同一时刻该连接以「连接超时」原因断开。重试多次必现，进图加载稍慢时 100% 触发。

## 排查过程

1. 全仓 grep「连接超时」唯一命中 `MirConnection` 的连接超时踢出逻辑，确认是服务端主动断开而非客户端崩溃。
2. `MirConnection.cs:190-192`：连接超时字段为 `static readonly ConnectionTimeout = Settings.TimeOut`（此前某次「审计接线」把历史硬编码 60000ms 改为读配置）。
3. `Settings.cs:68`：代码内默认值 `TimeOut = 60000`，看似没问题。
4. **实机检查部署区 `Configs\Setup.ini`：`TimeOut=10000`** —— 这是旧默认值时期写盘的陈旧配置。静态字段在类加载时一次性读入，锁死 10 秒。
5. 心跳时序核对：客户端 KeepAlive 每 60 秒一发（`GameScene.cs` NextPing+60000）；服务端主动 S.KeepAlive 间隔 10 秒。进图加载（大地图/大量对象）一旦超过 10 秒没有上行包，服务端即判定超时踢线——与「进图慢就掉」完全吻合。
6. 交叉排除：`IPBlockSeconds=5` 只影响封 IP 时长，与掉线无关；网络层连通正常（玩家能登录能进图）。

## 修复内容

1. `Server\Settings.cs`（Load 段）：读取 `TimeOut` 后钳制下限 60000：
   ```csharp
   TimeOut = Reader.ReadUInt16("Network", "TimeOut", TimeOut);
   // 20261116 连接超时下限钳制：历史上 MirConnection 硬编码 60000ms；审计接线后 ini 存量陈旧值（如 10000）
   // 会让静态 ConnectionTimeout 锁死 10 秒，客户端 60 秒心跳间隔下进图稍慢即被踢「连接超时」。钳制下限 60000。
   if (TimeOut < 60000) TimeOut = 60000;
   ```
   行为等价收敛：硬编码时代恒为 60000；即使 ini 再出现陈旧小值也不会复现。防御性增强：真想调更严格超时（>60000）仍可在 ini 自定义。
2. 部署区 `C:\1.40\mir2-deploy\Server\Configs\Setup.ini`：`TimeOut=10000` → `TimeOut=60000`，立即纠偏（不依赖下次写盘）。

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：0 警告 0 错误。
- 逻辑复核：`ConnectionTimeout` 为 `static readonly`，类加载时赋值一次；钳制发生在 `Settings.Load()` 读取 ini 之后、任何连接建立之前，时序安全。
- 部署区 ini 已确认改为 60000；新 Server.dll 部署后重启即生效。
