# 20261115 修复：地图编辑器打开 mir2-deploy 地图不显示

## 现象

用户在地图编辑器（tools\MapEditor，Crystal.MapEditor 汉化版）中打开 `C:\1.40\mir2-deploy\Client\Map` 下的 .map 文件（如 0.map），界面不显示任何地图内容（黑屏/空白），无报错弹窗。

## 排查过程

1. **地图格式识别**：抽查 0.map、0100.map、0122_Rebuild.map、D2077.map、01132.map 文件头，全部为 `Map 2010 Ver 1.0`（Wemade 2010 格式）。MapCode.cs `MapReader.initiate()` 的判断条件 `(Bytes[0]==0x10) && (Bytes[2]==0x61) && (Bytes[7]==0x31) && (Bytes[14]==0x31)` 均命中 → 走 `LoadMapType1()`（15 字节/格）。以 0.map 验证：offset 21 处 w=0xA884、xor=0xAA38、h=0xA884 → 宽=高=0xA884^0xAA38=700；700×700×15+54=7,350,054 字节，与文件大小**精确吻合** → 地图解析本身无问题。
2. **渲染依赖链**：Main.cs 打开地图后绘制时按 `Libraries.MapLibs[BackIndex/MiddleIndex/FrontIndex]` 取图（BackIndex=0→Tiles、MiddleIndex=1→Smtiles、FrontIndex=byte+2→Objects 系）。图库在 `MLibrary.cs` 的 `Libraries` 静态构造函数中从**写死的相对路径** `.\Data\Map\WemadeMir2\Tiles.lib` 等加载——相对**编辑器 exe 运行目录**。
3. **定位根因**：全盘搜索确认 `Map Editor.exe` 仅存在于 `tools\MapEditor\Map Editor\bin\x64\Release\net8.0-windows\`，该目录下 Data 文件夹只有一个空的 `Objects`，**没有任何 Map 图库**。`MLibrary.Initialize()` 对文件缺失静默返回（不报错）→ 全部 MapLibs 为空库 → 单元格取图全部落空 → 什么都不画。这就是"打开不显示"的根因。
4. **部署区资源核实**：`C:\1.40\mir2-deploy\Client\Data\Map\` 下有完整的 `WemadeMir2`（Tiles.Lib 617MB/SmTiles/Objects2~28/Objects_32bit 共 31 个文件）与 `ShandaMir2` 目录，与编辑器期望布局一致；文件头版本 int32=3 ≥ 编辑器要求的 2，格式兼容。
5. **发现次要缺口**：对比部署客户端的图库加载器 `Client\MirGraphics\MLibrary.cs`（L140：`for (int i = 2; i < 29; i++)` 加载 Objects2~Objects28 → MapLibs[3..29]），编辑器原版循环为 `i < 28` 只加载到 Objects27（MapLibs[28]）。部署区存在 `Objects28.Lib`（2026-06-27 新增，9,339 图），引用它的地图在编辑器里会缺前景物件。

## 修复内容

### 修复点 1：源码——图库循环边界与客户端对齐（1 行）

- 文件：`tools/MapEditor/Map Editor/MLibrary.cs`（L41）
- `for (int i = 2; i < 28; i++)` → `for (int i = 2; i < 29; i++)`（加载 Objects2~Objects28，与客户端 `Client\MirGraphics\MLibrary.cs` 一致），并加中文注释。
- 行为等价收敛：仅扩展 File.Exists 守护的加载范围，原逻辑逐字保留。

### 修复点 2：部署——编辑器放入客户端根目录（上游预期布局）

Crystal 编辑器设计上就要放在客户端根目录运行（相对路径共享客户端 Data）。已将编译产物复制到 `C:\1.40\mir2-deploy\Client\`：

- `Map Editor.exe`（168,960 字节）、`Map Editor.dll`、`Map Editor.deps.json`、`Map Editor.runtimeconfig.json`、`Map Editor.pdb`
- `SlimDX.dll` 客户端根目录本就存在（与编辑器依赖同版本，未重复复制）
- 文件名无与客户端现有文件冲突；编辑器运行时如缺 `Data\Objects`（保存 .X 物件用）会自动创建空目录，无害。

### 修复点 3（顺手加固）：bin 目录 junction

为方便开发测试，给编译输出目录建了目录联接，使 bin 里的副本也能直接用客户端图库：

```
mklink /J "tools\MapEditor\Map Editor\bin\x64\Release\net8.0-windows\Data\Map" "C:\1.40\mir2-deploy\Client\Data\Map"
```

联接指向缺失时 `File.Exists` 返回 false → 空库，不会崩溃，安全。

## 使用说明

- 以后从 `C:\1.40\mir2-deploy\Client\Map Editor.exe` 启动编辑器（推荐，与客户端共用图库）。
- 打开地图：直接"打开"选 .map 文件，或右侧路径框选 Map 目录后从目录树双击。
- 库引用健康自检：打开地图后点"地图信息"按钮，窗口内每条引用会标注 可用/文件缺失/无效索引。

## 已知边界（未改动，仅记录）

- 盛大 AniTiles1 编辑器映射为 MapLibs[199]，客户端为 MapLibs[190]（上游差异）；本次部署的 Wemade 2010 格式地图不引用 AniTiles，不受影响。
- 盛大 2012 格式（LoadMapType3）与 Mir3 地图的图库覆盖面编辑器与客户端略有出入（如 Mir3 的 Dungeonsc/Innersc/Furnituresc 等）；当前部署地图全部为 Wemade 2010 格式，暂不涉及。
- 更换客户端部署路径后需同步重建 junction 或重新复制编辑器文件。

## 回滚方法

1. 还原源码：`git checkout` 本提交（或把 MLibrary.cs L41 循环改回 `i < 28`）。
2. 删除部署文件：`del "C:\1.40\mir2-deploy\Client\Map Editor.exe" "Map Editor.dll" "Map Editor.deps.json" "Map Editor.runtimeconfig.json" "Map Editor.pdb"`。
3. 删除 junction：`rmdir "tools\MapEditor\Map Editor\bin\x64\Release\net8.0-windows\Data\Map"`（rmdir 删联接不影响目标目录）。
