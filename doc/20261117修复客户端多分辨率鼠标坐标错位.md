# 20261117修复客户端多分辨率鼠标坐标错位

## 现象

用户反馈：客户端设置为**不全屏**、在 **1024×768 分辨率**桌面下运行时，**底板 UI 鼠标点不上**（登录/选角/游戏底部按钮点击错位或无效）。要求覆盖全部分辨率、全屏与非全屏逐一核查，确认是否 bug 并修复。

## 排查过程

1. **现场配置实证**：`deploy\Client\Mir2Config.ini` [Graphics]：`FullScreen=False` / `Borderless=True` / `Resolution=1024` / 无 `ScreenWidth` 项。
   - `Settings.Resolution=1024`（Settings.cs:82/221）只是**显示器档位**，仅供 `CheckResolutionSetting()` 校验，不驱动游戏逻辑分辨率。
   - 游戏逻辑分辨率/D3D 后缓冲 = `Settings.ScreenWidth×ScreenHeight`，硬编码默认 **800×600**（Settings.cs:9），**只由游戏内 `CMain.SetResolution()`（:696）运行时改**。ini 无对应项 → 用户所谓"1024 分辨率"指桌面，游戏窗口仍是 800×600。
2. **坐标换算机制**：D3D 后缓冲恒 = ScreenWidth×ScreenHeight（`Windowed=true` 恒定，DXManager.cs:64-65/301/304-305），Present 拉伸到窗体 ClientSize。`CMain_MouseMove`（:194-218）`MPoint = PointToClient(Cursor.Position)`，**仅 FullScreen 时**按 `ScreenWidth/ClientSize` 比例换算；窗口模式 ClientSize=逻辑分辨率，理论 1:1。
3. **命中链审计（子代理全量 105 个 .cs）**：底板按钮命中链 13 处 `IsMouseOver` **全部用 CMain.MPoint**（逻辑坐标，正确）；MapControl/NPCDialogs 历史已修。→ "按钮点不上"**非命中逻辑本身**。
4. **根因锁定**：
   - **主因=DPI 未感知**：客户端零 HighDpi 配置（无 manifest/config/csproj 设置，全局搜 `SetHighDpiMode` 等零命中），.NET 8 WinForms 默认 **SystemAware**。Windows 缩放≠100%（1024×768 笔记本/小屏常见 125%/150%）时，`PointToClient` 返回的坐标与 D3D 物理后缓冲不一致 → 鼠标位置与画面错位 → 点不上。
   - **叠加=6 处 e.Location 物理坐标残点**：历史修复把命中判定改用 MPoint，但遗漏少量直接用原始 `MouseEventArgs.e.Location`（物理像素）与逻辑坐标混算的点——大地图点击（BigMapDialog.cs:604-616）、音量/音乐滑块（MainDialogs.cs:3076/3140）。全屏拉伸或非 100% DPI 下必错位。

## 修复内容

1. **`Client\Program.cs`（DPI 感知，主修）**：Main 中 `Application.EnableVisualStyles()` **之前**插入 `Application.SetHighDpiMode(HighDpiMode.DpiUnaware);`（必须早于任何窗体创建，否则抛 InvalidOperationException）。DpiUnaware 让进程按虚拟 96 DPI 运行、由 Windows 对整窗位图缩放，`ClientSize` 与 D3D 后缓冲恢复 1:1，鼠标命中对齐——覆盖所有分辨率/全屏/非全屏与任意系统缩放。附 20261117 注释。
2. **`Client\MirScenes\Dialogs\BigMapDialog.cs`（4 处）**：`UpdateBigMapCoordinates`（:604-607）与 `OnMouseClick`（:613-616）内 `e.Location.X/Y` → `CMain.MPoint.X/Y`（OffsetX/Y=DisplayLocation、ScaleX/Y 基于逻辑 Size，统一用逻辑坐标口径）。订阅链不变。
3. **`Client\MirScenes\Dialogs\MainDialogs.cs`（2 处）**：`SoundBar_MouseMove`（:3076）`e.Location.Subtract(SoundBar.DisplayLocation)` → `CMain.MPoint.Subtract(...)`；`MusicSoundBar_MouseMove`（:3140）同款。

未改：`clientWidth readonly` 构造缓存（HeroDialogs.cs:388/MainDialogs.cs:4551，切分辨率后组队面板/英雄菜单布局偏移，非命中、不影响点击，P2 登记在案）。

## 验证证据

- `dotnet build Client\Client.csproj -c Release`：**0 错误**（1 存量 MSB3277 无害警告）；
- 逻辑复核：DpiUnaware 统一 ClientSize 与 D3D 后缓冲口径；6 处坐标残点改用逻辑坐标 MPoint，与全仓命中链一致；
- 覆盖核查结论：
  - **窗口模式各分辨率（1024/1280/1366/1920）**：后缓冲=ScreenWidth×ScreenHeight、ClientSize 同值、MPoint 不换算 → 1:1；DpiUnaware 消除系统缩放干扰；
  - **全屏模式**：MPoint 按比例换算回逻辑坐标（历史已修），DpiUnaware 下窗体=物理屏、换算口径一致；
  - 大地图/音量/音乐滑块：物理坐标残点已统一为 MPoint，全屏/非 100% DPI 不再错位。
- 待用户实测：重启 Client.exe 后在 1024×768 非全屏及各分辨率/全屏下点击底板 UI、大地图寻路、音量/音乐滑块均对齐。
