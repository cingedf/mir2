# 20261115修复矿石窗按钮布局

> 用户十问⑨：矿石窗口（采矿设置→矿石开采率页）控件拥挤，两对 +/- 按钮视觉混排分不清归属。定位 MiningInfoForm.Designer.cs 两处按钮坐标移位解决。

## 现象

- server.exe「矿石」窗（MiningInfoForm，450x305）→「矿石开采率」页内两组列表各有 +/- 按钮对：方案组（MineIndexcomboBox 91,6 + MineAddIndexbutton/MineRemoveIndexbutton）与掉落组（MineDropsIndexcomboBox 12,12 + MineAddDropbutton/MineRemoveDropbutton）。
- 两组按钮 y 仅差 6px 且 x 交错（掉落组 148/176 落在方案组 91-218 区间内），视觉上分不清哪对 +/- 管哪个列表。

## 排查过程

- 窗体定位：`Server.MirForms\Systems\MiningInfoForm.Designer.cs`（入口菜单 SMain「矿石」）。
- 精确现场：MineRemoveDropbutton.Location (176,12) 在 :408、MineAddDropbutton (148,12) 在 :418（Size 21x21）；方案组 MineRemoveIndexbutton (218,6) 在 :428、MineAddIndexbutton (189,6) 在 :438。
- 方案组按钮（189/218,6）自身排布正常不需动；只需把掉落组移到方案组右侧空白区，消除 x 交错。
- 页宽 419：移位后掉落组按钮占 247-297，与方案组右缘 239 仅 8px 间隔，空间充足无重叠。

## 修复内容（`Server.MirForms\Systems\MiningInfoForm.Designer.cs` 两处）

1. `:408` MineRemoveDropbutton.Location (176,12) → **(276,12)**（注释「20261115 修复（十问⑨）」）。
2. `:418` MineAddDropbutton.Location (148,12) → **(247,12)**。
- 其余控件零改动；方案组 (189/218,6) 保持不动。

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：**0 警告 0 错误**（10.02s）。
- 逻辑复核：按钮 Click 事件/Size/TabIndex 均未动，纯显示位置调整；移位后两组按钮各自成对紧邻所属下拉框，交错消除。
