# 20261115 修复旧版物品信息列表枚举下拉英文

## 现象
- 用户打开 server.exe → 主菜单「物品信息」，窗体标题「物品信息列表」（旧版 ItemInfoForm）：
  - 「所需类型」下拉闭合态显示英文枚举名 MaxDC/MaxAC，期望显示「上限攻击/上限魔御」等中文；
  - 所需职业（Warrior/...）、所需性别（Man/Woman）、物品类型筛选哨兵 "All" 同样英文。
- 前一轮（8ea709c）针对 ItemInfoFormNew/MonsterInfoFormNew 修复并探针验证通过，但用户反馈依旧 —— 修复打错了窗体。

## 排查
- SMain.cs 菜单分两组入口：
  - `itemInfoToolStripMenuItem`（菜单文案「物品信息」）→ 旧版 ItemInfoForm，窗体标题「物品信息列表」；
  - `itemNEWToolStripMenuItem`（菜单文案「物品编辑(导入导出)」）→ 新版 ItemInfoFormNew，窗体标题「物品信息」。
- 用户描述「物品信息列表」与旧版窗体标题逐字吻合 → 用户实开旧版，前一轮修复落在用户不打开的新版窗体上（探针只验证了新版窗体，方向性失误）。
- 旧版窗体为 ListBox+详情布局，枚举下拉在构造函数以 `Items.AddRange(原始枚举)` 填充（ItemInfoForm.cs:27-36），
  闭合态经 ToString() 显示英文枚举名；SelectedItem 语义被三处强转消费（:227/:346-349/:529），不能改 Items 结构。
- RTypeComboBox/RClassComboBox/RGenderComboBox 均 DropDownList 样式（Designer:753/804/946）→ 闭合态文字也走 DrawItem，
  OwnerDraw 方案可完整覆盖闭合态与下拉列表。

## 修复
- ItemInfoForm.cs：
  - 构造函数将 7 个枚举下拉（IType/IGrade/RType/RClass/RGender/ISet/ITypeFilter）DrawMode=OwnerDrawFixed 并挂 LocalizedEnumDrawItem；
  - 新增私有 LocalizedEnumDrawItem：枚举项经 ToLocalizedServerString 显示中文（中文 json Enum 段，无键回退原名），非枚举项显示 ToString；
  - 顺手汉化：ITypeFilterComboBox 哨兵 "All" → "全部"（判断按 SelectedIndex==Items.Count-1，与文案无关，安全）。
- MonsterInfoForm.cs：同款修复 ImageComboBox（Monster 枚举英文图像名），顺手汉化。
- 零语义影响：Items 保持原始枚举，SelectedItem/SelectedIndex、编辑回写、保存逻辑一字未动。

## 验证
- dotnet build Server.MirForms\Server.csproj -c Release → 0 警告 0 错误。
- 运行验证点：旧版「物品信息列表」所需类型下拉闭合态显示「上限攻击/上限魔御」；所需职业显示「战士/道士」等；
  类型筛选哨兵显示「全部」；选择后编辑与保存回写正常（SelectedItem 语义未动）。
