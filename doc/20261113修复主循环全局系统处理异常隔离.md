# 20261113修复主循环全局系统处理异常隔离

> ⑤容错加固第二步第四段。承接：切片每对象（36b1b84）、每地图（e909487）、龙系统（d5e8bc5）、ThreadLoop 恢复式容错（aba3b12）。

## 现象

WorkLoop 主循环每 tick 调用 `Process()`（Envir 全局段：ProcessNewDay 日切换、GuildsAtWar 战争倒计时+EndWar、行会/商品/征服等计时段）——任一子系统抛异常直接冒泡到内层致命 catch → 全服踢人停机。

## 排查过程

- 现场核查：`Process();` 紧跟龙系统段之后、存档门控（`Time >= saveTime`）之前。
- 引用逻辑链核查：该调用为 Envir 实例方法本身（this.Process()），**单入口无逐项维度**，节流键固定 `WorkLoopEnvir`。
- 语义边界确认：全局段内部各计时子段（日切换/战争/行会）均为「到点才跑」门控（前几轮体检已确认健康）；异常隔离后，抛异常的子段本 tick 跳过、下一 tick 重入（计时字段未被消费前不会误跳过下一周期），毒状态由节流日志暴露。

## 修复内容

**`Server\MirEnvir\Envir.cs`**（WorkLoop 全局段，单文件）：

```csharp
try
{
    Process();
}
catch (Exception ex)
{
    ErrorThrottle.Notify("WorkLoopEnvir", () =>
        MessageQueue.Enqueue($"主循环全局系统处理异常 => {ex}"));
}
```

- **存档段（BeginSaveAccounts/SaveDB/SaveGuilds/SaveGoods/SaveConquests）不在本段范围、保持致命停机语义**（第二步既定纪律：存档完整性 > 容错）；公告广播段与无人休眠段亦未动。

## 验证证据

- `dotnet build Server\Server.Library.csproj -c Release`：**0 警告 0 错误**。
- 逻辑复核：Process() 原语义逐字保留于 try 内；异常只跳过本 tick 全局段，后续存档/公告段照常执行。
