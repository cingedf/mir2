# 20261119修复NPC脚本引擎健壮性

## 现象

新维度审计（NPC 脚本引擎与配置健壮性路线）回报 7 项缺陷，其中 1 项 P0 可致全服主循环卡死，1 项 P1 可致死循环 OOM，5 项 P2 为异常中断/NRE/绕过校验：

1. **F1【P0】** 玩家执行带多个跳转动作的 NPC 页时，服务端主循环死循环卡死全服。
2. **F2【P1】** GIVEITEM 脚本动作发放 StackSize=0 的物品配置时死循环 + OOM。
3. **F3【P2】** 商店页打开瞬间 NPC 消失（切换地图/被删）时，服务端 NRE。
4. **F4【P2】** 畸形 #INSERT/#INCLUDE 脚本 token 致启动期脚本解析崩溃。
5. **F5【P2】** NPC 检查脚本 Random 判定参数为负时抛异常中断脚本检查。
6. **F6【P2】** 无公会玩家执行行会金币脚本动作时 NRE。
7. **F7【P2】** NPCConfirmInput 路径 PageName 无长度校验，绕过 CallNPC 的 30 字符限制。

## 排查过程

- **F1 入队链逐层读全证实**：`CallNPCNextPage`(PlayerObject.cs) 正向 `for(i<ActionList.Count)` + `RemoveAt(i)` + `CompleteNPC(action.Params)`；`CompleteNPC`(:4715-4738) → `NPCScript.Call(PlayerObject,uint,string)`(:851-917) 遍历 page.SegmentList → segment.Check → ActionType.Goto/Call 命中时 `NPCSegment.cs:3888-3902` `player.ActionList.Add(new DelayedAction(DelayedType.NPC, -1, ...))`。单次 Call 遍历页内所有 segment，一页多个 Goto/Call 就 Add 多个 -1 动作到尾部；for 循环 RemoveAt(i) 后 i++ 不回退（还跳过紧邻后继元素），Count 增长可快于 i → 永不退出。
- **F2**：`NPCSegment.cs:3545` `while(count>0)` 内 `:3562 count -= item.Info.StackSize`；StackSize==0 时 count 恒定 → 死循环且每轮 `CreateFreshItem` 分配 → OOM。
- **F3**：`NPCScript.cs:960` `callingNPC = NPCObject.Get(player.NPCObjectID)` 后 :962 有 null 检查，但 :968 `sentGoods.AddRange(callingNPC.UsedGoods)` 逃逸出检查块 → null 时 NRE。
- **F4**：`NPCScript.cs:318/:352` `split[1].Substring(1, split[1].Length - 2)`，畸形 token（长度<2 或无配对引号）时负长度抛 ArgumentOutOfRangeException → 启动期脚本解析崩溃。
- **F5**：`NPCSegment.cs:1973/:2181/:2561` `Envir.Random.Next(0, tempInt)`，tempInt<0 时抛 ArgumentOutOfRangeException（%INPUTSTR → NPCVar 可注入负值）。
- **F6**：`NPCSegment.cs:3443/:3454` 直接解引用 `player.MyGuild.Gold`，无公会玩家执行 GiveGuildGold/TakeGuildGold 时 NRE。
- **F7**：`MirConnection.cs:3616 NPCConfirmInput` 无 PageName 长度校验，而 `CallNPC` 路径有 `>30 SendDisconnect` → 可绕过。

## 修复内容

1. **F1**（PlayerObject.cs CallNPCNextPage）：改快照待处理动作 + budget=64：`var pending = ActionList.Where(a => a.Type == DelayedType.NPC && a.Time == -1).Take(64).ToList(); foreach (var action in pending) { ActionList.Remove(action); CompleteNPC(action.Params); }`——按引用移除避免索引跳过，遍历中新增动作留待下次调用，budget 防病态脚本无限加动作。
2. **F2**（NPCSegment.cs GIVEITEM）：while 前加 `if (info.StackSize <= 0) { MessageQueue.Enqueue(失败日志); break; }`。
3. **F3**（NPCScript.cs ProcessSpecial）：把 `sentGoods.AddRange(callingNPC.UsedGoods)` 移入 `if (callingNPC != null)` 块内。
4. **F4**（NPCScript.cs ParseInsert/ParseInclude）：Substring 前加 `if (split[1].Length < 2 || split[1][0] != '"' || split[1][split[1].Length-1] != '"') continue;`。
5. **F5**（NPCSegment.cs 三处 CheckType.Random）：`failed = tempInt < 0 || 0 != Envir.Random.Next(0, tempInt);`（负值短路视为检查失败，不再调用 Next）。
6. **F6**（NPCSegment.cs GiveGuildGold/TakeGuildGold）：case 开头加 `if (player.MyGuild == null) return;`。
7. **F7**（MirConnection.cs NPCConfirmInput）：入口加 `if (p.PageName == null || p.PageName.Length > 30) return;`。

（注：子代理声明已自查无缺陷的项——#INSERT 自引用去重、%ARG(n) 越界、%INPUTSTR 二次解析、CALC/Craft/合成除零、Buy NPCPage 空引用、ParseScript 空白行——本批未改动。）

## 验证证据

- `dotnet build Server.MirForms\Server.csproj -c Release`：**0 警告 0 错误**；
- 行为复核：合法 NPC 页跳转（含单/多 Goto/Call）行为等价——F1 快照后本轮只处理已入队动作，新增动作留到下轮，仍会被逐步执行；正常物品发放/商店/Random 判定/行会金币操作不受影响；
- 待实测：多跳转脚本页不再卡死；畸形配置不再中断启动/主循环。
