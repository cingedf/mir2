# 20261111修复玩家信息窗口属性框与搜索区布局

## 现象

管理界面（在线玩家列表双击玩家打开的 PlayerInfoForm）两个问题：

1. **属性框只读**：「玩家信息」与「英雄信息」标签页的物理防御/魔法防御/物理攻击/魔法攻击/道术/准确/敏捷/攻击速度共 16 个数值框灰色只读（`Enabled=false + ReadOnly=true`），无法修改。
2. **右下搜索区重叠**：「搜索」容器（SearchBox）内的标志列表 PlayerFlagsListView、搜索框 FlagSearchBox 与按钮互相压盖，布局破碎。

## 排查过程

1. **属性框只读为上游原设计**：对照旧版 crystal 源码（C:\1.40\mir2\src\crystal），16 框同样双锁。机制原因：`Player.Stats` 是由等级/装备/套装/技能/buff 每次全量重算（HumanObject.RefreshStats 先 `Stats.Clear()` 再逐项累加）的聚合值，角色存档里没有「基础属性」持久化字段——直接改必被下次刷新覆盖。
2. **搜索区重叠根因**：angelk727 移植时把 SearchBox 从旧版 323×261 缩小到 189×110，但内部子控件坐标原样保留——列表高 233 装不进 110 高的容器、按钮横向位置 192+128=320 超出 189 宽度，整体溢出压盖。
3. **改造方案经用户选定**：属性框做成可编辑采用「方案 B 临时生效」——填写的值以无限时长 buff 加给在线玩家/英雄（`RemoveOnDeath|RemoveOnExit`，死亡/下线自动失效，不写存档），改动面小、无存档结构风险。

## 修复内容

- `Server.MirForms\Account\PlayerInfoForm.Designer.cs`：
  - 16 个属性框解锁（玩家 8 框 + 英雄 8 框 `Enabled=true`、`ReadOnly=false`）。
  - SearchBox.Size (189,110)→(323,261)（恢复旧版容量）；FlagSearchBox.Location (31,40)→(196,57)、占位文本改中文「搜索标志编号」（对齐旧版坐标）。
- `Server.MirForms\Account\PlayerInfoForm.cs`：
  - 新增 `ParseMinMax()`：解析 min-max 双值框（支持 `-`/全角连接符/单值写法）。
  - 新增 `ApplyStatsBuff()`：把 5 个双值框（防御/魔御/攻/魔/道 → BuffType.防御提升/魔法防御提升/攻击力提升/魔法力提升/道术力提升，各写 Min+Max 两键）+ 3 个单值框（准确/敏捷/攻击速度 → 准确提升/敏捷提升/攻击速度提升）合成一个 `new Stats`，先 `RemoveBuff` 清 8 类旧 buff，再 `AddBuff(type, target, 0, stats)`（duration=0 无限时，refreshStats 自动重算生效）。
  - `SaveChanges()`/`HeroSaveChanges()` 在原五项/两项保存后追加调用；目标离线（无 Player/Hero 对象）时如实弹窗提示「临时属性仅对在线生效」。

## 使用说明与注意

- 属性框修改属**临时增益**：立即生效、玩家死亡或下线自动失效，不会写进存档；离线玩家/英雄不可用（弹窗提示）。
- 搜索区为「玩家标志」面板：FlagSearchBox 输入编号过滤、ActiveFlagsCheckBox 只显激活、Enable/Disable Selected Flag 开关选中标志、OpenFlagsButton 生成/打开 Envir\SET [].txt。
