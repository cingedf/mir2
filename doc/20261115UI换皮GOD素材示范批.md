# 20261115 UI换皮GOD素材示范批

## 现象

Crystal 客户端（mir2-angelk727 血统）UI 观感老旧：窗体均为低细节暗棕扁平贴图，与同期其他传奇引擎（GOD、HotBlood 等）相比明显不华丽。用户要求画面/UI 华丽化，优先从 UI 界面入手。

## 排查过程

1. **确认窗口背景帧的真实来源**：全仓扫描确认对话框类自身继承 `MirImageControl` 并在构造函数直接赋 `Index`/`Library`（如 `InventoryDialog.cs` L27-28），无独立 Background 子控件（全仓仅 3 处例外）。`Title.Lib` 为主窗体库，`Prguse.Lib` 为窗体+控件混合库。
2. **确定换皮硬约束**：
   - 帧内 alpha 只有 0/255 两值，右/底有 1-3px 透明 padding 被 `MLibrary.TrueSize`（VisiblePixel 扫描）裁掉 → 替换时必须保持 **alpha 包围盒** 与原帧一致，否则控件尺寸（`GetTrueSize`）与布局会变；
   - 窗体内部必须保持不透明低亮度（原帧内部均色 R/G/B ≈ 24-45），否则白字看不清；
   - 绘制走 `Library.Draw(Index, pos, ForeColour, false, Opacity)`，`ForeColour` 为乘法着色，按白色=原样设计。
3. **素材选型**：优先搜现成素材，避免自绘。
   - HotBlood UI 包（3209 张 PNG，687 种尺寸）：实测高度 25 的 248 张宽度全在 20-33px，45/52/60/68/72/80 官方按钮档位命中 0 张，尺寸指纹与 Crystal 窗框完全不匹配，**排除**；
   - 官方 Crystal PSD/PNG（Main UI.zip 等）：即当前 UI 的设计稿，重导入外观零变化，**排除**；
   - **GOD 引擎全套（C:\xxxxx）**：Cocos2d-x 客户端，散图（`C:\baidunetdiskdownload\...\cocosstudio\`）含高分辨率暖金棕风格整窗素材，华丽度数值（量化色数/细节边缘率/暖色占比）显著优于 Crystal 现有窗框，**选用**。
4. **尺寸适配方案**：GOD 素材与 Crystal 目标帧无一相同尺寸 → 等比 scale-to-cover + 居中裁剪（System.Drawing，HighQualityBicubic）到目标帧 alpha 包围盒尺寸。


## 验证证据

1. **库结构完好**：libdump 双文件比对（替换后 vs .bak）`mismatched frames 0/1297`（Title.Lib）、`0/2447`（Prguse.Lib），所有未替换帧的 W/H/X/Y/HasMask 元数据完全未动。
2. **端到端无损**：从替换后库重新 export 8 帧，与设计稿 PNG 逐像素（A/R/G/B 四通道）比对，8 张全部 `sizeMatch=True、diffPixels=0`。
3. **白字可读性**：内部亮度（中心 50% 区域，alpha>=128 像素）新图全部 20.6-46.4（阈值 60），旧图 5.5-49.7，均未超过旧图两倍。
4. **库体积增量可接受**：Title.Lib 6762802→7596807（+12.3%）、Prguse.Lib 13351451→14026050（+5.1%），GOD 素材色彩丰富导致 GZip payload 膨胀，总量仍在可控范围。
5. **回滚资产**：`deploy\Client\Data\Title.Lib.bak`(6762802 字节)、`Prguse.Lib.bak`(13351451 字节)。

## 回滚方法

- 整批回滚：把 `deploy\Client\Data\Title.Lib.bak`、`Prguse.Lib.bak` 复制回同名文件（去掉 .bak 后缀）即恢复原 UI。
- 单帧回滚：用 mirimport 从 .bak 库 export 对应帧 PNG，再 replace 回正式库。
- 本次未改源码，无需重新编译。
