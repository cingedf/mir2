# 20261116修复审计P0五项安全漏洞

## 现象

第十二轮四路全仓深度审计（服务器核心/玩法系统/客户端渲染/协议与安全）共回报 **P0×5**，全部为可被恶意客户端稳定触发或直接破坏经济/权限体系的高危缺陷：

1. **ChangeHero 负下标**（PlayerObject.cs:10119）：客户端传 index=-1 每包必炸 → 熔断计数打满 → 全服停机；
2. **NPC Craft 配方越界**（NPCScript.cs）：recipe null 解引用 + 4 处 `slot > Length` off-by-one（slot==Length 放行后 `Inventory[slot]` 越界）；
3. **ChatItem 正则注入**（ItemData.cs:1482 + PlayerObject.cs:4490）：玩家聊天标题仅转义括号，剩余正则元字符注入 + Regex 无超时 → 回溯爆炸挂死主循环；
4. **商城限量库存键不一致**（PlayerObject.cs）：读 `Info.Index` 写 `GIndex`（独立流水号，永不相等）→ 限量商品库存恒 0，可无限扫空；
5. **GM 密码硬编码**（Server\Settings.cs:45）：源码里明文 `@9396399`，任何拿到源码/反编译者可提权 GM。

## 排查过程（熔断机制关键认知）

- Envir.cs:663-671 主循环隔离 catch 每次异常计数，60s 窗口 500 次 → 触发熔断：踢全服+停机存档；
- 「每包必抛异常」类缺陷 = 单 IP 一分钟内即可打满熔断造成全服停机，故 1/2/3 均定 P0；
- 客户端包字段（Craft.Slots 等）在 MirConnection 仅做 Stage 检查直通，服务端必须自校验；
- 商城 GIndex=Envir.cs:3036 `++GameshopIndex` 独立流水号（ItemData.cs:811），与 Product.Info.Index 无映射关系。

## 修复内容

1. **P0-1** PlayerObject.cs:10119：`if (index < 0 || Info.Heroes.Length <= index) return;`（负下标+上界双防）。
2. **P0-2** NPCScript.cs：Craft 处理入口 recipe==null 提前 return；四处 `slot > player.Info.Inventory.Length` → `slot >= ...`（:1318/:1356/:1419/:1444）。
3. **P0-3** ItemData.cs：RegexInternalName 改 `Regex.Escape(Title ?? string.Empty)` 全量转义；PlayerObject.cs:4490 Regex 构造加 `TimeSpan.FromMilliseconds(100)` MatchTimeout。
4. **P0-4** PlayerObject.cs 写键 4 处 `Product.GIndex` → `Product.Info.Index`（:14286/:14290/:14297/:14301），与读侧 8 处统一；:14163 协议显示字段 `S.GameShopStock{GIndex=...}` 与字典键无关，不动；存量存档旧键成孤儿数据只少计不多计，不迁移。
5. **P0-5** Server\Settings.cs:45：硬编码 GM 密码 → `string.Empty`（须在 Setup.ini [General] GMPassword 配置才启用；空=聊天提权彻底禁用）。提权链核查：@GM LOGIN 设 GMLogin → Chat 比对密码 → IsGM；空消息已拦截，空密码永不匹配。deploy Setup.ini 已有 GMPassword=@9396399 配置行，运行时不受影响。
